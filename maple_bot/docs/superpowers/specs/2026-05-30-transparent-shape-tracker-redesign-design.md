# 투명 도형 찾기 추적기 재설계

작성일: 2026-05-30
대상 파일: `transparent_shape_standalone.py`

## 1. 배경 / 문제

메이플 "투명 도형 찾기" 미니게임 자동 추적기.

게임 메커니즘:
- 도형(네모·세모·동그라미·별 등)이 **항상 가운데서 흰색으로 시작**.
- 시작 후 **끝까지 계속 이동**하면서 동시에 **점점 투명**해짐 → 배경(바위 텍스처)과 색이 같아져 **일그러진 테두리만** 보임.
- 분홍색 과녁/톱니 아이콘 = **사용자 마우스 커서**(우리가 직접 움직이는 것). 추적 대상이 아님.
- 안내문: "커서를 도형 위에 놓은 뒤 점점 투명해지는 도형을 따라가세요."
- 준비시간 포함 전체 **30초 미만**. 성공 시 "투명 도형 찾기가 종료되었습니다 / SUCCESS" 화면.

### 현재 버그 (확인됨)

```
find_white()  → 흰 도형이 투명해지면 gray > 200 임계값에 안 걸려 감지 실패
   ↓ 폴백
find_diff()   → 프레임 차분. 우리가 마우스를 움직이고 있어
                분홍 커서가 매 프레임 이동 → 차분이 "커서"를 변화 영역으로 검출
   ↓
추적 대상이 분홍 커서로 점프 (오인)
```

핵심 결함 2가지:
1. **커서 마스킹이 어디에도 없다** → 차분/검출이 분홍 커서를 잡는다.
2. **외형 변화(흰→투명) 적응 모델이 없다** → 흰색이 사라지면 추적 끊김.

## 2. 채택 설계: A′ — 로컬 템플릿 추적기

CSRT(`cv2.TrackerCSRT`)가 하는 일을 base OpenCV의 `cv2.matchTemplate`로 직접 구현한 경량 상관 추적기. **contrib 의존성 없음**(현재 설치된 OpenCV 4.13 headless에는 CSRT 미포함 확인).

### 비교한 대안
| 방식 | 결과 |
|---|---|
| A. CSRT 트래커 | contrib 필요 → headless 충돌 위험. 폐기 |
| **A′. 로컬 템플릿 추적기** | **채택. 의존성 0, 외형 점진 적응, 커서 차단** |
| B. 커서마스킹 차분+칼만 | 커서가 도형 가릴 때·도형 정지 시 약함 |
| C. 광학흐름(LK) | 투명화로 특징점 소실, 배경 텍스처 드리프트. 가장 불안정 |

### 파이프라인 (매 프레임)
```
1. 보드 ROI 캡처
2. 분홍 커서 마스킹  ← HSV in_range(분홍/자홍) → 마스크 영역 inpaint
                       (모든 검출 단계에서 커서 제거 — 구조적 차단)
3. 예측 위치 = last_pos + velocity   (velocity = 직전 변위의 EMA)
4. 예측 위치 주변 작은 윈도우에서만 cv2.matchTemplate (TM_CCOEFF_NORMED)
5. 매칭 점수 >= MATCH_THRESH ?
     예  → 새 위치 채택. 템플릿 느린 갱신: tmpl = 0.9·tmpl + 0.1·patch
     아니오 → 예측 위치 유지, lost_frames += 1 (LOST_MAX까지 버팀)
6. velocity 갱신 → EMA 스무딩 → win32api 커서 이동
```

### 초기화
게임 시작 시 가운데에서 `find_white`로 흰 도형을 1회 감지 → 그 바운딩 패치를 첫 템플릿으로 저장.
- 가운데 시작이 항상 동일하므로 안정적.
- 초기 감지 실패 시 최대 INIT_TIMEOUT(예: 3초) 재시도, 그래도 실패하면 ROI 중심을 기본 시작점으로.

### 종료 조건
1. **SUCCESS/종료 화면 감지** → 즉시 정지 (밝은 노란 글자 비율 또는 종료 패널 색 변화).
2. **하드 타임아웃 35초** → 무조건 자동 정지.
3. **F10 수동 정지** → 항상 가능 (기존 단축키 시스템 유지).

## 3. 핵심 설계 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 커서 오인 방지 | 입력 단계 HSV 마스킹 + inpaint | 분홍 커서가 어떤 검출에도 안 들어옴 |
| 흰→투명 적응 | 템플릿 느린 갱신(0.9/0.1) | 외형 점진 변화 추종 |
| 연속 이동 | velocity 예측 + 로컬 윈도우 검색 | 빠른 이동도 윈도우 안에 포착 |
| 일시 소실 | LOST_MAX까지 예측값 유지 | 투명 구간/가림에도 안 끊김 |
| 종료 | SUCCESS 감지 OR 35s OR F10 | 30초 미만 세션에 맞춤 |
| 의존성 | base OpenCV만 | contrib/headless 충돌 회피 |

## 4. 파라미터 (초기값)

```python
MATCH_THRESH   = 0.45    # NCC 매칭 채택 임계
TMPL_SIZE      = 64      # 초기 템플릿 한 변(px), 흰도형 크기에 맞춤
SEARCH_MARGIN  = 40      # 예측위치 ± 검색 윈도우 여유(px)
TMPL_UPDATE    = 0.10    # 템플릿 갱신 비율 (1-이 값만큼 이전 유지)
LOST_MAX       = 15      # 연속 미검출 허용 프레임
VEL_ALPHA      = 0.5     # velocity EMA
HARD_TIMEOUT   = 35.0    # 초
# 분홍 커서 HSV 범위 (OpenCV H 0~179)
CURSOR_HUE     = (140, 175)
CURSOR_SAT_MIN = 80
CURSOR_VAL_MIN = 80
```
기존 EMA_ALPHA / MAX_SPEED / SPEED_PROP(마우스 이동 제어)는 그대로 재사용.

## 5. 구현 범위 (transparent_shape_standalone.py)

수정/추가는 **추적 로직에 한정**. UI·단축키·ROI 시스템은 그대로 둔다.

| 대상 | 변경 |
|---|---|
| 파라미터 블록 | 위 신규 상수 추가 |
| `find_diff()` | **제거 또는 미사용** (커서 오인의 직접 원인) |
| 신규 `mask_cursor(img)` | HSV 마스킹 + inpaint |
| 신규 `match_track(img, tmpl, pred, search)` | 로컬 NCC 매칭 |
| 신규 `detect_end_screen(img)` | SUCCESS/종료 감지 |
| `ShapeTracker.__init__` | 템플릿·velocity·lost·시작시각 상태 추가 |
| `ShapeTracker.run()` | 초기화 → 매 프레임 마스킹·예측·매칭·갱신·종료체크로 재작성 |

UI에서 건드리지 않는 것: `HotkeyPoller`, `KeyCaptureButton`, `RoiOverlay`, `MainWindow`, 단축키 저장/로드, 다크 스타일.

## 6. 디버그 / 검증

- 디버그 오버레이(옵션): 노란 박스(검색 윈도우), 빨간 십자(매칭 위치), 자홍 마스크(제외 커서), 파란 원(실제 커서), 매칭 점수 텍스트.
  - OpenCV headless라 imshow 불가 → PyQt6 QLabel에 QImage로 표시하거나 디버그 PNG 저장.
- 검증 시나리오:
  1. 흰 구간: 가운데 흰 도형을 즉시 잡고 추적 시작.
  2. 투명 전환 구간: 흰색 사라져도 템플릿 매칭으로 계속 추종.
  3. 커서 근접: 분홍 커서가 도형 옆/위에 있어도 추적 대상이 커서로 안 튐.
  4. 종료: SUCCESS 화면에서 자동 정지(또는 35초 타임아웃).

## 7. 리스크 / 폴백

| 리스크 | 대응 |
|---|---|
| 투명 후반 매칭 점수 < 임계 지속 | LOST_MAX 동안 velocity 예측으로 직진 추종 |
| 템플릿 드리프트(배경 학습) | 갱신 비율 0.10으로 보수적, 점수 낮으면 갱신 skip |
| inpaint 비용 | 커서 주변 작은 ROI만 inpaint |
| SUCCESS 감지 오탐 | 타임아웃이 안전장치로 항상 존재 |
