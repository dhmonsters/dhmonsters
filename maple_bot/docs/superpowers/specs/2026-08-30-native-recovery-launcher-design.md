# Claude 네이티브 복구 실행기 설계

## 목적

PyQt6, Python 또는 PyInstaller 초기화 단계에서 오류가 발생해 메인 UI가 열리지 않더라도 사용자가 오류 내용을 확인하고 이전 버전 복구 또는 최신 버전 재설치를 실행할 수 있게 한다.

실제 프로그램 설치는 항상 한 버전만 유지한다. 이전 버전은 실행 가능한 두 번째 설치본이 아니라 복구용 설치 파일 한 개로만 보관하므로 DLL, 설정, 프로세스가 충돌하지 않는다.

## 적용 버전

첫 적용 버전은 Claude 2.4.7로 한다. 2.4.7 설치 과정에서 현재 설치된 2.4.6 설치 파일을 복구용으로 확보한 뒤 새 버전을 설치한다.

## 구성 요소

### 네이티브 복구 실행기

- 설치 후 사용자가 실행하는 파일 이름은 계속 `Claude.exe`로 유지한다.
- `Claude.exe`는 .NET Framework 기반의 작은 Windows Forms 실행기로 만든다.
- 복구 실행기는 Python, PyQt6, Qt DLL에 의존하지 않는다.
- 복구 실행기는 관리자 권한으로 시작하며 자신이 직접 실행한 실제 앱 프로세스를 끝까지 감시한다. 기존 앱 내부의 재실행 방식으로 관리자 권한을 넘기지 않는다.
- 실제 PyInstaller 프로그램은 `ClaudeApp.exe`로 이름을 분리한다.
- 바탕화면과 시작 메뉴 바로가기는 복구 실행기인 `Claude.exe`를 가리킨다.

### 실제 프로그램

- 기존 `run_integrated.py` 기반 프로그램은 `ClaudeApp.exe`로 빌드한다.
- PyInstaller 기본 windowed traceback 창은 비활성화한다.
- Python 코드가 시작된 뒤 발생한 처리되지 않은 예외는 UTF-8 JSON 또는 텍스트 오류 파일에 기록한다.
- UI가 실제로 표시되면 복구 실행기가 확인할 수 있는 준비 완료 신호를 기록한다.
- 정상 종료와 업데이트 설치를 위한 종료는 명시적인 정상 종료 신호 또는 종료 코드 0으로 구분한다.

### 복구 저장소

- 기본 위치는 `%ProgramData%\Claude\Recovery`로 한다.
- `previous_setup.exe`에는 직전 버전 설치 파일 한 개만 보관한다.
- `recovery.json`에는 이전 버전, 현재 버전, 설치 경로, 설치 파일 SHA-256, 생성 시각을 저장한다.
- 설치된 각 버전에는 해당 버전 설치 파일의 공식 URL과 SHA-256을 담은 로컬 `release.json`을 둔다.
- `release.json`은 빌드 산출물에 미리 포함하지 않는다. 설치기가 실행된 원본 설치 파일의 SHA-256을 설치 시점에 계산하여 생성하므로 설치 파일이 자기 자신의 해시를 포함해야 하는 순환 문제를 피한다.
- 마지막 치명적 오류 내용은 `%ProgramData%\Claude\Recovery\last_crash.json`에 UTF-8로 기록한다.
- 사용자 설정과 라이선스 파일은 복구 저장소에 복제하지 않고 기존 보존 정책을 그대로 사용한다.

## 실행 흐름

1. 사용자가 `Claude.exe`를 실행한다.
2. 복구 실행기가 관리자 권한 상태에서 `ClaudeApp.exe`를 직접 자식 프로세스로 시작한다.
3. 자식 프로세스가 준비 완료 신호를 남기면 정상 시작으로 기록한다.
4. 자식 프로세스가 종료 코드 0으로 끝나면 복구창을 표시하지 않는다.
5. 준비 완료 전 비정상 종료 또는 실행 중 비정상 종료가 발생하면 복구창을 표시한다.
6. 오류 파일이 있으면 상세 내용을 표시하고, 없으면 종료 코드와 일반적인 시작 실패 안내를 표시한다.

업데이트 설치를 위해 앱이 종료된 경우에는 정상 종료 신호를 남기고 설치기를 시작한 뒤 복구 실행기도 종료한다. 작업 관리자 강제 종료처럼 정상 신호 없이 프로세스가 사라진 경우에는 비정상 종료로 처리한다.

일반 감지 실패, 템플릿 미검출, 입력 재시도, 기능별 처리 오류처럼 프로그램이 계속 실행 가능한 로그는 복구창 조건에 포함하지 않는다.

## 복구창

복구창에는 다음 버튼을 둔다.

- `이전 버전으로 되돌리기`.
- `업데이트 확인`.
- `오류 내용 복사`.
- `닫기`.

이전 설치 파일이 없거나 해시 검증에 실패하면 되돌리기 버튼을 비활성화하고 이유를 표시한다.

### 이전 버전으로 되돌리기

1. 실행 중인 `ClaudeApp.exe`가 없는지 확인한다.
2. `previous_setup.exe`의 SHA-256을 `recovery.json`과 비교한다.
3. 복구 실행기 자신을 임시 폴더의 복구 작업자로 복사하고 현재 실행기 종료 후 작업을 넘긴다.
4. 복구 작업자는 설치 경로와 메타데이터가 일치하는지 재검증한 뒤 현재 버전의 프로그램 파일만 명시적 허용 목록으로 정리한다.
5. 사용자 설정, 라이선스, 복구 캐시와 Interception 드라이버 파일은 정리 대상에서 제외한다.
6. 검증된 이전 설치 파일을 같은 설치 경로로 실행한다.
7. 설치 완료 후 복구된 버전의 `Claude.exe`를 실행한다.

복구 중에는 두 버전의 프로그램을 동시에 실행하지 않는다.

### 업데이트 확인

1. GitHub Raw의 `maple_bot/version.json`을 HTTPS로 조회한다.
2. 더 높은 버전이 있으면 버전과 변경 내용을 표시하고 설치 파일을 내려받는다.
3. 공개 `version.json`의 SHA-256으로 다운로드 파일을 검증한다.
4. 최신 버전과 로컬 버전이 같아도 `현재 버전 다시 설치` 선택을 제공한다.
5. 더 높은 버전으로 업데이트할 때는 현재 버전 복구본을 먼저 확보한 뒤 새 설치기를 실행한다.
6. 같은 버전 재설치는 기존 복구본을 교체하지 않고 검증된 최신 설치기만 실행한다.

네트워크 오류가 발생하면 복구창은 유지하고 오류 메시지만 갱신한다. 이전 버전 복구는 네트워크 없이도 동작한다.

## 업데이트 전 이전 버전 확보

새 버전을 적용하기 전에 현재 버전 설치 파일을 `previous_setup.exe`로 확보한다.

- 설치기가 생성한 로컬 `release.json`에서 현재 버전의 공식 URL과 SHA-256을 읽는다.
- 임시 파일로 현재 버전 설치 파일을 다운로드하고 SHA-256을 검증한다.
- `previous_setup.exe`가 이미 현재 버전과 일치하고 해시가 정상이면 다시 다운로드하지 않는다.
- 다운로드 후 SHA-256 검증이 통과해야 새 버전 설치를 허용한다.
- 확보 또는 검증에 실패하면 업데이트를 중단하고 현재 버전을 그대로 유지한다.
- 검증된 임시 파일과 메타데이터를 원자적으로 `previous_setup.exe`와 `recovery.json`으로 교체한다.
- 교체가 완료된 뒤에만 새 버전 설치기를 실행한다. 따라서 새 버전 설치에 실패하면 바로 직전의 현재 버전으로 복구할 수 있다.

## 2.4.7 최초 전환

2.4.6에는 새 복구 캐시 기능이 없으므로 2.4.7 설치기가 다음 순서로 처리한다.

1. 기존 설치 경로의 `version.txt`에서 2.4.6을 확인한다.
2. 2.4.7 설치기에 고정된 공식 URL에서 `Claude_v2.4.6_Setup.exe`를 임시 파일로 다운로드한다.
3. 2.4.7 설치기에 고정된 2.4.6 SHA-256과 비교한다.
4. 검증이 실패하면 2.4.7 설치를 시작하지 않는다.
5. 검증이 성공하면 `previous_setup.exe`와 `recovery.json`을 기록하고 2.4.7을 설치한다.

수동 신규 설치처럼 이전 버전이 없는 경우에는 복구 파일 없이 설치하며 복구창의 되돌리기 버튼을 비활성화한다.

## 무결성 및 보안

- 다운로드는 HTTPS GitHub Release URL만 허용한다.
- `version.json`에 `sha256` 필드를 추가한다.
- 각 설치본의 로컬 `release.json`에도 그 버전의 공식 URL과 SHA-256을 기록한다.
- 다운로드한 설치 파일과 로컬 복구 설치 파일은 실행 전에 항상 SHA-256을 검증한다.
- 복구 실행기는 메타데이터의 임의 로컬 경로나 임의 실행 명령을 실행하지 않는다.
- 복구 파일은 관리자만 변경 가능한 `%ProgramData%` 하위에 저장한다.

## 설치기 변경

- `installer.iss`의 주 실행 파일과 바로가기를 `Claude.exe` 복구 실행기로 연결한다.
- 실제 앱 파일은 `ClaudeApp.exe`로 설치한다.
- 설치 중 실행 중인 Claude 프로세스를 모두 정상 종료한 뒤 파일을 교체한다.
- 복구 실행기가 새 설치기를 시작하면 파일 잠금을 남기지 않고 종료하며, 설치기는 완료 후 새 `Claude.exe`를 실행한다.
- 이전 설정, 라이선스, 맵, 템플릿 사용자 데이터는 삭제하지 않는다.
- 제거 프로그램에서는 프로그램 파일과 복구 캐시 제거 여부를 사용자에게 구분해 처리한다.

## 오류 처리

- 자식 프로세스 생성 실패도 치명적 시작 오류로 처리한다.
- 오류 기록 파일을 읽지 못해도 복구창 자체는 표시한다.
- 복구 설치기 실행 실패 시 복구창을 닫지 않고 오류를 표시한다.
- 임시 복구 작업자는 허용된 설치 경로 밖의 파일을 삭제하지 않으며 경로 검증 실패 시 즉시 중단한다.
- 업데이트 다운로드 실패나 해시 불일치 시 기존 설치와 복구 파일을 변경하지 않는다.
- 동일한 오류창이 중복으로 열리지 않도록 복구 실행기 단일 인스턴스를 적용한다.

## 테스트

### 단위 테스트

- 정상 종료와 비정상 종료 판정.
- 준비 완료 전후의 오류 판정.
- 버전 비교와 같은 버전 재설치 분기.
- 복구 메타데이터 읽기 및 손상 처리.
- SHA-256 일치와 불일치 처리.
- 이전 설치 파일이 없을 때 버튼 비활성화.
- 임시 다운로드 검증 성공 후에만 복구본이 원자적으로 교체되는지 확인.
- 정상 종료, 업데이트 종료, 강제 종료를 서로 구분하는지 확인.

### 통합 테스트

- Qt DLL을 의도적으로 비활성화한 `ClaudeApp.exe`에서 복구창 표시.
- 정상 앱 실행 시 복구창 미표시.
- `이전 버전으로 되돌리기`로 같은 설치 경로에 직전 버전 복원.
- 새 버전 전용 DLL과 실행 파일이 제거되고 설정·라이선스·드라이버가 보존되는지 확인.
- 2.4.6에서 2.4.7로 전환하기 전에 2.4.6 복구본이 확보되는지 확인.
- 최신 버전 확인, 같은 버전 재설치, 네트워크 실패 처리.
- 설정과 라이선스가 복구 전후 유지되는지 비교.
- 두 Claude 버전 프로세스가 동시에 남지 않는지 확인.

### 배포 검증

- 빌드 산출물에 Poppler ICU와 Codex 작업용 DLL이 없는지 기존 검증 유지.
- 복구 실행기가 Qt DLL을 모두 제거한 환경에서도 실행되는지 확인.
- 설치 파일 이름, 버전 네 파일, GitHub Release, Raw 업데이트 정보 일치 확인.

## 범위 제외

- 일반 감지 실패나 재시도 로그마다 복구창을 표시하지 않는다.
- 여러 과거 버전 목록을 보관하거나 선택하는 기능은 추가하지 않는다.
- 두 버전을 서로 다른 설치 경로에 동시에 설치하지 않는다.
- PyInstaller 부트로더 자체를 수정하지 않는다.
