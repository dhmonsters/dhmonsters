# 캐릭터 캡처 저장 수정 기록

## 사용자 결정

캐릭터 템플릿은 여러 파일로 누적하지 않는다. `y_p.png` 하나가 있더라도 새 캡처를 같은 파일에 덮어쓴다.

## 확인된 문제

기준색은 계산 결과가 기존 슬라이더 값과 같으면 값 변경 신호가 발생하지 않아 설정 저장이 생략될 수 있다. 템플릿은 실행 형태에 따른 영구 사용자 경로와 스캐너 로드 경로가 일치하지 않는다.

## 적용 시점

파일 저장은 캡처 직후 완료한다. 실행 중 스캐너는 기존 구조대로 다음 F1 시작 시 설정과 템플릿을 다시 로드한다.

## 구현 결과

기준색 HSV 네 값은 캡처 후 설정 객체에 직접 기록하고 저장한다. 템플릿은 `.y_p.pending.png`를 정상 생성한 뒤 고정 파일 `y_p.png`로 교체하므로 누적되지 않는다. 설치본의 사용자 템플릿은 내장 템플릿보다 우선한다.

## 검증 결과

관련 캡처·페이지·캐릭터 감지·설정 변환 테스트는 54개 통과했다. 여기에는 기존 `y_p.png`가 실제 디스크에서 새 PNG로 교체되고 임시 파일이 남지 않는 검증이 포함된다. 기존 `mss.mss` 폐기 예정 경고 9개가 있으며 새 경고는 없다. 확장 실행에서는 오래된 Humanizer 및 이전 공격·픽업 구조를 기대하는 `tests/test_runtime.py` 6개가 별도로 실패했으며 이번 변경 파일과 관련이 없어 수정하지 않았다.
