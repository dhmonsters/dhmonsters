# 2.4.9 시작 오류 및 복구 핫픽스 계획

## 목표

- `core.recovery_protocol` 누락으로 발생한 2.4.8 시작 실패를 재발 방지와 함께 수정한다.
- 업데이트 경로가 건너뛰어진 경우에도 검증된 이전 버전 설치본을 로컬에 보관한다.
- 오류 대화상자를 성공으로 오판하지 않고 실제 UI 준비 신호로 배포본을 검증한다.
- 테스트와 설치본 검증 후 2.4.9를 배포하고 자동 업데이트 메타데이터를 갱신한다.

## 검증 기준

1. 배포 분석 목록에서 필수 복구 모듈이 빠지면 검증 테스트가 실패한다.
2. 패키지 실행 후 제한 시간 안에 준비 신호 파일이 생성되어야 한다.
3. 2.4.9 설치 전에 2.4.7 설치본과 메타데이터가 SHA-256 검증 후 보관된다.
4. 단위 테스트, 복구 실행기 테스트, 빌드, 설치본 시작 검증이 모두 통과한다.
5. 저장소와 공개 업데이트 메타데이터가 2.4.9로 일치한다.
