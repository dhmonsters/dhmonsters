# 캐릭터 캡처 드래그 완료 수정 설계

## 목표

`기준색 캡처`와 `캐릭터 템플릿 캡처`에서 마우스 이동 이벤트가 전달되지 않더라도 실제 버튼 해제 위치로 선택 영역을 확정하고 선택 창을 종료한다.

## 확인된 원인

`core_ui/shot_selector.py`의 `_Canvas.mouseReleaseEvent()`는 마우스 버튼을 놓은 이벤트의 좌표를 사용하지 않고 마지막 `mouseMoveEvent()`가 기록한 `self.cur`를 사용한다. 일부 환경에서 이동 이벤트가 생략되거나 합쳐지면 `self.cur`가 시작점에 남아 선택 영역이 2픽셀 이하로 판정된다. 이 경우 `region_selected`와 `accept()`가 실행되지 않아 창은 유지되고 다음 드래그에서 표시 수치만 초기화된다.

## 검토한 접근

1. 권장안은 마우스 해제 이벤트의 실제 위치를 `self.cur`에 반영한 뒤 기존 완료 콜백을 호출하는 것이다. 원인에 직접 대응하며 변경 범위가 가장 작다.
2. 선택 최소 크기 제한을 제거할 수 있지만 잘못된 클릭까지 저장되므로 사용하지 않는다.
3. 동기식 `QDialog.exec()`를 비동기식 `open()`으로 교체할 수 있지만 이번 원인과 무관하고 페이지 처리 범위가 커지므로 사용하지 않는다.

## 변경 범위

- `core_ui/shot_selector.py`의 `_Canvas.mouseReleaseEvent()`만 동작을 변경한다.
- `tests/test_shot_selector.py`에 이동 이벤트 없이 누르기와 놓기만 발생하는 회귀 테스트를 추가한다.
- `core_ui/pages.py`, 캡처 좌표 변환, HSV 계산, 템플릿 저장 경로는 변경하지 않는다.
- EXE 빌드, 설치본 생성, 배포는 진행하지 않는다.

## 성공 조건

- `mouseMoveEvent()` 없이 다른 좌표에서 버튼을 놓으면 `region_selected`가 정확히 한 번 발생한다.
- 선택 창이 Accepted 상태로 종료된다.
- 기존 좌표 환산 테스트와 페이지 캡처 테스트가 모두 통과한다.
