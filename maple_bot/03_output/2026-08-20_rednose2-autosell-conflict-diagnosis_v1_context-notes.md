# 빨코2와 자동판매 충돌 진단 기록

## 사진 로그 분석

- 사진 1의 짧은 미검출은 마지막 좌측 이동 의도를 유지해 X=42에서 다시 검출되고 목표 X=41 도착으로 정상 복구됐다.
- 사진 2는 `stair7 up commit` 뒤 위 텔레포트를 실행했지만 Y 확인에 실패해 우측 텔레포트를 건너뛰었다.
- 이어진 이동은 `pos=None`으로 시작했고 좌표 미검출 분기에서는 이동 제한시간을 검사하지 않아 수동 정지 전까지 계속 대기했다.
- 사진에는 `자동판매` 또는 `auto-sell` 실행 로그가 없어 사진 속 정지의 직접 원인은 자동판매가 아니다.

## 자동판매와 빨코2의 동시 실행 구조

- 자동판매 시작 시 `_junk_selling=True`가 되어 일반 이동·공격·픽업 틱과 빨코2의 활성 조건이 중지된다.
- 판매 작업은 별도 `JunkSellWorker` 스레드에서 빨코2의 `prepare_auto_sell_from_floor2()`를 직접 호출한다.
- 빨코2 스레드가 비활성 신호를 확인하고 현재 복합 입력을 끝냈는지 기다리는 확인 절차는 없다.
- 두 스레드는 잠금 없는 동일한 `RouteInputOwner`를 공유하므로 자동판매 시작 경계에서 방향키 또는 텔레포트 키 해제가 겹칠 가능성이 있다.
- 자동판매가 본 판매 단계에 들어간 이후에는 다른 행동 틱이 차단되므로 지속적으로 두 동작이 동시에 실행되는 구조는 아니다.
- `_junk_selling=True`는 판매 스레드 내부에서 설정된다. 스레드를 만든 직후 메인 흐름이 빨코2 러너를 시작할 수 있어 시작 경계 경쟁이 존재한다.
- `sell_on_start` 실행은 캐릭터 스캐너 시작보다 먼저 요청되므로 첫 위치가 아직 준비되지 않은 상태에서 진입을 시도할 수 있다.

## 추가 영향

- `sell_on_start`가 켜져 있으면 F1 시작 직후 자동판매가 실행된다.
- 주기 자동판매는 처음 켰을 때 즉시 실행하지 않고 설정 간격 뒤 실행된다.
- 진입 또는 판매 실패 시 5초 뒤 다시 예약되므로 실패가 반복되면 빨코2 사냥을 5초 간격으로 계속 끊을 수 있다.

## 설정 및 테스트 확인

- 현재 소스 작업 폴더와 릴리스 작업 폴더의 저장 설정은 모두 `auto_sell_enabled=false`, `sell_on_start=false`다.
- 따라서 첨부 사진을 만든 다른 PC의 실제 설치 설정은 사진만으로 확인할 수 없다.
- `tests/test_auto_sell_runtime.py`와 `tests/test_rednose2_recovery_autosell_minimap.py`의 기존 테스트 11개는 통과했다.
- 기존 테스트는 판매 진입·복귀 결과와 예약 상태를 확인하지만 빨코2 스레드가 완전히 멈춘 뒤 판매 이동을 시작하는 상호배제는 검증하지 않는다.

## 결론

- 사진 속 장시간 정지는 자동판매가 아니라 stair7 위 텔레포트 직후 연속 미검출과 이동 루프의 무제한 대기 결함이다.
- 자동판매를 켜면 정상 판매 중 지속 충돌은 막혀 있지만, 판매 시작 순간에는 빨코2 입력과 경쟁할 수 있다.
- 시작 시 판매 또는 5초 실패 재시도가 활성화된 환경에서는 이 짧은 경쟁이 반복되어 사냥이 끊기는 현상으로 보일 수 있다.
