# 배포 실행파일 모듈 경로 격리 기록

## 추가 원인

- PyInstaller 실행에서 `run_integrated.py`의 `ROOT`는 설치 루트가 아니라 `_internal`이다.
- 기존 코드는 `ROOT.parent`도 검색 경로 맨 앞에 넣어 설치 루트의 구형 `core_ui`가 새 내장 모듈보다 먼저 선택될 수 있었다.
- 2.4.11 설치기는 루트의 구형 코드 폴더만 제거하고 `_internal` 전체 교체는 하지 않았다.

## 결정

- 배포 실행에서는 PyInstaller가 제공하는 `sys._MEIPASS`만 우선 검색 경로로 사용한다.
- 설치기는 `_internal`을 먼저 제거해 새 배포 묶음으로 완전히 교체한다.
- AppData의 사용자 설정과 템플릿은 변경하지 않는다.

## 구현 확인

- 배포 검색 경로 함수가 없어 회귀 테스트 2개가 수정 전 실패했다.
- 배포본은 `sys._MEIPASS`만 사용하고 소스 실행은 프로젝트 루트와 부모 경로를 유지하도록 분리했다.
- 관련 UI, 설정, 배포, 복구 테스트 51개가 통과했다.
- 설치 루트에 구형 `core`, `core_ui`, `ui`와 `_internal` 표식 파일을 둔 상태로 2.4.12를 덮어썼다.
- 설치 후 구형 루트 폴더와 `_internal` 표식 파일이 모두 제거됐고 시작 검사는 종료 코드 0, 버전은 2.4.12였다.
- 설치파일 크기는 69,119,314바이트이며 SHA-256은 `F2C7ED058F14AD8611286D9529DFF6CF2D99ABAAFBAD68C1CD956CC62963D99A`이다.
- GitHub Release `v2.4.12`의 원격 설치파일 크기와 SHA-256이 로컬 파일과 일치했다.
- `main`의 자동 업데이트 메타데이터를 2.4.12로 게시하고 원격 원문을 확인했다.
- 배포 직전 관련 회귀 테스트 51개가 통과했고, 빌드된 `ClaudeApp.exe --release-startup-check`는 종료 코드 0이었다.
