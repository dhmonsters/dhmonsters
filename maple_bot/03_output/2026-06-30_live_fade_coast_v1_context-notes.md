# 라이브 페이드 이후 추적 보강 컨텍스트 노트

## 로그 판단
- `20260630_134158_001` 세션은 `SESSION_START` 기준 fps가 20이었다.
- 실제 `CANDIDATES` 이벤트 간격은 평균 약 178ms였고 실제 처리 속도는 약 5.6fps였다.
- f0부터 f31까지는 흰색 앵커가 잡혔지만 f32부터 후보가 0개가 되었고, f36부터 `hold_limit_exceeded`, `primary_missing`, `no_target`으로 떨어졌다.
- 따라서 완성한 시간축 selector가 빠진 것이 아니라, selector에 넣을 후보가 사라진 것이 핵심 원인이다.

## 구현 판단
- motion coast는 정답 GT를 쓰지 않는다.
- 라이브에서 이미 본 흰색 앵커의 최근 위치와 속도만 사용해서 후보가 0개인 프레임에 임시 후보를 하나 넣는다.
- raw 후보가 이미 있는 프레임에는 motion coast를 끼워 넣지 않는다.
- UI 미리보기 PNG는 녹화 검증용 부가 자료이므로 매 프레임 저장하지 않고 5프레임 간격으로 줄였다.
- CCTV 화면은 `latest_preview_frame`으로 메모리 전달해 디스크 왕복을 줄였다.
