# Puzzle2 연속 감시 및 Interception 컨텍스트

## 고정 결정

- 사용자가 선택한 동작은 게임창을 강제로 앞으로 가져오지 않는 방식이다.
- 게임창이 없거나 전면이 아니면 프로그램은 종료하지 않고 대기한다.
- 전체 종료 조건은 F12와 솔버 종료 버튼뿐이다.
- 시작할 때 이전 Puzzle2 세션을 삭제하지만 새 배포본 검증 전 기존 ZIP은 삭제하지 않는다.
- 받은 V6497 SOT 코어의 추적 알고리즘은 유지하고 Puzzle2 어댑터가 반복 실행과 저장 수명주기를 관리한다.
- 일반 마우스 fallback은 사용하지 않는다. Interception 활성화 실패는 명확한 오류로 표시한다.
- 화면 커서 보정은 흰색 타겟이 확실한 구간에서만 학습하고 이후에는 고정한다. 계속 학습하면 과거와 같이 우측 아래 표류가 발생할 수 있다.

## 기존 구조에서 확인한 문제

- `SotLiveRuntime`은 `run_one_shot()`을 한 번만 호출해 대기 만료나 성공 뒤 스레드가 끝난다.
- 시작할 때마다 타임스탬프 세션 폴더가 추가되며 이전 폴더를 정리하지 않는다.
- V6497 마우스 이동은 상대 이동 함수에 직접 연결되어 있고 `run_integrated.py`의 Interception 선택기를 사용하지 않는다.
- 패키지 설정에 Interception 모듈이 명시되어 있지 않다.

## 구현 방향

- UI에서 시작한 스레드는 반복 루프를 실행하고, 동기 단위 테스트는 제한된 회수로 같은 루프를 검증한다.
- 대기 만료와 게임창 관련 오류는 재시도 대상으로 분류하고 짧은 중단 가능한 대기 후 다시 호출한다.
- 성공 뒤에는 종료 화면을 바로 새 퍼즐로 오인하지 않도록 재무장 지연을 둔다.
- 세션 정리는 `output_root` 바로 아래 항목만 대상으로 하며, 경로가 예상 루트인지 확인한 뒤 수행한다.

## 구현 및 검증 결과

- 연속 실행 루프는 `QUEST_WAIT_TIMEOUT`, 게임창 부재, 전면 창 손실, 추적 실패를 재시도 대상으로 처리한다.
- 성공 횟수를 누적하고 성공 뒤 `WAIT_REARM`을 거쳐 다시 `WAIT_QUEST`로 진입한다.
- 대기와 재무장 중에도 F12를 짧은 간격으로 확인한다.
- 게임창이 전면이 아니면 `activate()`를 호출하지 않는다.
- Interception 마우스는 `move_to()`와 `click()`만 노출하며 다른 입력 백엔드를 거부한다.
- 분홍 커서 보정은 직전 목표와 다음 화면 커서 중심의 오차를 초반에만 학습한다. 추적 단계에서는 고정한다.
- Python 3.12, Torch 2.6.0+cu124 환경이 `sm_61`부터 `sm_90`까지 포함함을 확인했다.
- RTX 4060에서 V6497 모델 CUDA 추론 점수 `0.7490234375`를 확인했다.
- 패키지 내부에서 Interception 필수 API 세 개를 직접 불러오는 검사를 통과했다.
- 최종 관련 테스트는 26개가 통과했다.
- 빌드 임시 폴더는 ZIP 검증 뒤 제거됐다.
