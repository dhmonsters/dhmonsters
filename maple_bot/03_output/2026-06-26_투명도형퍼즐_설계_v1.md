# 투명도형 퍼즐 추적 고도화 설계

## 목적

이 문서는 투명도형 퍼즐 추적 고도화 작업의 기준 정의와 아키텍처를 고정하기 위한 설계도다.

목표는 녹화된 16개 GT만 맞추는 것이 아니라, 허가된 테스트 퍼즐과 녹화 자료에서 매번 새로 나오는 랜덤 판의 타겟 정체성을 끝까지 추적하고 검증 가능한 기록을 남기는 것이다.

## 범위

이 설계는 합법적으로 준비된 퍼즐 게임, 녹화 영상, 이미지 시퀀스, 디버그 로그를 분석하는 로컬 검증 도구를 대상으로 한다.

실제 서비스의 보호 장치를 우회하거나 자동 입력으로 해제하는 실행 기능은 이 설계 범위에 넣지 않는다.

`puzzle.py`는 추적 판별기, 분석 UI, 녹화, 알림, 로그 검증을 묶는 실험 앱의 진입점으로 둔다.

## 문제 정의

이 퍼즐은 매 프레임에서 정답 후보를 새로 고르는 문제가 아니다.

시작 시점에 명확히 주어진 타겟의 정체성을 시간축 위에서 유지하고, 투명화, 겹침, 배경 데칼 혼입으로 관측이 오염되는 구간에서는 판단을 보류했다가, 분리 이후 다시 원래 타겟의 신분을 복원하는 문제다.

따라서 목표는 프레임별 최고 점수 후보 선택기가 아니라, 처음 타겟의 신분을 끝까지 상속시키는 시간 기반 정체성 판별기를 만드는 것이다.

## 핵심 판단

검출 문제는 거의 해결된 것으로 본다.

남은 병목은 후보 10개에서 20개 중 무엇이 처음 타겟의 신분을 이어받는지 고르는 정체성 판별 문제다.

겹침 구간은 실패 예외가 아니라 1급 상태로 설계한다.

후보를 더 많이 뿌리는 것보다, 후보 path가 전체 시간축에서 처음 타겟이었다는 설명을 얼마나 잘 유지하는지가 중요하다.

## 색상 신호의 위치

색상은 메인 해결축이 아니다.

메인 해결축은 시간 기반 정체성 유지다.

다만 컬러 버전에서는 배경, 글라스 테두리, 투명화 과정, 렌더링 잔차에서 약한 색상 차이가 생길 수 있으므로 색상은 보조 관측 신호로 취급한다.

흑백 업그레이드는 이 보조 신호를 약화시키고, 문제를 명암, 경계, 질감, 시간 연속성 중심으로 강제한 변화로 본다.

## 기존 UI 참고 기준

기존 탭 기반 UI는 `ui/main_window.py`, `ui/tab_main.py`, `ui/tab_settings1.py`를 참고한다.

기존 신형 콘솔 UI는 `core_ui/shell.py`, `core_ui/theme.py`를 참고한다.

새 퍼즐 앱은 신형 콘솔 UI의 상단 내비게이션, 중앙 작업 화면, 하단 로그 드로어 구조를 따른다.

기존 텔레그램 설정, 경보음, 로그 필터, 화면 캡처 설정은 재사용 가능한 개념으로 본다.

## 탐지 영역 고정

탐지 영역은 퍼즐을 푸는 영역이 아니라, 거탐 또는 테스트 퍼즐이 등장했는지 확인하는 감지 전용 영역이다.

기존 설정의 `settings1.lie_detector.region` 역할을 기준으로 삼는다.

이 영역은 타이틀, 팝업 상단, 안내 문구, 퍼즐 출현 신호처럼 “퍼즐이 시작됐다”는 이벤트를 잡기 위한 영역이다.

탐지 영역의 출력은 `감지됨`, `감지 점수`, `감지 시각`, `감지 프레임`, `감지 근거`까지만 담당한다.

탐지 영역은 타겟 추적 후보를 만들지 않는다.

탐지 영역은 정체성 판별에도 직접 들어가지 않는다.

탐지 영역이 퍼즐 시작을 확정하면 그 순간부터 새 추적 세션을 열고, 퍼즐 영역의 프레임 스트림과 녹화를 시작한다.

탐지 영역은 오탐 방지를 위해 연속 감지 조건을 가진다.

단발 감지는 로그에 남기되 세션 시작으로 승격하지 않는다.

탐지 영역은 게임창 기준 좌표계에 묶는다.

절대 모니터 좌표, 게임창 client 좌표, 프레임 내부 좌표를 섞지 않는다.

감지 로그에는 반드시 어떤 좌표계로 기록됐는지 남긴다.

## 퍼즐 영역 고정

퍼즐 영역은 실제 추적, 후보 생성, 정체성 판별, 검증, 녹화의 기준이 되는 유일한 판이다.

기존 설정의 `settings1.transparent_shape.board_roi` 역할을 기준으로 삼는다.

이 영역은 퍼즐판 내부만 포함하고, 타이틀, 안내 문구, 버튼, 게임 UI, 외곽 여백은 최대한 제외한다.

퍼즐 영역 안에서만 YOLO 후보, raw 후보, 배경성 점수, 겹침 상태, path 점수를 계산한다.

퍼즐 영역 밖에서 발견된 후보는 추적 후보가 아니다.

퍼즐 영역은 세션 시작 시 한 번 확정하고, 그 세션 동안 고정한다.

게임창 이동이나 해상도 변화가 감지되면 기존 세션을 그대로 이어가지 않고 `ROI_INVALID` 상태로 표시한다.

퍼즐 영역은 비율 좌표와 세션 절대 좌표를 함께 보관한다.

비율 좌표는 재사용과 재현을 위한 설정값이다.

세션 절대 좌표는 녹화, 오버레이, 텔레그램 스냅샷, JSONL 재생을 위한 실행값이다.

퍼즐 영역의 원본 crop은 항상 저장 가능해야 한다.

오버레이 crop은 설명 자료용이고, 원본 crop은 재분석 자료용이다.

## 탐지 영역과 퍼즐 영역의 관계

탐지 영역은 문지기다.

퍼즐 영역은 경기장이다.

탐지 영역이 세션을 열고, 퍼즐 영역이 모든 추적 판단을 책임진다.

탐지 영역의 점수가 높다고 해서 추적 신뢰도가 올라가지 않는다.

퍼즐 영역의 추적이 흔들린다고 해서 탐지 영역을 다시 후보 생성에 끌어오지 않는다.

두 영역은 같은 게임창 기준 좌표계에서 해석하되, 역할과 로그 스키마는 분리한다.

## 세션 시작 규칙

탐지 영역에서 퍼즐 출현 신호가 연속 조건을 만족하면 `PUZZLE_DETECTED` 이벤트를 만든다.

`PUZZLE_DETECTED` 이벤트가 발생하면 즉시 원본 CCTV 녹화, 퍼즐 crop 녹화, JSONL trace를 시작한다.

세션 시작 시 게임창 위치, 탐지 영역, 퍼즐 영역, 해상도, DPI 배율, 입력 출처를 한 번에 기록한다.

이 값들은 이후 모든 프레임 로그의 기준 메타데이터가 된다.

세션 중 ROI가 바뀌면 조용히 보정하지 않고 명시적으로 로그에 남긴다.

## 전체 아키텍처

`puzzle.py`는 진입점만 담당한다.

내부 책임은 아래 모듈로 나눈다.

### 1. 입력 계층

이미지 시퀀스, 영상 파일, 화면 녹화, 디버그 JSONL을 같은 프레임 스트림으로 변환한다.

각 프레임에는 원본 이미지, 시간, 프레임 번호, 입력 출처, ROI 정보를 붙인다.

### 2. 관측 계층

YOLO와 보조 후보 생성기로 매 프레임 후보 박스와 중심을 만든다.

이 계층은 정답을 고르지 않는다.

목표는 정답 후보가 빠지지 않게 후보군을 유지하는 것이다.

### 3. 배경성 판별 계층

각 후보가 독립 타겟인지, 배경 데칼인지, 반복 배경으로 설명되는지 평가한다.

강체 배경 흐름, 한 바퀴 전 유사도, 주변 질감 동조, ring/background texture, 색상 보조 신호를 약한 증거로 누적한다.

### 4. 정체성 계층

처음 타겟에서 시작한 신분 가설을 유지한다.

프레임별 최고 후보를 고르지 않고, 전체 경로가 처음 타겟의 신분을 자연스럽게 상속하는지 평가한다.

### 5. 겹침 상태 계층

박스 병합, 중심 밀림, 후보 소실, 갑작스러운 후보 전환을 겹침 의심 상태로 다룬다.

이 상태에서는 신분 결정을 보류하고, 분리 이후 재확인한다.

### 6. 경로 평가 계층

단일 후보 점수보다 후보 path의 설명력을 본다.

좋은 path는 시작 anchor에서 자연스럽게 출발하고, 배경 데칼로 설명되지 않으며, 겹침 중 신분을 성급히 바꾸지 않고, 분리 후에도 일관된 이동 가능성을 가진다.

### 7. 검증 계층

GT, frame replay, 녹화 영상, 후보 로그를 같은 기준으로 채점한다.

결과는 성공 여부만 남기지 않고 실패 원인, 겹침 구간, 후보 전환 시점, 보류 판단, 재획득 판단까지 남긴다.

## 상태 모델

`INIT_VISIBLE`은 흰색 타겟이 명확한 준비 구간이다.

`TRACK_CONFIDENT`는 정체성이 안정적으로 이어지는 구간이다.

`OCCLUSION_SUSPECTED`는 겹침이나 박스 병합이 의심되는 구간이다.

`IDENTITY_HOLD`는 판단을 보류하고 기존 신분을 유지하는 구간이다.

`REACQUIRE`는 분리 이후 원래 타겟을 다시 확인하는 구간이다.

`LOST`는 복원 근거가 부족해 실패로 남기는 구간이다.

## UI 설계

UI는 분석자의 시선을 중앙 퍼즐 화면에 두고, 주변 패널은 판단 근거를 빠르게 확인하는 형태로 둔다.

### 상단 바

프로젝트명, 현재 입력 출처, 상태 칩, 녹화 상태, 텔레그램 연결 상태를 보여준다.

상태 칩은 대기, 재생, 분석 중, 겹침 의심, 보류, 재획득, 실패로 나눈다.

### 좌측 입력 패널

이미지 시퀀스 열기, 영상 열기, JSONL 열기, 화면 녹화 시작, ROI 선택을 배치한다.

입력 출처를 바꿔도 중앙 화면과 하단 타임라인은 같은 구조로 동작해야 한다.

### 중앙 CCTV 화면

인게임 창 또는 녹화 프레임을 실시간 CCTV처럼 보여준다.

오버레이는 후보 박스, 선택 path, 보류 구간, 겹침 의심 박스, 재획득 후보를 색상과 선 종류로 구분한다.

분석자가 나중에 녹화만 보고도 왜 그 판단이 나왔는지 이해할 수 있어야 한다.

### 우측 분석 패널

현재 후보 수, 선택 후보, 정체성 신뢰도, 배경성 점수, 겹침 점수, 재획득 근거, 색상 보조 신호 상태를 표시한다.

숫자만 나열하지 않고 “왜 이 후보가 살아남았는지”를 짧은 문장으로 보여준다.

### 하단 타임라인

프레임 이동, 재생 속도, 북마크, 실패 구간, 겹침 구간, 보류 구간, 재획득 구간을 표시한다.

타임라인에서 구간을 클릭하면 해당 프레임과 관련 로그가 함께 이동해야 한다.

### 로그 드로어

기존 `core_ui/shell.py`의 로그 드로어 방식을 따른다.

로그 카테고리는 입력, 관측, 정체성, 겹침, 재획득, 알림, 녹화, 오류로 나눈다.

로그는 화면 표시용과 검증 자료용을 분리한다.

화면 표시용은 사람이 읽기 쉽게 줄이고, 검증 자료용은 JSONL로 자세히 남긴다.

## 텔레그램과 알림

텔레그램은 분석 이벤트 알림과 검증 자료 알림에 사용한다.

거탐 또는 테스트 퍼즐 감지 시 알림, 분석 시작, 분석 실패, 재획득 실패, 녹화 완료, 리포트 생성 완료를 알림 이벤트로 둔다.

알림에는 원본 프레임 일부, 현재 상태, 저장된 녹화 파일명, JSONL 파일명을 포함할 수 있다.

토큰과 Chat ID 설정은 기존 `ui/tab_settings1.py`의 개념을 참고하되, 새 앱에서는 알림 설정 패널로 분리한다.

## 화면 녹화와 검증 자료

녹화는 필수 기능으로 둔다.

녹화 대상은 원본 CCTV 화면, 분석 오버레이 화면, 후보 로그 JSONL, 요약 리포트 네 가지다.

원본 녹화는 나중에 재분석할 수 있어야 한다.

오버레이 녹화는 사람에게 설명하기 위한 자료다.

JSONL은 재현 가능한 검증 자료다.

요약 리포트는 성공률, 평균 오차, 실패 원인, 겹침 횟수, 보류 횟수, 재획득 성공 여부를 담는다.

## 데이터 산출물

모든 산출물은 `03_output` 아래 날짜별 폴더로 저장한다.

녹화 파일명은 `YYYY-MM-DD_투명도형퍼즐_record_v1.mp4` 형식을 따른다.

분석 로그는 `YYYY-MM-DD_투명도형퍼즐_trace_v1.jsonl` 형식을 따른다.

요약 리포트는 `YYYY-MM-DD_투명도형퍼즐_report_v1.md` 형식을 따른다.

이름이 겹치면 버전 번호를 올린다.

## 테스트 전략

1차 테스트는 기존 16개 GT로 한다.

2차 테스트는 녹화 영상 replay로 한다.

3차 테스트는 새 랜덤 테스트 퍼즐 녹화로 한다.

성공 기준은 단순 종료 성공이 아니라, 정체성 전환 없이 타겟 신분을 유지했는지로 본다.

실패 리포트는 반드시 `검출 누락`, `후보 선택 실패`, `박스 내부 중심 복원 실패`, `겹침 중 신분 전환`, `분리 후 재획득 실패`, `배경 데칼 오판` 중 하나로 분류한다.

## 설계 원칙

후보 생성과 후보 선택을 섞지 않는다.

겹침 구간을 예외 처리하지 않고 상태로 승격한다.

현재 프레임의 최고 점수보다 전체 path의 정체성 설명력을 우선한다.

화면에 보이는 판단과 파일에 남는 판단 근거가 일치해야 한다.

운영 기능은 분석 기능을 방해하지 않아야 한다.

알림, CCTV, 녹화, 로그는 모두 검증 자료를 남기기 위한 주변 장치로 둔다.
