# 큰 지도 전역좌표 맵핑 설계

## 1. 목표

현재 `run_integrated.py` 실행 경로는 미니맵 캡처 내부 좌표를 지도 전체 좌표처럼 사용한다. 미니맵이 큰 지도의 일부만 보여주는 이동 창형 구조에서는 화면이 이동할 때 같은 로컬 좌표가 다른 실제 위치를 가리킨다.

이번 개선의 목표는 큰 지도 이미지의 절대좌표를 기준으로 현재 미니맵 창, 캐릭터, 사냥 영역, 공격 범위, 이동점과 액션점을 일관되게 관리하는 것이다. 사용자는 사냥 구역 밖에도 명시적인 이동점과 액션점을 배치할 수 있어야 하며, 반복 루트와 일회성 목적지 이동을 모두 사용할 수 있어야 한다.

## 2. 확정된 요구사항

- 지도 구조는 큰 지도 일부만 미니맵에 보이는 `이동 창형`이다.
- 큰 지도 원본 이미지를 불러와 사용한다.
- 큰 지도와 미니맵에서 같은 기준점 두 곳을 찍어 원점과 동일 비율 배율을 보정한다.
- 큰 지도 이미지와 게임 미니맵의 방향 및 가로세로 비율은 같다.
- 전역 위치는 수동 기준점과 미니맵 배경 추적을 함께 사용하는 혼합 방식으로 계산한다.
- 사냥·이동 구역 밖에서는 사용자가 배치한 이동점과 액션점만 실행한다.
- 액션점은 키, 누르는 시간, 반복 횟수, 실행 후 대기만 설정한다.
- 저장된 순서형 반복 루트와 일회성 목적지 이동을 모두 지원한다.
- 기존 `config.json`의 로컬 좌표는 보정 완료 시 전역 좌표로 자동 변환한다.
- 전역 추적이 끊겨도 마지막 위치와 로컬 변화로 추정하며 시간 제한 없이 모든 명령을 계속 실행한다.
- 추적 상태는 확정 위치와 추정 위치로 구분해 화면에 표시한다.

## 3. 좌표 모델

### 3.1 좌표계 구분

- `world` 좌표는 불러온 큰 지도 이미지의 픽셀 좌표다. 모든 영구 설정의 기준이다.
- `viewport` 좌표는 현재 미니맵 캡처의 좌상단이 큰 지도에서 차지하는 위치다.
- `local` 좌표는 현재 미니맵 캡처 내부의 픽셀 좌표다.
- `screen` 좌표는 실제 게임 화면 캡처의 픽셀 좌표다. 몬스터 탐지와 공격 범위 계산에만 사용한다.

캐릭터 전역 위치는 다음 관계로 계산한다.

```text
world_character = viewport_origin + local_character * calibration_scale
```

큰 지도에서 현재 미니맵 안의 위치를 찾거나 반대로 투영할 때는 동일한 배율과 원점 변환을 사용한다. 화면 픽셀 기반 공격 범위는 기존 `camera_w_ratio` 변환을 유지하되, 표시할 때만 현재 전역 캐릭터 위치 주변의 큰 지도 좌표로 투영한다.

### 3.2 두 점 보정

사용자는 큰 지도 이미지에서 기준점 A와 B를 찍고, 현재 미니맵에서 같은 지점 A와 B를 찍는다. 두 좌표쌍으로 동일 비율 배율과 이동 오프셋을 계산한다.

보정 완료 조건은 다음과 같다.

- 두 기준점 사이 거리가 최소 허용값보다 크다.
- 두 좌표계에서 A에서 B로 향하는 방향 차이가 허용 오차 안이다.
- 계산된 배율이 양수다.
- 역변환 후 두 기준점의 재투영 오차가 허용 범위 안이다.

## 4. 구성요소 설계

### 4.1 큰 지도 모델

큰 지도 모델은 다음 정보를 소유한다.

- 지도 식별자와 이미지 경로.
- 이미지 폭과 높이.
- 기준점 두 쌍과 계산된 배율·이동 오프셋.
- 사냥 영역과 기타 지정 영역.
- 이동점, 사다리점, 액션점.
- 노드 사이 연결과 저장된 반복 루트.
- 기존 설정 변환 완료 여부와 원본 백업 경로.

큰 지도 이미지는 설정 파일에 복사하지 않고 경로로 참조한다. 경로가 없거나 이미지를 읽을 수 없으면 전역 모드는 시작하지 않고 기존 로컬 모드만 사용할 수 있게 한다.

### 4.2 미니맵 창 추적기

추적기는 현재 미니맵 배경을 직전 프레임 및 큰 지도 이미지와 비교해 `viewport_origin`을 갱신한다.

- 정상 매칭 시 상태는 `confirmed`다.
- 매칭 신뢰도가 기준 미만이면 상태는 `estimated`다.
- `estimated` 상태에서는 마지막 확정 원점, 최근 이동 방향, 로컬 캐릭터 변화량으로 전역 위치를 계속 추정한다.
- 매칭이 복구되면 새 확정 좌표로 즉시 순간이동시키지 않고 짧은 보정 구간을 거쳐 오차를 흡수한다.
- 사용자가 선택한 정책에 따라 `estimated` 상태의 시간 제한과 명령 제한은 두지 않는다.

화면에는 현재 전역 좌표, 창 원점, 매칭 신뢰도, `확정` 또는 `추정` 상태를 표시한다.

### 4.3 이동점과 연결망

이동점은 큰 지도 좌표와 도착 허용 반경을 갖는다. 사다리 연결은 기존 `BlockRunner`가 필요로 하는 사다리 X, 위·아래 Y, 방향, 잡기 설정을 전역 좌표로 저장한다.

연결은 한 노드에서 다른 노드로 이동하는 방법을 나타낸다.

- 같은 층 좌우 이동은 `walk` 또는 `teleport`를 사용한다.
- 층 이동은 등록된 사다리 연결을 사용한다.
- 등록되지 않은 공간을 자동 탐색하거나 임의로 연결하지 않는다.
- 일회성 목적지 이동은 등록된 연결망에서 최단 노드 경로를 계산한다.
- 반복 루트는 사용자가 저장한 노드 순서를 그대로 실행하며 필요할 때 반복한다.

### 4.4 액션점

액션점은 큰 지도 좌표와 도착 허용 반경을 가지며 다음 필드만 허용한다.

- 입력 키.
- 키를 누르는 시간.
- 반복 횟수.
- 반복 사이 대기.
- 액션 완료 후 대기.

액션점은 사냥 구역 안팎 어디든 배치할 수 있다. 캐릭터가 허용 반경에 들어왔을 때만 실행하며, 한 번의 노드 진입에서 중복 실행하지 않는다. 복합 조건식, 스크립트, 임의 매크로 편집은 범위에서 제외한다.

### 4.5 사냥·공격 영역

- 사냥 영역은 큰 지도 절대좌표의 사각형 또는 다각형으로 저장한다.
- 기존 몬스터 감지용 화면 캡처 영역은 별도 `screen` 좌표 설정으로 유지한다.
- 공격 범위는 캐릭터 중심 화면 픽셀 설정을 유지하고 큰 지도 표시용으로만 변환한다.
- 사냥 영역 밖에서는 자동 사냥 판단을 시작하지 않는다.
- 사냥 영역 밖의 공격은 사용자가 명시적으로 배치한 액션점으로만 실행한다.

## 5. 설정 저장 구조

기존 설정을 유지하면서 `world_map`과 `navigation` 구성을 추가한다.

```json
{
  "world_map": {
    "enabled": true,
    "image_path": "maps/example.png",
    "image_width": 1000,
    "image_height": 500,
    "calibration": {
      "world_points": [[120, 80], [820, 310]],
      "local_points": [[25, 20], [245, 92]],
      "scale": 3.18,
      "offset": [40.5, 16.4]
    },
    "tracking_policy": "continue_estimated"
  },
  "navigation": {
    "nodes": [
      {
        "id": "node-001",
        "kind": "waypoint",
        "x": 620.0,
        "y": 210.0,
        "arrival_radius": 4.0,
        "label": "포탈 앞",
        "action": null
      },
      {
        "id": "node-002",
        "kind": "action",
        "x": 820.0,
        "y": 210.0,
        "arrival_radius": 4.0,
        "label": "포탈 진입",
        "action": {
          "key": "up",
          "hold_sec": 0.2,
          "repeat": 1,
          "repeat_interval_sec": 0.0,
          "wait_after_sec": 1.0
        }
      }
    ],
    "edges": [
      {
        "id": "edge-001",
        "from": "node-001",
        "to": "node-002",
        "bidirectional": true,
        "traversal": "walk",
        "ladder": null
      }
    ],
    "routes": [
      {
        "id": "route-001",
        "name": "기본 반복 루트",
        "node_ids": ["node-001", "node-002"],
        "loop": true
      }
    ]
  }
}
```

필드명과 의미는 위 구조로 고정한다. `nodes.kind`는 `waypoint`와 `action`만 허용한다. 이동 방법은 노드가 아니라 `edges.traversal`에 저장하며 `walk`, `teleport`, `ladder`만 허용한다. `ladder` 연결일 때만 `ladder` 객체에 `x`, `y_top`, `y_bot`, `direction`, `exit_side`, `grab_side`, `jump_offset`을 저장한다. 데이터 클래스에서 검증한 뒤 JSON으로 직렬화하며 알 수 없는 필드는 기존 `Block.from_dict`처럼 무시해 전방 호환성을 유지한다.

## 6. 기존 설정 자동 변환

보정이 완료된 시점의 현재 미니맵 창 원점을 기준으로 기존 데이터를 변환한다.

- `floor_hunt.route`의 `pos_x`, `pos_y`, `target_x`, `start_x`, `end_x`, 사다리 좌표를 전역 좌표로 변환한다.
- 기존 `zones`의 좌우 경계와 Y 범위를 전역 영역으로 변환한다.
- 기존 설정은 변환 전에 프로젝트 루트의 `config.pre_world_map_YYYYMMDD_HHMMSS.json`으로 보존한다.
- 변환 완료 표식을 저장해 같은 설정을 두 번 변환하지 않는다.
- 변환 중 검증에 실패하면 새 전역 설정을 저장하지 않고 기존 로컬 설정을 유지한다.

## 7. 실행 흐름

1. `run_integrated.py`가 기존 방식대로 설정과 런타임을 조립한다.
2. 전역 모드가 활성화되어 있으면 큰 지도와 보정값을 로드한다.
3. 미니맵 캡처에서 캐릭터 로컬 위치와 배경 매칭 위치를 얻는다.
4. 전역 위치 공급자가 큰 지도 캐릭터 좌표와 추적 상태를 갱신한다.
5. 반복 루트 또는 일회성 목적지 요청이 전역 노드 경로로 변환된다.
6. 경로의 각 연결은 기존 `BlockRunner`가 실행할 수 있는 임시 로컬 목표로 변환된다.
7. 액션점 도착 시 제한형 액션 실행기가 키 입력을 수행한다.
8. 추적이 끊기면 `estimated` 상태로 전환하고 동일한 흐름을 시간 제한 없이 계속한다.

## 8. UI 흐름

동선·이동 페이지에 큰 지도 편집 모드를 추가한다.

- 큰 지도 이미지 불러오기.
- 기준점 A·B를 큰 지도와 현재 미니맵에서 각각 선택.
- 보정 결과와 재투영 오차 확인.
- 사냥 영역 그리기 및 이동.
- 이동점, 사다리점, 액션점 배치.
- 노드 연결과 반복 루트 순서 편집.
- 목적지 노드 선택 후 일회성 이동 시작.
- 현재 미니맵 창 테두리, 캐릭터 전역 위치, 추적 신뢰도 표시.
- 기존 로컬 설정 변환 미리보기와 적용.

기존 `RouteCanvas`의 미니맵 좌표 편집은 유지하되 전역 모드에서는 큰 지도 좌표 변환기를 통해 읽고 쓴다. 기존 로컬 모드는 전역 지도 미설정 시 호환 경로로 유지한다.

## 9. 실패 처리

- 지도 이미지 누락 시 전역 모드 비활성화와 원인 로그를 남긴다.
- 두 점 보정이 유효하지 않으면 저장하지 않고 다시 선택하도록 안내한다.
- 배경 매칭 실패 시 `estimated` 상태로 전환하되 이동과 액션은 계속한다.
- 목적지까지 등록된 연결 경로가 없으면 해당 요청만 실패시키고 입력키를 해제한다.
- 액션 키가 비어 있거나 반복 횟수가 0이면 저장 단계에서 거부한다.
- 설정 자동 변환 실패 시 백업과 기존 설정을 그대로 유지한다.
- 런타임 정지 또는 안전 모드 진입 시 기존과 동일하게 모든 유지 입력을 해제한다.

## 10. 검증 기준

- 두 점 보정과 역변환 오차가 허용 범위 안이다.
- 미니맵 창이 움직여도 동일한 실제 지점의 전역 좌표가 안정적으로 유지된다.
- 기존 로컬 루트가 전역 좌표로 변환된 뒤 같은 위치를 가리킨다.
- 사냥 구역 밖 이동점까지 이동할 수 있다.
- 사냥 구역 밖 액션점에서 지정 키가 정확한 횟수와 시간으로 실행된다.
- 반복 루트와 일회성 목적지 이동이 같은 노드 연결망을 공유한다.
- 추적 실패 상태에서 명령이 계속되고 상태가 `추정`으로 표시된다.
- 추적 복구 후 전역 좌표가 실제 위치로 보정된다.
- 전역 지도 미설정 상태에서 기존 로컬 실행이 회귀 없이 동작한다.

## 11. 제외 범위

- 미니맵 캡처를 자동으로 이어 붙여 큰 지도 이미지를 생성하는 기능.
- 등록되지 않은 공간의 자율 탐색과 자동 길 찾기.
- 임의 스크립트 또는 복합 매크로 편집기.
- 회전, 원근, 기울어짐이 있는 지도 변환.
- 기존 몬스터 탐지 알고리즘 자체의 재설계.

## 12. 구현 순서 권장안

1. 좌표 변환과 데이터 모델을 순수 로직으로 구현하고 단위 테스트를 고정한다.
2. 큰 지도 불러오기와 두 점 보정 UI를 연결한다.
3. 미니맵 배경 추적기와 전역 위치 공급자를 연결한다.
4. 이동점·연결·액션점 편집과 저장을 연결한다.
5. 기존 `BlockRunner`에 전역 목표 변환 어댑터를 연결한다.
6. 반복 루트와 일회성 목적지 이동을 연결한다.
7. 기존 설정 자동 변환과 백업을 추가한다.
