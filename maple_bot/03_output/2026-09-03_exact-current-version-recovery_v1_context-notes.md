# 현재 설치 버전 복구본 보관 작업 기록

## 확인된 원인

- 2.4.9 설치기는 기존 설치 버전과 관계없이 2.4.7 설치파일을 복구본으로 내려받는다.
- 2.4.7 다운로드 또는 고정 SHA-256 검증이 실패하면 새 버전 설치도 중단된다.
- 이 정책은 사용자가 요구한 실제 직전 설치 버전 복구와 다르다.

## 확정된 요구사항

- 2.4.8을 포함해 예외 없이 업데이트 직전 설치 버전을 그대로 보관한다.
- 별도 버전을 설치하지 않고 설치파일과 복구 메타데이터만 보관한다.
- 복구 파일은 저장 후 SHA-256을 다시 검증한다.
- 사용자의 기존 `tests/test_block_runner.py` 변경과 무관한 파일은 건드리지 않는다.

## 구현 및 검증 기록

- 설치된 버전과 새 버전이 다를 때만 복구본을 준비한다.
- 설치된 버전에서 `Claude_vX.X.X_Setup.exe` 파일명과 공식 GitHub Release URL을 생성한다.
- 다운로드한 설치파일의 SHA-256을 계산하고 복사 후 다시 대조한다.
- `recovery.json`의 `previous_version`에는 실제 설치 버전을 기록한다.
- 신규 설치와 동일 버전 재설치에서는 기존 복구 정보를 변경하지 않는다.
- 2.4.1, 2.4.5, 2.4.8의 실제 GitHub Release 자산 이름을 확인했다.
- 실패 재현에서는 새 정책 함수가 없어 Inno Setup 하네스 컴파일이 실패했다.
- 구현 후 복구 관련 테스트 29개가 통과했다.
- 전체 설치기 검증 컴파일이 종료 코드 0으로 통과했다.
