# 사용자 맵 동선 호환 인수인계 기록

## 승인된 동작

- 배포 시에는 기본 맵 3개만 포함한다.
- 배포받은 컴퓨터에서 사용자가 추가한 맵은 저장 후 계속 유지한다.
- 빨코2와 빨코3은 기존 전용 러너를 사용한다.
- 일반 맵만 신규 또는 구형 이동 블럭 러너를 사용한다.

## 구현 전 상태

- `_ensure_required_presets`가 필수 목록 밖의 사용자 프리셋을 삭제했다.
- 사용자 맵이 삭제되면 활성 맵도 빨코2로 강제 변경됐다.
- 일반 맵에 구형 `route`만 있으면 `LegacyRouteGuard`가 이동을 차단했다.
- 빨코2·빨코3 분기는 일반 route 분기보다 먼저 평가되고 있었다.

## 구현 결과

- 필수 프리셋 밖의 이름을 삭제하던 허용 목록 반복문을 제거했다.
- 활성 맵이 실제 프리셋에 존재하면 사용자 이름을 그대로 보존한다.
- 빨코 별칭 정규화와 필수 프리셋 자동 추가는 유지했다.
- 일반 맵의 구형 `route` 분기는 `FloorHuntRunner`를 사용하도록 복원했다.
- 초기 생성과 F1 직전 설정 재적용 경로를 모두 동일하게 수정했다.
- 빨코2·빨코3 분기는 일반 route 분기보다 앞에 있어 전용 러너 우선순위가 유지된다.
- `floor_hunt_runner`가 있으면 `BotMovementLoop`를 만들지 않는 기존 정책도 유지돼 중복 이동 스레드가 생기지 않는다.

## 테스트 결과

- 사용자 맵 저장 후 `ConfigManager` 재로드에서도 활성 맵과 `route_steps`가 유지됐다.
- 빨코 별칭이 기존 빨코2 프로필을 덮어쓰지 않는 테스트가 통과했다.
- 일반 구형 route의 초기 생성 및 재적용이 `FloorHuntRunner`를 선택했다.
- 빨코2와 빨코3은 일반 구형 route가 함께 있어도 각각 전용 러너를 선택했다.
- 관련 회귀 테스트는 52개가 통과했고 기존 `mss.mss` 경고 9개만 발생했다.

## 기존 테스트 기준선

- 넓은 테스트 묶음의 실패 중 28개는 수정 전 v2.3.11 배포 소스에서도 동일하게 발생했다.
- 해당 실패는 제거된 Humanizer 생성자 API, `route` 대신 `route_steps`를 쓰게 된 캔버스, 기존 런타임 기대값 불일치다.
- 이번 변경 범위에서는 이 오래된 테스트와 무관한 코드를 수정하지 않았다.

## 최종 검토

- Critical 또는 Important 문제는 발견되지 않았다.
- 기존 사용자 프리셋을 삭제하는 코드가 제거됐고 필수 3개 프리셋 추가 동작은 유지된다.
- 일반 구형 route만 `FloorHuntRunner`로 연결되며 빨코2·빨코3 분기 순서는 바뀌지 않았다.
- 기존 미커밋 변경이 있는 파일은 별도 인덱스로 이번 변경 줄만 커밋한다.
- EXE 빌드와 배포는 수행하지 않았다.
