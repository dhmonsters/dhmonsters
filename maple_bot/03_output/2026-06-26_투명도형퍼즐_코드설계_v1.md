# Transparent Puzzle Console Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `puzzle.py`를 진입점으로 하는 투명도형 퍼즐 분석 콘솔을 만들고, 탐지 ROI, 퍼즐 ROI, 녹화, trace, 정체성 상태머신을 먼저 안정화한다.

**Architecture:** `puzzle.py`는 앱 실행만 담당하고, 실제 책임은 `core/puzzle`와 `ui/puzzle_console.py`로 나눈다. 기존 투명도형 고도화 작업은 후보 소스와 참고 자료로만 쓰고, 새 구조의 중심은 세션, ROI, trace, 보류와 재획득 상태 전이다.

**Tech Stack:** Python 3.14, PyQt6, OpenCV, NumPy, mss, 기존 `core_ui` 테마, 기존 `core.vision.transparent_*` 모듈.

## Global Constraints

- 한국어 응답과 문서명을 유지한다.
- 산출물은 `03_output`에 저장한다.
- 새 소스 파일 첫 줄에는 파일 역할을 설명하는 한국어 주석을 넣는다.
- 삭제 작업은 하지 않는다.
- 기존 투명도형 고도화 실험을 반복하지 않는다.
- 실제 서비스 보호 장치 우회용 자동 입력 구현은 범위에 넣지 않는다.
- 먼저 재현 가능한 녹화와 trace를 만든 뒤 추적 점수 함수를 붙인다.

## 기존 작업에서 고정할 결론

### 반복 금지 항목

| 항목 | 이유 | 새 설계에서의 처리 |
|---|---|---|
| `phase_catalog` 단독 강화 | 단독 source가 2/16 수준이었다. | 보조 증거로만 둔다. |
| `TransparentPuzzleEngine` 단독 신뢰 | white anchor replay 버그 제거 후 0/16이었다. | 직접 source로 쓰지 않는다. |
| raw 후보 greedy continuity | raw center oracle은 높지만 greedy family는 충분히 못 살렸다. | raw 후보는 MHT 또는 path evidence에 넣는다. |
| family를 더 많이 뿌리기 | 후보 증가가 selector 혼란을 키웠다. | 후보보다 path 설명력과 상태 전이를 먼저 만든다. |
| local-box 전체 기본 실행 | 후보 family 폭발로 느려졌다. | opt-in 분석 모드로만 둔다. |
| prep_end를 period로 고정 | 실제 lag와 차이가 있었다. | period는 측정값으로만 사용한다. |
| selector shadow만 믿기 | 오래된 로그에는 shadow 필드가 없고 source rescue가 불명확했다. | replay 분석과 비교 자료로만 둔다. |

## 핵심 인터페이스

### `RoiSpec`

```python
@dataclass(frozen=True)
class RoiSpec:
    name: str
    basis: Literal["monitor", "window_client", "board_frame"]
    x: int
    y: int
    w: int
    h: int
    x_ratio: float | None = None
    y_ratio: float | None = None
    w_ratio: float | None = None
    h_ratio: float | None = None
    dpi_scale: float = 1.0
    window_title: str = ""
```

### `PuzzleSession`

```python
@dataclass(frozen=True)
class PuzzleSession:
    session_id: str
    started_at: str
    source_kind: str
    detect_roi: RoiSpec
    board_roi: RoiSpec
    output_dir: Path
    trace_path: Path
    raw_video_path: Path
    board_video_path: Path
    overlay_video_path: Path
```

### `FramePacket`

```python
@dataclass(frozen=True)
class FramePacket:
    session_id: str
    frame_index: int
    timestamp_ms: int
    source_frame: np.ndarray
    board_frame: np.ndarray
    source_kind: str
    roi_snapshot: dict[str, object]
```

### `Candidate`

```python
@dataclass(frozen=True)
class Candidate:
    candidate_id: str
    frame_index: int
    bbox: tuple[float, float, float, float]
    center: tuple[float, float]
    score: float
    source: str
    class_name: str = ""
```

### `CandidateEvidence`

```python
@dataclass(frozen=True)
class CandidateEvidence:
    candidate_id: str
    bg_score: float = 0.0
    motion_divergence: float = 0.0
    rigid_violation: float = 0.0
    phase_similarity: float = 0.0
    texture_bg_score: float = 0.0
    color_residual: float = 0.0
    merge_likelihood: float = 0.0
    notes: tuple[str, ...] = ()
```

### `IdentityDecision`

```python
@dataclass(frozen=True)
class IdentityDecision:
    state: Literal[
        "INIT_VISIBLE",
        "TRACK_CONFIDENT",
        "OCCLUSION_SUSPECTED",
        "IDENTITY_HOLD",
        "REACQUIRE",
        "LOST",
    ]
    point: tuple[float, float] | None
    candidate_id: str | None
    confidence: float
    reason: str
    hold_frames: int
    debug: dict[str, object]
```

## 컨텍스트 노트

- 이번 구현은 추적 알고리즘 성능 개선보다 재현 가능한 실험 껍데기를 우선한다.
- 기존 16개 GT는 목표가 아니라 시험지다.
- raw box oracle 16/16은 검출 문제가 거의 해결됐다는 근거다.
- live source upper 9/16은 현재 live family pool만으로는 부족하다는 근거다.
- `TransparentPuzzleEngine` 단독은 신뢰 source가 아니다.
- `phase_catalog`와 raw family는 새 구조의 주인공이 아니라 evidence와 후보 source다.
- 겹침 구간은 예외가 아니라 `OCCLUSION_SUSPECTED`와 `IDENTITY_HOLD` 상태로 다룬다.
- UI의 가치는 “잘 맞힌다”보다 “왜 그렇게 판단했는지 녹화와 trace로 설명된다”에 있다.

## 완료 기준

첫 번째 구현 완료 기준은 정답률이 아니다.

완료 기준은 아래 네 가지다.

1. `puzzle.py --replay`가 세션 폴더를 만든다.
2. 원본, board crop, overlay 녹화와 `trace.jsonl`이 생성된다.
3. trace에 탐지, ROI, 후보, evidence, identity 상태가 남는다.
4. UI에서 같은 프레임의 CCTV, 후보, 상태, 로그가 함께 이동한다.

이 기준을 통과한 뒤에 후보 점수 함수와 정체성 path 비용을 고도화한다.
