# 기타템 템플릿 동적 목록 작업 기록

## 승인된 동작

- 항목이 없을 때는 `+` 버튼만 표시한다.
- `+` 버튼을 누를 때마다 기타템 1, 기타템 2 순서로 행을 추가한다.
- 각 행의 템플릿 설정은 전체 화면이 아닌 게임창 클라이언트 캡처만 사용한다.
- 같은 항목을 다시 설정하면 해당 `item_N.png`를 덮어쓴다.
- `−` 버튼은 해당 파일을 삭제하고 뒤 항목을 앞으로 당겨 연속 번호를 유지한다.
- 기존 템플릿 파일이 있으면 프로그램 시작 시 행으로 복원한다.

## 기존 코드 확인

- 구형 설정 화면에는 전체 화면 선택기를 사용하는 템플릿 추가 기능이 있다.
- 현재 자동화·운영 화면에는 기타템 판매 체크와 수동 판매 버튼만 있다.
- 현재 판매 로직은 시스템 파일 목록에 `item_1.png`를 포함해 첫 템플릿을 판매 대상에서 제외한다.

## 구현 결과

- 자동화·운영 화면의 기타템 판매 아래에 동적 세로 목록과 `+` 버튼을 추가했다.
- 행 수는 `settings2.junk_sell.item_template_count`에 저장해 빈 행도 재실행 후 유지한다.
- 기존 `item_N.png`가 있으면 가장 큰 번호까지 기존 행으로 복원한다.
- 각 행의 템플릿 설정은 `_capture_game_client`가 반환한 게임창 클라이언트 이미지만 사용한다.
- 같은 번호를 다시 설정하면 해당 파일을 덮어쓴다.
- `−` 삭제 확인 후 해당 파일을 삭제하고 뒤 파일을 앞으로 이동한다.
- 판매 대상은 숫자 순서의 모든 `item_N.png`이며 `item_1.png`도 포함한다.

## 검증 결과

- 신규 테스트는 구현 전 4건 모두 예상한 미구현 사유로 실패했다.
- 구현 후 기타템·자동판매·UI 관련 테스트 41개가 통과했다.
- 변경 파일 문법 검사와 공백 오류 검사가 통과했다.
- 기존 `mss.mss` 사용에 대한 폐기 예정 경고 9건은 이번 변경과 무관하다.
- 현재 `tests` 전체 실행은 제거된 `RiskProfile`을 가져오는 기존 테스트 2건 때문에 수집 단계에서 중단된다.
- `RiskProfile` 오류와 관련된 코드 및 테스트는 이번 요청 범위 밖이므로 수정하지 않았다.
