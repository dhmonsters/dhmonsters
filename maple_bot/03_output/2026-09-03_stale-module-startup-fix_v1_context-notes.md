# 구형 설치 모듈 잔존 시작 오류 수정 기록

## 확인된 원인

- `platform1415_attack_hold_sec`는 현재 `core/config_adapter.py`와 `core_ui/rednose2_coordinate_widget.py` 양쪽에 존재한다.
- 깨끗한 2.4.10 배포 묶음은 구버전 설정 파일로도 정상 시작했다.
- 2.4.7 설치 경로의 구형 `core_ui`를 2.4.8 경량 설치 경로에 남겨 실행하자 `Unhandled exception in script`가 재현됐다.
- 2.4.8 이후 설치파일은 루트의 `core`, `core_ui`, `ui`를 포함하지 않지만 기존 설치 폴더를 제거하지 않아 과거 파일이 남을 수 있다.
- 남은 구형 UI가 새 기본 설정 목록을 읽으면 존재하지 않는 입력칸을 딕셔너리 인덱스로 조회하여 `KeyError`가 발생한다.

## 결정

- 사용자 설정이나 템플릿은 건드리지 않는다.
- 설치 폴더 루트의 폐기된 코드 폴더만 새 설치 전에 제거한다.
- UI는 기본 설정 목록과 화면 목록이 일시적으로 달라도 종료되지 않도록 방어한다.

## 구현 확인

- 미래 시간 설정 키를 강제로 추가한 회귀 테스트는 수정 전 `KeyError`로 실패했다.
- UI가 실제 입력칸 존재 여부를 확인하도록 수정한 뒤 관련 테스트 13개가 통과했다.
- UI, 설정 변환, 배포 묶음, 설치 복구 계약 관련 테스트 49개가 통과했다.
- 수정 배포 버전은 2.4.11로 결정했다.
