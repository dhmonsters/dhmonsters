# 이동 블럭 무동작 진단 인수인계 기록

## 사용자 증상

- 빨코2와 빨코3 전용 동선은 제외한다.
- 나머지 맵은 프로그램의 이동 블럭 UI에서 동선을 구성한다.
- 해당 이동 블럭 동선이 실행되지 않는다.

## 조사 원칙

- UI 저장부터 입력 호출까지 데이터 흐름을 역추적한다.
- 최근 이동 실행권 변경과 일반 맵 분기를 우선 확인한다.
- 증거가 확보되기 전에는 수정하지 않는다.

## 확인된 데이터 흐름

1. 활성 `core_ui`의 블럭 편집기는 `floor_hunt.route_steps`에 저장한다.
2. F1 시작 시 `to_runtime_config`가 `route`와 `route_steps`를 각각 런타임 설정으로 변환한다.
3. 빨코2·빨코3은 전용 러너를 사용한다.
4. 일반 맵의 `route_steps`가 있으면 `RouteStateRunner`를 사용한다.
5. 일반 맵에 구형 `route`만 있으면 `LegacyRouteGuard`를 만들며 실제 이동은 실행하지 않는다.
6. `floor_hunt_runner`가 존재하면 `BotMovementLoop`는 만들지 않는다.

## 확정 원인 1

- `core/config_manager.py`의 `_ensure_required_presets`가 허용 이름을 `초급 수련장`, `빨코2`, `빨코3`으로 제한한다.
- 허용 목록 밖의 사용자 사냥터 프리셋은 설정 로드 때 `pop`으로 삭제된다.
- 활성 맵이 허용 목록 밖이면 강제로 `빨코2`로 바뀐다.
- 메모리 재현 결과 `사용자맵` 하나가 로드 후 필수 3개로 교체되고 활성 맵은 `빨코2`가 됐다.
- 과거 백업 `config.before_rednose2_only_20260722_145102.json`에는 14개 프리셋이 있었지만 현재 `config.json`에는 3개만 남아 있다.

## 확정 원인 2

- 구형 이동 블럭은 `floor_hunt.route`에 저장돼 있다.
- `route_mode=True`, `route_steps=[]`, `route` 존재 조건에서 런타임은 `LegacyRouteGuard`를 생성한다.
- 이 가드는 시작할 때 안내 로그만 남기며 이동 입력을 실행하지 않는다.
- 동시에 컨트롤러는 `floor_hunt_runner`가 존재한다고 판단해 일반 `BotMovementLoop`도 생성하지 않는다.
- 기존 런타임 테스트는 `LegacyRouteGuard`에 `run_once`가 없어 실패했다.

## 최소 수정 범위

- 필수 프리셋은 추가·보정하되 사용자 프리셋을 삭제하지 않도록 설정 로드 정책을 변경한다.
- 기존 사용자 `route`를 안전하게 `route_steps`로 마이그레이션하거나, 호환 실행기를 사용하도록 분기를 복원한다.
- 전용 빨코2·빨코3 러너의 실행권 정책은 유지한다.
- 사용자 프리셋 보존, 활성 맵 보존, 구형 route 실행 또는 마이그레이션, 전용 러너 중복 이동 방지를 회귀 테스트로 고정한다.
