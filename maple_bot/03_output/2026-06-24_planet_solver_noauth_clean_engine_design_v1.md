# 2026-06-24 planet_solver_noauth 정리 및 새 추적 엔진 설계 v1

## 목표.

`planet_solver_noauth.py`에서 오래된 추적 실험 흔적을 제거하고, 투명 도형 퍼즐 판단 로직을 새 엔진으로 분리한다.

목표는 단순한 코드 정리가 아니라 16/16 오프라인 GT 통과를 향해 실험과 라이브 적용을 분리하는 것이다.

## 현재 문제.

`planet_solver_noauth.py`는 UI, 캡처, YOLO 로딩, ByteTracker, 녹화, 알람, 마우스 보정, 예전 추적 실험 옵션을 한 파일에서 처리한다.

이 구조에서는 새 추적 가설을 넣을 때마다 라이브 코드가 더 복잡해지고, 실패 원인을 추적하기 어려워진다.

현재 확인된 핵심 병목은 후보 검출이 아니라 후보 박스 내부의 타겟 중심 복원이다.

## 남길 부분.

- UI 시작과 정지 흐름.
- 게임 창 탐색과 클라이언트 ROI 계산.
- 화면 캡처와 미리보기 표시.
- YOLO 모델 로딩과 후보 박스 생성.
- 핑크 커서 검출 기반 마우스 보정.
- 녹화와 JSONL 후보 저장.
- 소리 알람과 기본 상태 표시.

이 부분은 추적 엔진 밖의 입출력 계층으로 유지한다.

## 제거할 부분.

- 체크박스에서 이미 사용하지 않는 추적 실험 옵션.
- 라이브 코드 안에 직접 섞인 vortex, 주기차분, 턴재획득 실험 분기.
- ByteTracker를 최종 판단자로 삼는 구조.
- 추적 상태와 UI 상태가 한 루프 안에서 뒤섞인 임시 변수 묶음.
- 오프라인 검증 없이 라이브에 바로 붙은 임시 family 선택 로직.

삭제는 한 번에 크게 하지 않고, 새 엔진으로 대체 가능한 부분부터 제거한다.

## 새 엔진 경계.

새 파일은 `core/vision/transparent_puzzle_engine.py`로 둔다.

엔진은 프레임마다 다음 입력을 받는다.

- 현재 프레임 번호.
- YOLO 후보 박스 목록.
- 흰색 도형 anchor 또는 없음.
- 현재 프레임 이미지 또는 회색 이미지.
- 게임 ROI와 캡처 기준 좌표.

엔진은 다음 출력을 반환한다.

- 추적 위치.
- 추적 신뢰도.
- 선택한 후보 index 또는 없음.
- 현재 상태 이름.
- 디버그 정보.

`planet_solver_noauth.py`는 이 출력만 보고 마우스를 움직이고 미리보기를 그린다.

## 새 엔진 내부 상태.

새 엔진은 단일 트랙 ID에 의존하지 않는다.

다음 상태를 함께 관리한다.

- 흰색 단계 anchor 상태.
- 준비 구간에서 만든 배경 catalog.
- 측정된 period와 frame별 local lag.
- 후보별 배경 설명 가능성.
- 후보별 raw 이동 이상도와 강체 위반도.
- 합쳐진 후보 박스 내부의 가능한 타겟 중심점.
- 검출을 잠시 믿지 않는 coast 상태.
- 분리 순간 재획득 상태.

## 1차 구현 범위.

1차 구현은 라이브 적용보다 오프라인 replay를 우선한다.

먼저 `_record_debug`와 `_gt_frames`를 입력으로 새 엔진을 재생하는 스코어러를 만든다.

오프라인에서 기존 consensus 9/16보다 명확히 좋아지는지 확인한 뒤 라이브에 연결한다.

## 16/16을 위한 핵심 가설.

남은 실패판은 후보 박스 안에 정답이 없는 문제가 아니다.

box-grid oracle이 16/16이므로, 정답은 대부분 YOLO 박스 내부에 있다.

따라서 새 엔진의 중심은 다음이다.

- 배경으로 설명되는 후보를 무조건 제거하지 않는다.
- 배경 후보와 타겟이 합쳐진 merged blob을 별도 상태로 둔다.
- merged 상태에서는 박스 중심 대신 내부점 가설을 유지한다.
- 내부점은 프레임 단위 점수보다 시간적 일관성으로 고른다.
- 신뢰 낮은 구간에서는 검출 중심을 버리고 상태 예측을 우선한다.
- 분리 순간에는 넓은 gate로 재획득하되, 직전 merged 맥락이 있을 때만 허용한다.

## 라이브 연결 기준.

다음 조건을 만족하기 전에는 새 엔진을 기본 라이브 경로로 켜지 않는다.

- 오프라인 16개 GT에서 기존 9/16보다 높을 것.
- 124417, 111417, 062325 중 최소 2개 이상을 개선할 것.
- 기존 성공판을 크게 망가뜨리지 않을 것.
- 관련 단위 테스트와 replay 채점 스크립트가 통과할 것.

## 테스트 계획.

- `transparent_puzzle_engine` 단위 테스트를 만든다.
- 준비 구간 period와 local lag 추정 테스트를 만든다.
- merged blob 상태 전환 테스트를 만든다.
- coast 상태에서 검출 중심을 무시하는 테스트를 만든다.
- `_record_debug` 16개 GT replay 점수를 산출한다.

## 구현 순서.

1. 새 엔진 파일과 replay 스코어러를 만든다.
2. `planet_solver_noauth.py`의 추적 루프에서 엔진 입력에 필요한 데이터만 추출한다.
3. 기존 ByteTracker 판단 결과와 새 엔진 결과를 동시에 로깅하는 shadow mode를 만든다.
4. 오프라인 replay로 새 엔진을 반복 개선한다.
5. 기준을 넘으면 라이브 기본 추적 경로를 새 엔진으로 바꾼다.
6. 더 이상 참조하지 않는 실험 옵션과 분기를 제거한다.

## 위험과 대응.

가장 큰 위험은 새 엔진이 특정 GT 16개에 과적합되는 것이다.

대응은 오프라인 점수만 보지 않고, 사용자가 새로 녹화할 랜덤 타겟 자료를 shadow mode로 같이 비교하는 것이다.

두 번째 위험은 라이브 입력과 오프라인 JSONL 입력의 후보 형식 차이다.

대응은 엔진 입력 타입을 작게 고정하고, replay와 live가 같은 adapter를 쓰게 하는 것이다.

## 승인된 방향.

UI, 캡처, YOLO, 마우스, 녹화는 유지한다.

추적 판단부는 새 엔진으로 분리한다.

오프라인 검증 전에는 라이브 기본 경로로 켜지 않는다.
