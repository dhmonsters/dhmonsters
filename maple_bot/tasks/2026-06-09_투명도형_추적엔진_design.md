# 투명도형 추적 엔진 재설계 — 설계 문서 (1단계)

> 작성일 2026-06-09. 대상 파일 `maple_bot/planet_solver_noauth.py`.

## 배경 — 왜 다시 만드나

투명 도형 미니게임에서 현재 추적 파이프라인(M2 분류 → M1 specialist 검출)은 **투명 구간에서 0% 추적**(완전 고장)이다. 11가지 고전 CV 방식을 샘플 영상으로 실측한 결과 전부 실패했다.

| 방식 | median 오차 | 40px 이내 |
|------|-----------|----------|
| 다중후보+움직임분별 | 270px | 0% |
| 프로스트 검출기 | 228px | 28% |
| MOG2 배경차분 | 185px | 1% |
| 템플릿/MIL/물리융합 | 93~183px | 16~44% |
| **ViT + 움직임 게이트** | **45px** | **47%** |

### 근본 원인 (실측 확인)

- 완전 투명 시 도형이 배경의 동일 모양 덩어리들과 **거의 구분 불가** → 외형 전역 검색 불가
- 배경이 정지가 아님(f336 vs f900 평균 픽셀차 43.5) → 배경차분/광학흐름 무력
- 도형 움직임은 median 1.2px/frame로 느림. 벽 반사 확인(49프레임 중 17회 속도반전). 즉 타겟은 **바운싱 볼**
- **병목은 "선택"이 아니라 "검출"** — 움직임 분별 로직은 옳으나, 투명 타겟을 후보로 검출하지 못해 분별 대상에 정답이 없음

### 결론

- 고전 CV로 신뢰성 있는 투명 추적은 불가
- **off-the-shelf 최선 = ViT 딥러닝 추적기 + 움직임 게이트 (median 45px, 도형 크기 내 ~55%)**
- 신뢰성 확보는 2단계(직접 학습할 YOLO 프로스트 검출기)가 담당. 1단계는 즉시 개선 + 2단계가 꽂힐 seam 제공

## 목표 (1단계 범위)

`planet_solver_noauth.py`의 M2 분류 + M1 specialist 추적 경로를 제거하고, **밝기 락온 → ViT 추적 + 움직임 게이트**로 교체한다. 2단계 YOLO 검출기가 무수정으로 꽂힐 재획득 인터페이스(seam)를 만든다.

성공 기준.
- 투명 구간 추적이 현재 0% → 도형 크기(~60px) 내 유지율 약 50% 이상 (오프라인 샘플 기준 재현)
- 실시간 루프(~20fps)에서 ViT 추론이 프레임 예산 내 동작
- M2 오분류 이슈 소멸 (분류 자체를 제거)
- 2단계 검출기 연결 지점이 단일 인터페이스로 격리됨

## 아키텍처 — 4개 단위

### 1. 흰색 락온 `acquire_white(det_bgr) -> bbox|None`
- 밝기 임계값(>200) 이진화 → 최대 윤곽 bounding rect
- 면적 하한(200px) 미만이면 None
- 도형 크기 상한 60px로 박스 클램프(중심 유지)
- 팝업당 흰 도형은 1개이므로 모호함 없음. 모델 불필요

### 2. 커서 제거 `mask_cursor(bgr) -> bgr` (매 프레임)
- 실제 게임에서 우리 마우스가 도형 위에 있음 → ViT가 도형 대신 커서를 쫓는 것 방지
- `win32api.GetCursorPos()`로 커서의 DET 상대좌표 산출 → 원형 마스크 → `cv2.inpaint(TELEA)`
- 기존 코드의 커서 inpaint 로직 재사용. 단, **M2 init 1회가 아니라 매 추적 프레임 실행**으로 이동
- 좌표 산출 실패 시 HSV 핑크 마스킹으로 폴백

### 3. ViT 연속 추적 `VitShapeTracker` (`core/vision/vit_shape_tracker.py`)
- 모델 `vittrack.onnx`(700KB), `cv2.TrackerVit_create`
- `init(frame, bbox)` — 흰색 락온 bbox로 1회 초기화 + 상태 리셋
- `update(frame) -> (cx, cy, score, accepted)`:
  - `cv2.TrackerVit.update` → box, `getTrackingScore`
  - **움직임 게이트**: 직전 위치 대비 점프 > `VIT_MAX_JUMP`(30px)면 거부
  - 채택 시 위치 갱신 + **속도 EMA 갱신(실관측 프레임만)**
  - **거부 시 무동결 복구** — `recovery_mode`로 동작 결정

#### 복구 모드 실측 비교 (sample_transparent_shape.mp4, 941프레임)
| 모드 | median | <40px | <80px | 비고 |
|------|--------|-------|-------|------|
| freeze | 54px | 48% | 57% | 멈춤 → 게임상 실패 |
| **physics(기본)** | 124px | 42% | 44% | 벽 반사 + 실측속도, 계속 따라감 |
| inertia | 214px | 42% | 44% | 벽반사 없음 |
| frosted | 192px | 42% | 44% | ViT 재init 오염 |

- **결정: `physics` 기본.** 흰 도형은 재출현하지 않으므로 freeze의 "자연복귀"는 허상이고, 멈춘 마우스는 게임상 확정 실패. 무동결 4모드가 정상추적 구간(공통 ~42%)은 동일하고 차이는 이미 잃은 구간의 표류량뿐 → 진짜 천장은 2단계 검출기가 올림.
- `physics`: 거부 시 실측 속도(채택 프레임 EMA)로 전진 + 벽 반사. 절대 멈추지 않음.
- 상수: `VIT_MAX_JUMP=30`, `VIT_SCORE_MIN=0.0`. `update` 평균 6ms(20fps 여유).

### 4. 재획득 seam `find_frosted_blob` (2단계 YOLO 자리)
- 계약: `find_frosted_blob(det_bgr, pred_cx, pred_cy, ref_area) -> bbox|None` — 예측 위치 주변 ROI에서 도형 후보 반환
- **1단계: 프로스트 휴리스틱(밝기+텍스처 부드러움).** `frosted` 모드에서만 사용되며, 배경 가짜양성으로 역효과라 기본(physics)에선 미사용
- **2단계: 직접 학습할 YOLO**가 이 함수를 대체. 진짜 검출기가 후보를 주면 `frosted`/`inertia` 모드 + 움직임 분별로 정상추적 천장이 상승
- 연속 거부 `BLOB_MISS_LIMIT(5)` 도달 시 `needs_reacquire()=True` → 호출자가 `acquire_white` 재시도

## planet_solver_noauth.py 통합 지점

### 제거 (완료)
- M2 분류 호출 및 `_target_cls` 사용
- 매 프레임 M1 specialist/ensemble `detect()` + 박스 크기 필터 + MAX_JUMP 선택
- 속도 예측 외삽(`_vel_x/_vel_y`) 및 M2 디버그 이미지 저장
- 관련 상수(`MAX_JUMP`, `MAX_MISS_RESET`, `BOX_*_RATIO`, `CAPCHA_END_MISS_COUNT`)
- (M1/M2 모델은 현재 로드만 유지. 추적엔 미사용 — 후속 정리 가능)

### 유지
- 팝업 감지, 성공 카운트, 클릭(`_real_click`), 미리보기 emit, 텔레그램, 사운드

### 교체 흐름 (완료)
- 팝업 첫 감지 → 게임 창 포그라운드 1회
- 매 프레임: DET 캡처 → `GetCursorPos` 커서 inpaint → ViT
  - 미초기화: `acquire_white` → 발견 시 `VitShapeTracker.init`(프레임마다 재시도)
  - 초기화됨: `tracker.update` → 좌표에 `_real_click`
  - `tracker.needs_reacquire()` 시 `acquire_white` 재시도 후 재init
- 팝업 소멸 시 `_vit_active=False`로 추적기 비활성
- 팝업 소멸 → 성공 처리 + 추적기 해제

## 에러 처리
- `vittrack.onnx` 로드 실패 → 로그 + 추적 비활성(팝업 감지만), 크래시 금지
- `acquire_white`가 30프레임 내 실패 → 해당 팝업 스킵, 다음 팝업 대기
- `win32api` 미가용/좌표 실패 → HSV 핑크 마스킹 폴백
- ViT `update` 예외 → 해당 프레임 동결
