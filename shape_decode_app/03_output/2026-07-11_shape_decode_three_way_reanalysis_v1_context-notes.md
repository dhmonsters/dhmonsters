# Shape Decode 3자 재분석 판단 기록

## 2026-07-11

- 이번 작업에서는 코드를 수정하지 않고 요구사항과 차이의 원인을 먼저 확정한다.
- 원본 녹화 영상이 최상위 기준이다.
- 현재 Python 프로그램은 Tkinter와 CPU 픽셀 렌더링을 사용한다.
- Claude 프로그램은 단일 HTML과 WebGL 셰이더를 사용한다.
- Claude 프로그램은 배경을 제외한 도형 마스크, 미끼 배치, 타겟 상태 전환이 현재 Python 프로그램보다 원본에 가깝다는 사용자 평가를 비교 가설로 둔다.
- 영상에서 직접 확인한 사실과 사용자 요청으로 나중에 바뀐 동작을 최종 보고서에서 구분한다.
- 원본 영상은 640x280, 약 35.23초, 30fps이며 캔버스는 x=238, y=6, 394x264로 확인했다.
- 영상의 타겟은 Frame 0부터 중앙이 아닌 랜덤 위치에 나타나며 즉시 이동과 투명화가 시작된다.
- 별 타겟은 Frame 0에서 중심 약 (244, 106), Frame 34에서 약 (266, 123)으로 이동했고 Frame 72에는 흰 타겟이 검출되지 않았다.
- 원 타겟은 Frame 27에서 중심 약 (262, 116), Frame 65에서 약 (290, 145)로 이동했고 Frame 103에는 흰 타겟이 검출되지 않았다.
- OpenCV 특징점 추적 결과 배경은 자전 없이 시계방향 타원형 평행 공전을 한다. 별 구간은 약 1.39회, 원 구간은 약 1.37회로 측정됐다.
- 영상의 프레임별 전역 회전 중앙값은 0.006~0.008도 수준이고 스케일 중앙값은 약 1.00003이어서 자전이나 확대·축소가 아니라는 근거가 된다.
- 영상의 배경 명암 표준편차는 약 38~40, 현재 Python은 약 21~22다. 현재 배경은 영상보다 대비와 입체 경계가 크게 약하다.
- 영상의 평균 엣지 값은 약 13.7~14.3, 현재 Python은 약 8.8~9.2다. 현재 배경의 세부 질감 밀도가 부족하다.
- 현재 Python은 첫 360프레임 동안 타겟을 중앙에 고정하고 360~720프레임에 이동·투명화한다. 이는 영상 동작과 직접 충돌한다.
- Claude는 첫 150프레임 동안 중앙 고정과 제자리 회전을 적용한다. 이 역시 영상 원본보다는 이후 사용자 요청을 반영한 모델이다.
- 영상의 Sample은 화면 배치만 바꾸고 보이는 Level·Frame·Shape 값은 유지하는 것으로 관찰된다. 현재 Python처럼 세 값을 모두 무작위화하지 않는다.
- 영상에서 Shape를 Star에서 Circle로 바꿀 때 Frame 325는 유지되며 배경 도형 전체가 즉시 원으로 교체된다.
- 최종 자연어 명세는 영상 시간표를 우선하고 도형 종류만 별·원·네모·세모 네 개로 제한하는 방향으로 정리했다.
- 권장 구조는 현재 Python UI 배치를 유지하고 Claude의 단일 마스크·비겹침 배치·굴절 이중 림을 OpenCV·NumPy 배열 렌더러로 옮기는 방식이다.
