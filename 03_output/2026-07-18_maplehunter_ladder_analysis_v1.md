# MapleHunter v3.1.17 사다리 처리 정적 분석

분석일 2026-07-18
대상 `MapleHunter_v3.1.17.exe`
방식 실행하지 않은 PyInstaller 코드 객체·상수·문자열 분석

## 1. 결론

MapleHunter는 화면에서 사다리 자체를 찾아내지 않는다. 사용자가 좌표 HUD로 사다리의 X, 맨위 Y, 맨아래 Y를 미리 기록하고, 프로그램은 미니맵에서 노란 캐릭터 점을 찾아 현재 X·Y와 사다리 좌표를 비교한다.

성공률을 높이는 핵심은 확률 모델이 아니라 좌표 피드백이다. 사다리 X까지 먼저 정렬하고, 캐릭터가 아래층·위층·애매한 위치 중 어디에 있는지 나눈 뒤 서로 다른 입력 시퀀스를 사용한다. 등반 중에도 Y를 약 0.05초마다 다시 읽어 목표 높이에 도달할 때까지 위 키를 유지한다.

다만 사다리 붙잡기 성공을 별도 영상 상태로 확인하거나 같은 블록 안에서 여러 번 재시도하는 구조는 확인되지 않았다. 미니맵 좌표가 틀리거나 점프 한 번이 빗나가면 즉시 복구하는 능력은 제한적이다.

## 2. 좌표를 얻는 방식

`core.vision.CharacterDetector`는 MSS로 미니맵 영역을 캡처하고 BGR 이미지를 HSV로 변환한다. 노란색 범위를 마스크로 만든 뒤 면적 3~100픽셀인 윤곽선 중 가장 큰 윤곽선의 무게중심을 캐릭터 좌표로 사용한다.

동봉된 `config.json`에는 미니맵 영역 `(60,164)~(296,301)`과 HSV 하한 `[20,100,200]`, 상한 `[40,255,255]`가 저장되어 있다. 코드의 기본 범위는 `[20,100,100]~[40,255,255]`이며 동봉 설정은 밝기 하한을 200으로 높여 밝은 노란 캐릭터 점에 더 집중한다.

`gui.main_window.MainWindow._on_tracking_tick`은 50ms마다 좌표를 갱신해 `_last_known_coord`에 저장한다. 사다리 실행기는 `_get_current_coord`를 통해 이 값을 읽는다. 좌표는 전체 화면 좌표가 아니라 선택된 미니맵 영역 내부 좌표다.

## 3. 사용자가 사전에 입력하는 값

사다리 블록은 다음 값을 가진다.

| 값 | 의미 | 기본값 또는 사용법 |
|---|---|---|
| `x` | 사다리 중심 X | 좌표 HUD로 측정 |
| `y_top` | 사다리 맨위 Y | 맨위에 서서 측정 |
| `y_bot` | 사다리 맨아래 Y | 맨아래에 서서 측정 |
| `direction` | 붙잡은 뒤 이동 방향 | `up` 또는 `down`, 기본 `up` |
| `exit_side` | 위층에서 뛰어내릴 방향 | `left` 또는 `right`, 기본 `right` |
| `jump_key` | 점프 키 | 전역 설정, 기본 `alt` |

Y 좌표는 작을수록 위쪽이다. 프로그램이 사다리 형상을 자동 검출하지 않으므로 이 세 좌표의 정확도가 사다리 성공률에 직접 영향을 준다.

## 4. 전체 처리 흐름

| 단계 | 판단과 동작 | 확인된 보정값 |
|---|---|---|
| 1. X 정렬 | 일반 좌표 이동 함수로 사다리 X까지 접근 | 목표 오차 약 2픽셀, 전체 이동 제한 15초 |
| 2. 위치 분류 | 현재 Y를 `y_top`, `y_bot`과 비교 | 아래층·위층·애매한 위치의 3분기 |
| 3A. 아래층 | 위 키를 누른 채 Y를 계속 확인 | 0.05초 주기, 상단 허용 오차 2픽셀, 최대 30초 |
| 3B. 위층 | 아래 키 1초 후 이탈 방향과 점프 입력 | 방향 입력 간격 0.04초, 이탈 대기 0.4초 상수 존재 |
| 3C. 애매한 위치 | 사다리 쪽으로 이동하다 X 오차 ±4에서 점프와 위 키 입력 | 접근 제한 5초, X 확인 주기 0.03초 |
| 4. 붙잡은 뒤 | `direction`에 따라 상단 또는 하단 Y까지 이동 | Y 허용 오차 2픽셀, 최대 30초 |
| 5. 종료·중지 | 방향·점프·공격 키를 모두 해제 | 키 고착 방지 정리 함수 사용 |

### 4.1 아래층에서 위로 등반

`RoutineRunner._do_ladder`는 현재 Y가 `y_bot`과 거의 같으면 같은 층으로 판단한다. 코드 객체의 변수명 `diff_y_bot`, `same_level`과 상수 2를 함께 보면 허용 오차는 약 2픽셀이다.

`_climb_ladder_up_until`은 위 키를 계속 누르고 0.05초마다 현재 Y를 확인한다. Y가 `y_top`의 약 2픽셀 범위에 들어오면 위 키를 해제한다. 무한 고착을 막는 제한 시간은 30초다.

### 4.2 위층에서 빠르게 내려오기

현재 Y가 사다리 상단보다 위에 있으면 프로그램은 사다리를 타고 천천히 내려가기보다 `_descend_ladder_jump`를 사용한다. 아래 키를 1초간 누른 뒤 사용자가 지정한 좌·우 이탈 방향과 점프를 조합해 사다리에서 뛰어내린다.

이 함수에는 0.04초와 0.4초 타이밍 상수가 있다. 정적 코드 객체의 설명은 이를 “아래 1초 + 좌·우 + 점프” 방식의 빠른 하강으로 명시한다.

### 4.3 중간·애매한 위치에서 점프해 붙잡기

아래층 또는 위층으로 명확히 분류되지 않으면 `_jump_grab_ladder`가 실행된다. 현재 X가 사다리 왼쪽이면 오른쪽, 오른쪽이면 왼쪽 키를 누른다. 0.03초마다 X를 다시 읽다가 사다리 X의 ±4픽셀 범위에 들어오면 횡이동 키를 해제하고 점프와 위 키를 사용해 사다리를 붙잡는다.

접근 단계 제한 시간은 5초다. 붙잡은 뒤 `direction=up`이면 상단 Y까지, `direction=down`이면 하단 Y까지 좌표 피드백으로 이동한다. 관련 코드에는 0.05초 확인 간격, 0.5초 대기, 30초 제한과 2픽셀 허용 오차 상수가 들어 있다.

## 5. 성공 가능성을 높이는 요소

### 5.1 시간 고정 입력보다 좌표 피드백 사용

단순히 몇 초간 키를 누르는 방식이 아니라 이동 중 X·Y를 반복 측정한다. 캐릭터 이동 속도나 순간 지연이 조금 달라도 목표 좌표에 도달할 때까지 입력을 유지할 수 있다.

### 5.2 넓은 접근과 좁은 완료 허용 범위

사다리 붙잡기에는 ±4픽셀 창을 사용해 점프 시작 타이밍을 확보하고, 층 도착 판정에는 약 2픽셀을 사용해 비교적 정확하게 멈춘다. 접근과 완료 판정의 허용 범위를 다르게 둔 점이 핵심 보정이다.

### 5.3 현재 층에 따른 입력 분리

아래층에서는 바로 위로 등반하고, 위층에서는 아래 키와 측면 점프로 빠르게 이탈하며, 중간 위치에서는 횡이동 후 점프해 붙잡는다. 하나의 고정 입력을 모든 상황에 적용하지 않아 실패 가능성을 낮춘다.

### 5.4 높은 좌표 갱신 빈도

메인 추적은 50ms, 점프 접근은 30ms, 등반 높이 확인은 50ms 단위다. 사다리 X를 지나치거나 목표 Y를 과도하게 통과할 가능성을 줄이는 구성이다.

### 5.5 입력 전송 신뢰성 보완

시작 코드가 Interception 커널 입력 백엔드를 활성화할 수 있으면 `pyautogui` 키 함수를 Interception 방식으로 교체한다. 실패하면 일반 `pyautogui`로 폴백하되 방향키에 Windows 확장 키 스캔코드를 적용한다. 이는 사다리 판단 정확도가 아니라 위·아래·좌·우 키가 게임에 전달될 가능성을 높이는 보완이다.

### 5.6 중지 시 키 해제

정지 또는 오류 종료 시 좌·우·위·아래, 점프와 공격 관련 키를 일괄 해제한다. 이전 실패에서 눌린 키가 남아 다음 사다리 동작을 방해하는 문제를 줄인다.

## 6. 확인되지 않은 기능과 취약점

사다리 블록 내부에서 점프 붙잡기를 여러 번 반복하는 명시적 재시도 횟수는 확인되지 않았다. 루틴 전체는 무한 반복되므로 다음 순환에서 같은 사다리 블록을 다시 만날 수 있지만, 이는 즉시 재시도와 다르다.

사다리에 실제로 매달렸는지를 캐릭터 자세나 사다리 영상으로 판정하는 기능도 확인되지 않았다. 성공 여부는 이후 Y 좌표 변화에 간접적으로 의존한다.

노란색 윤곽선 중 가장 큰 하나를 캐릭터로 선택하므로 미니맵에 비슷한 노란 표시가 있으면 잘못된 좌표를 선택할 수 있다. 좌표가 잠시 사라졌을 때 `_last_known_coord`가 남아 있으면 오래된 좌표를 사용할 가능성도 있다.

±4와 2는 미니맵 픽셀 단위의 고정값이다. 미니맵 크기, 화면 배율, 영역 선택이나 맵별 표시 크기가 달라지면 같은 물리적 거리를 의미하지 않는다.

## 7. 개선 우선순위

| 우선순위 | 개선안 | 기대 효과 |
|---|---|---|
| 1 | 점프 후 Y가 연속 프레임에서 변하는지 확인하고 실패 시 2~3회 재시도 | 실제 붙잡기 실패의 즉시 복구 |
| 2 | 마지막 좌표의 시각을 저장하고 일정 시간 이상 오래되면 입력 중단 | 오래된 좌표에 따른 오동작 방지 |
| 3 | 사다리별 X 보정값과 점프 선행 거리를 저장 | 직업·이동속도·맵 차이 보정 |
| 4 | 고정 ±4 대신 최근 X 속도에 따른 동적 점프 창 사용 | 빠른 이동 중 사다리 통과 감소 |
| 5 | 노란 점 후보의 위치 연속성과 면적을 함께 평가 | 다른 노란 표시 오인 감소 |

## 8. 근거 위치

핵심 근거는 `core\routine_runner.py`의 `_do_ladder` 375행, `_climb_ladder_up_until` 417행, `_descend_ladder_jump` 434행, `_jump_grab_ladder` 456행에 해당하는 코드 객체다.

좌표 검출 근거는 `core\vision.py`의 `CharacterDetector._detect_in_region` 109행과 `gui\main_window.py`의 `_on_tracking_tick` 619행이다. 사다리 입력 항목과 사용자 안내는 `gui\block_editor.py`의 `open_block_editor` 66행에 해당한다.

Python 3.13 코드 객체를 Python 3.14에서 읽었기 때문에 일부 함수의 명령 단위 역어셈블은 불가능했다. 함수명, 변수명, 참조 이름, docstring과 상수는 직접 확인했지만 분기 연산자의 세부 표현은 해당 근거를 조합해 복원했다.
