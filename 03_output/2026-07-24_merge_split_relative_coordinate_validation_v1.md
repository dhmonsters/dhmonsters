# 병합-분리 배경 상대좌표 검증 결과

## 고정 목표

처음 흰색 타겟의 신분을 잃지 않고 끝까지 따라가는 시간축 판별기를 만든다.

GT는 실행 중 입력으로 사용하지 않고, 재생이 끝난 뒤 결과 채점과 실패 원인 분류에만 사용한다.

## 이번 구현

- 부분 겹침, 완전 병합, 분리, 재획득 상태를 구분하는 사건 상태기계를 유지했다.
- 타겟과 실제로 충돌한 가장 가까운 후보만 병합 상태 판정에 사용했다.
- 거의 같은 위치와 크기로 중복 검출된 박스는 별도 충돌 도형으로 세지 않았다.
- 병합 참여 도형이 주변 배경 기준점 트랙을 이어받지 못하게 했다.
- 두 박스가 따로 보이는 부분 겹침 동안 배경 상대좌표 지문을 최신 상태로 갱신했다.
- 부분 겹침 동안에도 보이는 타겟의 위치와 속도 이력을 계속 갱신했다.
- 충돌 배경 도형과 가까우며 화면에 잘리지 않은 안정 기준점 2~3개를 사용했다.
- 기존 신분 후보가 배경으로 판정되지 않으면 속도 예측보다 기존 신분을 우선했다.
- 병합 영역 밖의 먼 후보를 분리 자식 집합에서 제외했다.
- 최소 3회 관측과 서로 다른 심판 그룹 2개의 동의를 만족할 때만 shadow 선택을 허용했다.

## 대표 1판 결과

- 기준 replay는 101/150이었다.
- 병합-분리 상대좌표 shadow도 101/150이었다.
- 기준 replay 대비 순수 개선은 0프레임이었다.
- 기준 replay 대비 순수 손실은 0프레임이었다.
- 후보 중심 oracle 상한은 128/150이었다.
- 관련 회귀 테스트는 42개 모두 통과했다.

## 확인된 문제

상대좌표 지문 자체는 후반까지 생성되지만, 분리 자식 집합에 실제 두 자식 외의 주변 후보가 여러 개 섞인다. 배경 관계를 유지한 후보 하나를 제외한 뒤 남은 후보 중 하나를 고르는 현재 방식만으로는 타겟 계보를 확정할 수 없다.

또한 이미 신분이 불확실해진 후보를 기준으로 새 병합 사건을 반복해서 열면 실제 타겟이 배경 관계 후보로 오판될 수 있다. 가중치를 더 높이는 방식으로는 해결되지 않는다.

## 검증 판정

일반화 가능한 안전 장치는 확인됐지만 대표 1판의 통과 프레임이 늘지 않았다. 계획의 확대 조건을 충족하지 못했으므로 정식 Studio seed 10, 16GT 재검증, `puzzle.py` 라이브 연결은 진행하지 않는다. 기능은 opt-in shadow 상태로 유지한다.

다음 가설은 신분이 확실할 때 병합 사건을 열고, 같은 사건에서 나온 실제 두 자식만 계보로 연결하는 것이다. 대표 1판에서 개선이 1프레임 이상이고 기준 대비 손실이 0일 때만 검증 범위를 확대한다.
