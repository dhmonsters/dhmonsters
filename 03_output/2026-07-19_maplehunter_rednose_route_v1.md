# MapleHunter 빨코2 전 버전 동선 비교 분석

분석일은 2026-07-19이며 대상은 `MapleHunter_v3.1.17.exe`다. 원본 실행 파일과 입력 드라이버는 실행하지 않았다. PyInstaller 아카이브에 포함된 맵 소스와 Python 3.13 코드 객체를 정적으로 분석했다.

## 1. 핵심 결론

빨코2 계열은 세 세대로 나뉜다.

1. 일반 `빨코2`와 레거시 `빨코2(플래닛)`은 2층 우측 → 1층 하강 → 1층 좌측 → 계단 복귀의 짧은 4단계 루프다.
2. `빨코2_v2·v3·v4`는 메모리 좌표로 2층을 왕복하다가 일정 사이클마다 우측에서 1층으로 내려가 수거한 뒤 7번 계단으로 복귀한다. 세 버전의 동작 코드는 같고 수거 주기만 3·5·7사이클로 다르다.
3. `빨코2_v5`와 `빨코new`는 같은 동작을 이름만 바꿔 묶은 구현이다. 약 92.83~102.483초 동안 2층을 왕복한 뒤 24번 발판 → 1층 → 7번 계단 → 2층 → 14/15번 → 16번 → 27번 발판을 돌고 2층으로 복귀한다.

`config.json`에는 선택된 맵이나 루틴이 없다. 현재 파일에는 CCTV 미니맵 영역 `(69,153)~(236,255)`, 공격 시간·간격, 노란 점 검출 HSV 값만 있다. 실제 맵 동선은 `maps` 또는 `maps_planet` 폴더의 맵 모듈에서 로드된다.

## 4. 일반 빨코2 동선

고정 미니맵 영역은 `(43,159)~(276,297)`이다. 좌표는 미니맵 안에서 검출한 캐릭터 점의 픽셀 좌표다.

`2층 y=83 → 우측 텔포 공격 x≥173 → 아래 텔포 → 1층 y=100~102 → 좌측 텔포 공격 x≤54 → 계단 x=44~54 정렬 → 위 텔포 2회 → 2층`

### 4.1 이동 방식

- 오른쪽 또는 왼쪽 방향키를 계속 누른다.
- 공격키 `a`와 텔레포트키 `space`를 누르고 약 0.25초 대기한다.
- 우측 끝에서는 아래 방향과 `space`를 조합해 1층 도착까지 반복한다.
- 계단을 왼쪽으로 지나쳤으면 오른쪽으로 걸어 `x≥44`가 될 때 멈춘다.
- 위 텔레포트 두 번 후 `y=83±2`가 아니면 계단 범위로 다시 걸어가 위 텔레포트를 반복한다.

### 4.2 안정성 보정

- 같은 X·Y가 3초 유지되면 왼쪽 방향을 0.08초 누르고 점프한 뒤 0.3초 후 해제한다.
- 좌우 사냥 구간이 끝날 때 버프를 확인한다.
- 키 정리는 모든 방향키를 해제하는 방식이다.

근거는 `maps/빨코2.py` 12~26행, 49~72행, 74~130행, 134~233행이다.

## 5. 빨코2(플래닛) 레거시 동선

소스는 없고 Python 3.13 `.pyc`만 포함되어 있다. 코드 객체에서 확인된 좌표는 미니맵 `(60,164)~(296,301)`, 2층 `y=82±2`, 1층 `y=99~101`, 우측 끝 `x=175`, 계단 `x=48~55`다.

동선은 일반 빨코2와 동일한 4단계다.

`2층 우측 사냥 → 아래 텔포 → 1층 좌측 사냥 → 계단 정렬·위 텔포 → 2층`

다른 점은 공격을 별도 백그라운드 스레드가 담당하고, 방향 입력을 약 1초마다 다시 잡아 입력 누락을 줄인다는 것이다. 텔레포트 간격은 GUI의 `tele_interval`을 매번 다시 읽는다. 좌표를 5초 동안 읽지 못하면 현재 sweep을 강제 종료하며, 2층 복귀 단계에는 25초 제한과 추락 판정이 있다. 3초 낑김 시 왼쪽 점프를 사용하는 것은 일반형과 같다.

이 버전의 모듈 문서에는 좌표가 placeholder라고 적혀 있으나, 실제 컴파일된 객체에는 위 수치가 들어 있다. 따라서 주석보다 컴파일된 상수를 우선 근거로 사용했다.

## 6. 빨코2_v2 동선

v2부터는 화면 미니맵 좌표가 아니라 외부 메모리 리더가 읽은 월드 좌표를 사용한다. 메모리 리더가 연결되지 않으면 루틴을 시작하지 않는다.

### 6.1 평상시 사냥 루프

`2층 x=-2.70 → 우측 텔포 공격 → x=5.72 → 좌측 텔포 공격 → x=-2.70 → 사이클 +1`

한 번의 텔레포트 공격은 다음 6단계로 입력된다.

1. 방향키 누름.
2. `space` 누름.
3. 공격키 누름.
4. `space` 해제.
5. 방향키 해제.
6. 공격키 해제.

각 sweep은 최대 60초이며, Y가 2층 범위를 벗어나면 즉시 실패로 반환해 복구로 넘긴다.

### 6.2 3사이클마다 수거

`2층 우측 x≥7.4 → 공격 해제 → 걸어서 ID39 끝 x≈8.4 → 우측 점프 낙하 → 1층 y≈-0.7 → 좌측 텔포로 7계단 접근 → x=-4.46~-4.25 걷기 정렬 → 위 텔포 → 계단 y=0.2~0.7 → 우측 텔포 → 2층`

- ID39 끝은 텔레포트로 넘기지 않고 걸어서 정밀하게 맞춘다.
- 낙하 중 40·41·42번 중간 발판 `-0.4≤y≤0.5`에 걸리면 우측 점프를 최대 5번 추가한다.
- 1층 수거 이동에서는 왼쪽 방향을 유지하고 2.5초마다 텔레포트한다.
- 7번 계단 진입 전에는 공격을 끄고 X를 걷기로 보정한다.
- 위 텔레포트 후 계단 Y를 확인하고 우측 텔레포트로 2층에 들어간다.
- 내부 복귀는 5회 시도한다. 모두 실패하면 3초 후 외부 루프가 다시 호출하므로 매크로 정지 전까지 반복된다.

근거는 `maps_planet/빨코2_v2.py` 1~16행, 30~47행, 131~210행, 214~292행, 296~489행, 497~617행이다.

## 7. 빨코2_v3과 v4

v3과 v4는 v2 클래스를 그대로 상속하고 새 이동 함수를 만들지 않는다.

- v3은 `CYCLES_PER_PICKUP=5`다.
- v4는 `CYCLES_PER_PICKUP=7`이다.

따라서 사냥 범위, 텔레포트 입력, ID39 낙하, 중간 발판 탈출, 7번 계단 복귀는 v2와 완전히 같다. 차이는 1층 수거를 얼마나 자주 하느냐뿐이다. v2가 수거 안전성을 우선하고, v4가 2층 체류 시간을 가장 길게 가져가며, v3은 그 중간이다.

근거는 `maps_planet/빨코2_v3.py` 1~15행과 `빨코2_v4.py` 1~14행이다.

## 8. 빨코2_v5와 빨코new 동선

두 `.pyc`의 SHA-256은 파일명과 헤더 차이 때문에 다르지만, 클래스명·소스 경로·공격 스레드 이름을 같은 값으로 정규화하면 함수 목록, 중첩 코드, 상수와 문자열 메타데이터가 일치한다. 동작 차이는 확인되지 않았다.

소스 `빨코new.py`의 로그는 내부적으로 `[빨코2v5]`를 계속 사용한다. 즉 `빨코new`는 v5 동선을 사용자에게 새 이름으로 제공한 것으로 판단된다.

### 8.1 9단계 동선

1. 2층 `-2.9≤x≤6.0`을 약 92.83~102.483초 동안 좌우 텔레포트 공격으로 왕복한다.
2. 좌측 끝에서 `x=-4.25`로 접근하고 좌측 텔레포트로 24번 발판 `y≥1.05`에 진입한다.
3. 공격을 끄고 아래 텔레포트로 1층 `y≤-0.5`에 내려간다.
4. 7번 계단 중심 `x=-4.4`로 접근해 위 텔레포트하고 `0.26≤y≤0.50` 안착을 확인한다.
5. 계단에서 우측 텔레포트해 2층 `0.8≤y≤1.4`로 복귀한다.
6. 공격하며 우측 `x≥6.0`까지 1.3초 간격으로 천천히 텔레포트한다.
7. `x=2.345`로 접근해 위 텔레포트하고 14/15번 발판 `y≥1.7`을 확인한다.
8. 같은 X에서 위 텔레포트해 16번 발판 `y≥2.6`을 확인한다.
9. 좌측 텔레포트로 27번 발판 `2.2≤y≤2.55`에 안착하고 한 번 더 좌측 텔레포트한다. 2초간 공격한 뒤 아래 텔레포트를 최대 20회 시도해 2층으로 돌아간다.

이후 1단계 사냥 타이머를 새로 시작한다.

### 8.2 정밀 이동 방식

- 목표 X까지 거리가 텔레포트 한 칸인 1.5 이상이면 텔레포트로 접근한다.
- 남은 거리가 1.5 미만이면 공격을 끄고 걸어서 맞춰 발판을 지나치는 오버슈트를 줄인다.
- 기본 X 정렬 허용 오차는 0.15다.
- 발판 텔레포트 후에는 목표 Y가 확인될 때까지 다음 입력을 보내지 않는다.
- 14/15·16번 발판 진입은 기본 최대 6회, 7번 계단은 한 묶음당 최대 10회 시도한다.
- 1층에서 2층 복구는 몬스터 피격과 재낙하를 고려해 최대 60초 반복한다.

### 8.3 사람형 입력 변동

- 방향키와 공격키를 각각 1.135~3.12초의 독립 간격으로 잠깐 해제했다가 다시 누른다.
- 발판 끝이 아닌 구간에서 10% 확률로 텔레포트를 한 박자 쉬고 0.25~0.6초 제자리 공격한다.
- 발판 중앙 안전구간에서는 6% 확률로 텔레포트를 한 번 더 입력한다.
- 사냥 시간과 방향 전환 대기, 재그립 시간에 난수를 사용한다.
- 좌표를 20초 연속 읽지 못하면 메모리 리더 연결 문제로 보고 중단한다.

소스 상단 설명은 90초 또는 최대 104.948초라고 표현하지만, 실제 클래스 상수는 `92.83~102.483초`다. 실행에 사용되는 클래스 상수를 기준으로 비교했다.

근거는 `maps_planet/빨코new.py` 1~28행, 45~86행, 173~353행, 357~499행, 503~629행, 633~678행과 두 `.pyc` 메타데이터 비교 결과다.

## 9. 버전별 선택 관점

- 일반 빨코2는 구조가 가장 단순하지만 미니맵 픽셀과 색상 검출에 의존한다.
- 플래닛 레거시는 일반형에 입력 재그립과 시간 제한을 더했지만 좌표가 placeholder였던 흔적이 남아 있다.
- v2는 수거가 가장 잦아 아이템 회수에는 유리하지만 층간 이동 횟수가 많다.
- v3은 v2의 안정성을 유지하면서 수거 빈도를 중간 수준으로 줄인다.
- v4는 2층 사냥 체류가 가장 길지만 바닥 아이템 회수 간격도 가장 길다.
- v5·빨코new는 모든 상단 발판까지 수거하고 좌표 확인과 재시도가 가장 촘촘하다. 대신 루틴이 복잡하고 메모리 좌표 리더가 필수다.

## 10. 주요 실패 가능 지점

1. `config.json`의 CCTV 영역을 사냥 동선 좌표로 오해할 수 있다.
2. 일반형과 레거시는 미니맵 크기나 검출점이 달라지면 픽셀 임계값이 맞지 않을 수 있다.
3. v2~v5는 메모리 리더가 끊기거나 잘못된 좌표를 반환하면 이동 판단이 실패한다.
4. v2의 ID39 점프는 중간 발판 걸림을 최대 5회만 처리한다.
5. v5·빨코new의 24번 발판 실패 후에도 현재 Y를 보고 복구를 시도하므로 예상 밖 위치에서는 복구 시간이 길어질 수 있다.
6. 사람형 랜덤 입력은 주기성을 줄이지만 동일한 경로 판단을 바꾸지는 않는다.

## 11. 최종 동선 요약

`일반·레거시`는 매번 `2층 우측 → 1층 우측 → 1층 좌측 → 계단 → 2층`을 반복한다.

`v2·v3·v4`는 `2층 좌우 왕복 N회 → ID39 우측 점프 → 1층 좌측 수거 → 7계단 → 2층`을 반복하며 N은 각각 3·5·7이다.

`v5·빨코new`는 `2층 시간제 왕복 → 24번 → 1층 → 7계단 → 2층 → 14/15번 → 16번 → 27번 → 2층`의 전 발판 수거 투어를 반복한다.
