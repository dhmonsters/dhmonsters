# 병합-분리 사건 계보 구현 계획

## 목표

신분이 확실한 타겟과 배경 도형이 겹치기 시작한 순간부터 분리될 때까지 하나의 사건으로 묶고, 그 사건에서 나온 실제 두 자식만 비교해 타겟 신분을 복원한다.

## 전역 제약

- 실행 중 GT 좌표를 입력으로 사용하지 않는다.
- 프레임 번호, 화면 좌표, 고정 이동 방향을 규칙에 넣지 않는다.
- 거리와 이동량은 타겟 크기와 현재 판의 배경 흔들림으로 정규화한다.
- 관측이 부족하거나 두 자식 계보가 불명확하면 갈아타지 않고 보류한다.
- 대표 1판에서 기준 대비 개선이 1프레임 이상이고 손실이 0일 때만 검증 범위를 확대한다.
- 최종 관문을 통과하기 전까지 opt-in shadow와 마우스 OFF 검증 모드로 제한한다.

## 수정 파일

- `maple_bot/core/puzzle/merge_split_relative.py`
  병합 사건 문맥, 참여 도형 계보, 분리 자식 쌍 판별을 담당한다.
- `maple_bot/core/puzzle/studio_hypothesis_shadow.py`
  기존 selector를 기준으로 새 사건 계보 판별을 opt-in shadow로 실행하고 근거를 기록한다.
- `maple_bot/tests/test_merge_split_relative.py`
  상태 전환, 계보 유지, 두 자식 판별, 보류 조건을 검증한다.
- `maple_bot/tests/test_studio_hypothesis_shadow.py`
  기본 모드 불변과 shadow 선택·보류 trace를 검증한다.

## Task 1. 병합 사건 문맥 고정

다음 상태를 가지는 `MergeEventContext`를 추가한다.

```python
@dataclass
class MergeEventContext:
    event_id: int
    armed: bool
    target_track_id: str | None
    background_track_id: str | None
    anchor_track_ids: tuple[str, ...]
    premerge_target_point: Point | None
    premerge_background_point: Point | None
    merged_bbox: BBox | None
    observations: int
```

사건은 현재 타겟 후보가 최근 경로와 연결되고, 충돌 배경 후보가 최소 2회 연속 같은 공간 트랙으로 확인될 때만 연다. 사건이 열린 뒤에는 분리 또는 만료 전까지 새 사건으로 갈아타지 않는다.

TDD 순서는 신뢰 가능한 충돌에서 사건이 열리는 테스트, 불확실한 후보에서 사건이 열리지 않는 테스트, 사건 도중 다른 겹침 후보가 나타나도 event ID가 유지되는 테스트 순서로 진행한다.

## Task 2. 병합 전 두 참여 도형의 계보 유지

타겟과 충돌 배경의 후보 ID가 프레임마다 바뀌어도 다음 정보를 사용해 같은 트랙으로 연결한다.

- 최근 위치와 속도로 예측한 정규화 거리.
- 이전 박스와 현재 박스의 겹침 정도.
- 초기 타겟 대비 면적과 종횡비 차이.
- 주변 배경 기준점과의 상대좌표 잔차.

부분 겹침에서는 두 트랙을 모두 갱신한다. 하나의 큰 박스만 남는 완전 병합에서는 타겟 중심을 새 박스 중심으로 덮어쓰지 않고 잠재 경로만 유지한다.

TDD에는 부분 겹침, 하나의 큰 병합 박스, 후보 ID 변경, 화면 경계 잘림을 각각 독립 사례로 둔다.

## Task 3. 실제 두 분리 자식만 남기기

`select_split_child_pair()`를 추가한다.

```python
def select_split_child_pair(
    *,
    context: MergeEventContext,
    candidates: Sequence[Candidate],
    predicted_target_point: Point,
    stable_scale_px: float,
) -> SplitChildPair | None:
    ...
```

후보 쌍은 다음 조건을 모두 만족해야 한다.

- 두 후보가 직전 병합 영역 또는 그 이동 예측 영역에서 나온다.
- 두 후보의 합친 영역이 직전 병합 박스를 자연스럽게 설명한다.
- 한 후보는 병합 전 배경 트랙과 이어지고 다른 후보는 병합 전 타겟 트랙과 이어진다.
- 주변의 무관한 세 번째 후보를 추가해도 선택된 쌍이 바뀌지 않는다.

유효한 쌍이 하나로 좁혀지지 않으면 `None`을 반환하고 기존 신분을 유지한다.

## Task 4. 배경 자식 판별과 타겟 복원

선택된 두 자식에만 배경 상대좌표 심판을 적용한다. 병합 전 배경 관계를 유지한 자식은 배경이고, 관계가 깨진 다른 자식은 타겟이다.

- 기존 신분 후보가 타겟 자식이면 그대로 유지한다.
- 기존 신분 후보가 배경 자식이면 타겟 자식으로 전환을 제안한다.
- 두 자식의 관계 잔차 차이가 현재 판의 배경 흔들림보다 작으면 보류한다.
- 제안은 2개 이상의 독립 심판 그룹과 최소 3회 지속 관측을 통과해야 확정한다.

YOLO 점수는 현재 판 후보 분포보다 지나치게 낮을 때만 감점하며, 높은 점수만으로 신분을 교체하지 않는다.

## Task 5. 사건 단위 진단 trace

각 프레임에 다음 정보를 기록한다.

- `event_id`, 사건 개방·유지·종료 이유.
- 병합 전 타겟과 배경 트랙.
- 선택된 기준점 ID와 상대좌표 잔차.
- 분리 자식 후보 전체와 최종 두 자식 쌍.
- 기존 신분 유지 또는 교체 이유.
- 보류 시 부족한 관측과 심판 그룹.

이 trace로 실패를 사건 미감지, 계보 단절, 두 자식 선택 실패, 배경 판별 실패, quorum 차단의 다섯 종류로 자동 분류한다.

## Task 6. 단계식 검증

1. 단위 테스트를 먼저 실패시키고 최소 구현으로 통과시킨다.
2. 대표 Studio 1판만 A/B 재생한다.
3. 순수 개선 1프레임 이상, 순수 손실 0이면 성공으로 본다.
4. 성공하면 성공 보존판 1개, 혼합 3판, 정식 seed 10 순서로 확대한다.
5. 정식 seed 10에서 손실 0이면 GT 비참조 selector와 런타임 selector의 16GT 16/16을 확인한다.
6. 그 뒤 새 랜덤 Studio 1판, 3판, 10판으로 확대한다.
7. 모든 관문을 통과한 뒤에만 `puzzle.py` 마우스 OFF 검증 모드 연결을 검토한다.

## 실패 분기

- 사건이 열리지 않으면 병합 감지와 충돌 트랙 연속성을 수정한다.
- 사건은 열리지만 두 자식 쌍이 없으면 병합 영역 예측과 계보 연결을 수정한다.
- 두 자식은 맞지만 배경·타겟이 뒤집히면 기준점 선택과 상대좌표 지문을 수정한다.
- 타겟 제안은 맞지만 선택되지 않으면 quorum 관측 누적을 수정한다.
- 대표 1판에서 손실이 하나라도 생기면 확대하지 않고 해당 사건을 재현하는 테스트를 먼저 추가한다.

각 실패에서는 한 원인만 수정하고 대표 1판을 한 번만 재검증한다. 좌표, 특정 프레임, 특정 이동 방향에 맞춘 예외는 추가하지 않는다.
