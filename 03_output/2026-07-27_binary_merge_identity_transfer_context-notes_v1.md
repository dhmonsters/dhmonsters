# 이진 병합 신분 전달 컨텍스트 노트

## 2026-07-27 결정

고정 목표는 처음 흰색 타겟의 신분을 잃지 않고 끝까지 따라가는 시간축 판별기를 만드는 것이다.

현재 최우선 문제는 평범한 추적 구간이 아니라 타겟과 배경이 겹쳤다가 다시 분리될 때 배경 후보로 갈아타는 실패다. 따라서 전체 프레임 점수보다 병합 사건 단위 신분 전달 정확도를 먼저 검증한다.

사용자가 확인한 물리 조건에 따르면 배경 도형끼리는 서로 겹치지 않는다. 한 사건에는 타겟 1개와 배경 1개만 참여하며 세 개 이상의 물리 분리 자식은 존재하지 않는다. 세 개 이상의 검출은 중복 박스 또는 오검출로 처리한다.

준비 구간에서는 배경 후보의 지역 이동 방향, 속도, 크기, 주변 관계와 불확실성을 숫자로 압축한다. 전체 주기 확정은 선택 필수 조건이 아니다. 확실한 전체 주기 정보가 있을 때만 배경 판정을 강화하는 보조 증거로 사용한다.

병합 중에는 합쳐진 박스 중심을 타겟 위치로 사용하지 않는다. 병합 직전 타겟과 충돌 배경 상태를 따로 동결하고 독립적으로 예측한다. 분리 후에는 H1과 H2 두 역할 가설만 비교한다.

배경 연속성 심판과 타겟 운동 연속성 심판이 같은 가설을 지지해야 신분을 전달한다. 모양과 YOLO는 보조 감점만 담당한다. 증거가 부족하거나 충돌하면 HOLD한다.

분리 첫 관측에서 즉시 결정하지 않는다. 첫 관측이 모호하면 같은 사건 ID와 H1/H2 역할 가설을 유지하고, 이후 분리 관측에서 두 심판이 합의할 때까지 HOLD한다. 재획득 지연은 절대 프레임 수가 아니라 사용한 분리 관측의 상대 순서로 채점한다.

주변 상대거리 심판은 기존의 일반적인 local rigid 숫자를 그대로 가져오는 것으로 끝내지 않는다. 병합 직전 충돌 배경과 가까운 배경 기준점의 상대벡터를 저장하고, 분리 뒤 현재 기준점과의 관계를 실제로 다시 계산한다.

역할 가설의 최소 차이는 기록된 특정 판에 맞춘 고정 픽셀값으로 정하지 않는다. 준비 구간 배경 흐름 분산, 부모-자식 계보 잔차와 현재 후보 쌍의 불확실성으로 정규화한다.

첫 구현은 기존 live 선택을 바꾸지 않는 opt-in 사건 shadow다. 대표 사건 1개에서 올바른 신분 전달 1회와 잘못된 갈아타기 0회를 확인하기 전에는 기존 Studio replay 또는 `puzzle.py`에 선택 권한을 연결하지 않는다.

검증 자료는 숫자 JSONL과 Markdown 보고서를 우선한다. 성공 사건 영상은 장기 보관하지 않고 실패 사건도 대표 이미지 두 장 이내로 제한한다.

설계 문서는 `03_output/2026-07-27_binary_merge_identity_transfer_design_v1.md`다. 구현 계획은 `03_output/2026-07-27_binary_merge_identity_transfer_implementation_plan_v1.md`다.

## 2026-07-27 Task 1 구현 결과

순수 이진 역할 판별기를 추가했다. 타겟 운동과 배경 운동 심판이 같은 가설을 지지할 때만 신분을 전달하며, 불확실하거나 심판이 충돌하면 HOLD한다.

모양과 YOLO는 선택적 비용 신호로만 사용한다. 값이 없거나 비정상이면 유리한 0점으로 바꾸지 않고 건너뛴다. 이 보조 신호는 필수 운동 심판의 합의를 뒤집거나 새로운 필수 지지를 만들 수 없다.

필수 입력의 누락과 비정상 값, 중복 후보 ID, 불확실성 경계, 입력 순서 대칭성을 포함한 70개 테스트가 통과했다. 커밋은 `e69b066`, `f95cc9c`이며 수정 후 독립 재검토 승인을 받았다.

## 2026-07-27 Task 2 구현 결과

준비 구간의 연속 배경 후보를 보드 크기로 정규화해 중앙 이동과 MAD 불확실성으로 압축하는 프로필을 추가했다. 누락 전이는 0 이동으로 만들지 않고 별도 누락으로 기록한다.

후보 1~2개만으로는 강건한 배경 합의를 만들 수 없으므로 흐름을 확정하지 않는다. MAD 필터 적용 뒤에도 정상 매칭이 최소 3개 남아야 유효한 전이로 인정한다. 중복 제거, 입력 순서 불변성, 전역 최적 매칭, 비주기 이동과 회전 접선 흐름을 직접 검증했다.

Task 1과 Task 2의 누적 83개 테스트가 통과했고, 두 차례 보완 뒤 독립 재검토 승인을 받았다. 커밋은 `2a6d3a2`, `f466492`, `cf50eb9`다.

## 2026-07-27 Task 3 구현 결과

runtime trace에서 신뢰 가능한 병합 직전 타겟과 충돌 배경을 동결하고, 이진 병합 사건과 분리 관측을 재구성하는 shadow 어댑터를 추가했다. 병합 부모 중심은 타겟 운동 계산에 사용하지 않는다.

첫 유효 자식 쌍에서 사건을 닫지 않고 같은 사건 ID의 후속 분리 관측을 보존한다. 새 사건이 시작되거나 trace가 끝날 때 사건을 확정하며, 새 사건의 premerge는 첫 병합 프레임이 아니라 그 직전 separate 상태다.

흰색 앵커와 선택 타겟의 일치, 전이적 중복 병합, one-to-one 주변 앵커 재매칭, 모호한 앵커의 unavailable 처리, 사건 추출 실패 diagnostics를 보강했다. 누적 99개 테스트가 통과했고 두 차례 보완 뒤 독립 재검토 승인을 받았다. 커밋은 `231817b`, `9442c3d`, `be01439`다.

## 2026-07-27 Task 4 구현 결과

runtime trace만 받는 사건 replay와 GT를 사후에만 받는 scoring API를 분리했다. 서로 다른 GT를 사용해도 runtime replay 결과가 동일하다는 테스트를 고정했다.

실제 trace의 `SESSION_START.payload.board_roi`에서 보드 크기를 읽는다. GT 연결은 전체 raw 후보가 아니라 runtime이 확정한 물리 split child 두 개로 제한해 중복·context 후보가 채점을 오염시키지 않게 했다.

추출 실패와 중복 미해결도 replay 및 outcome에 남기며, 회복 지연은 절대 FPS가 아니라 분리 관측 순서로 정규화한다. 누적 107개 테스트가 통과했고 보완 뒤 독립 재검토 승인을 받았다. 커밋은 `6d2f49d`, `2ba9eda`다.

## 2026-07-27 Task 5 대표 사건 Gate 결과

대표 기록에서 사건 결과 1개만 검증했다. 물리 사건은 0개였고 추출 진단 1개가 생성됐다. 30개 raw 후보를 정확한 물리 자식 2개로 접지 못해 `duplicate_detection_unresolved`가 발생했으며 실패 단계는 `candidate_normalization`이다.

wrong switch는 0개지만 올바른 자식 전달을 평가할 물리 사건이 없으므로 Gate 1은 실패다. 두 번째 사건, 임계값 조정, Task 6 Studio 연결은 수행하지 않았다.

CLI는 첫 사건 또는 진단이 확정되는 즉시 extraction과 resolver 계산 자체를 멈추며, 기계 판정 `gate_verdict`, `failure_stage`, `expand_allowed`를 출력하도록 보완했다. 대표 사건은 다시 실행하지 않고 합성 회귀 테스트로만 보완했다. 최종 관련 테스트는 273개와 subtest 37개가 통과했다.
