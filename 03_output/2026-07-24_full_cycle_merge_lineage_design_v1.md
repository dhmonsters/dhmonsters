# 전체 주기 기반 병합 사건 계보 판별기 설계

## 1. 고정 목표

처음 흰색 타겟의 신분을 잃지 않고 끝까지 따라가는 시간축 판별기를 만든다.

이번 설계의 목적은 프레임마다 가장 그럴듯한 후보를 새로 고르는 것이 아니다. 타겟과 배경 도형이 겹친 순간을 하나의 사건으로 묶고, 분리된 두 자식 중 어느 쪽이 원래 배경이고 어느 쪽이 원래 타겟인지 복원하는 것이다.

## 2. 이번 설계가 해결할 문제

준비 시간에는 타겟이 중앙에 머물고 배경 도형은 한 바퀴 이상 움직인다. 이 구간은 배경 도형의 신분과 주기를 학습할 수 있는 관찰 구간이다.

하지만 화면 경계를 나갔다가 다시 들어오는 도형은 같은 도형인지 확실하지 않다. 이런 도형을 기준점으로 쓰면 병합 후 분리 판정이 오히려 흔들린다. 따라서 한 주기 동안 화면 안에서 계속 관찰되고, 한 바퀴 뒤에도 같은 위상에서 같은 모습과 위치 관계를 보인 도형만 배경 기준점으로 인정한다.

## 3. 핵심 원칙

- 전체 주기 생존 조건은 점수가 아니라 자격 조건으로 사용한다.
- 주기는 준비 종료 프레임을 그대로 믿지 않고 기존 period estimator와 local lag 보정 결과를 재사용한다.
- 원시 거리가 아니라 현재 도형 크기와 배경 왜곡을 반영한 정규화 상대좌표를 사용한다.
- 한 바퀴 전의 아무 프레임과 비교하지 않고 같은 위상으로 보정된 프레임과 비교한다.
- 병합 전부터 확인된 타겟과 배경의 계보만 분리 판정에 사용한다.
- 관찰이 부족하거나 기준점들이 서로 다른 답을 내면 갈아타지 않고 HOLD한다.
- 실행 중 GT 좌표를 입력으로 사용하지 않는다. GT는 실행이 끝난 뒤 채점에만 사용한다.
- 특정 프레임 번호, 화면 좌표, 절대 거리, 고정 회전 방향을 규칙에 넣지 않는다.

## 4. 기존 기능과의 관계

새 모듈이 주기를 다시 추정하지 않는다.

기존 `BackgroundCatalog.estimate_period()`와 live family pool의 `_estimate_catalog_period()`, `_choose_catalog_lag()`가 화면 전체 후보 집합의 반복 주기와 현재 프레임에 맞는 local lag를 제공한다. 새 판별기는 이 결과를 받아 개별 배경 트랙이 실제로 한 주기 동안 생존했는지 검증한다.

역할을 나누면 다음과 같다.

- 기존 catalog는 화면 전체가 한 바퀴 전과 얼마나 비슷한지 판단한다.
- 새 cycle anchor 판별기는 특정 도형이 한 바퀴 전과 같은 도형인지 판단한다.
- 새 merge lineage 판별기는 그 도형과 타겟이 겹쳤다가 갈라질 때 두 신분을 복원한다.

## 5. 처리 흐름

### 5.1 준비 구간에서 주기와 배경 트랙 수집

매 프레임의 배경 후보를 짧은 시간축 트랙으로 연결한다. 연결 비용은 중심 이동, 박스 크기와 종횡비 변화, 외곽선 또는 texture 유사도, 현재 판에서 측정한 배경 흐름을 함께 사용한다.

준비 구간이 끝나면 기존 catalog가 주기 `T`를 추정한다. 각 현재 프레임은 `T` 주변에서 가장 잘 맞는 local lag를 선택해 같은 위상 프레임을 찾는다.

### 5.2 전체 주기 배경 기준점 자격 심사

각 배경 트랙은 다음 조건을 모두 만족해야 `QualifiedCycleAnchor`가 된다.

- 한 주기 길이의 관찰 구간을 채운다.
- 도형 박스가 전체 구간에서 안전 여백 안에 머문다.
- 중간 누락이 허용된 짧은 관찰 공백보다 길지 않다.
- 경계 잘림, 큰 병합 박스, 신분 교환 의심 구간이 없다.
- 같은 위상끼리 비교했을 때 중심 위치의 loop closure 오차가 작다.
- 같은 위상끼리 비교했을 때 면적과 종횡비 변화가 허용 범위 안이다.
- texture 신호를 사용할 수 있으면 한 바퀴 전 texture와도 일치한다.

안전 여백과 오차는 픽셀 상수가 아니라 현재 도형의 대표 크기로 나눈 값으로 판단한다. 큰 해상도와 작은 해상도에서 같은 의미를 유지하기 위함이다.

자격 판정 결과는 다음 정보를 가진다.

- 안정된 트랙 ID.
- 주기와 local lag.
- 전체 주기 생존율.
- 경계 안전도.
- 위치, 모양, texture의 loop closure 점수.
- 위상별 중심과 박스 기록.

### 5.3 병합 사건 열기

`MergeEventContext`는 타겟이 배경과 실제로 겹치기 시작한 순간 한 번만 열린다.

사건을 열기 위한 조건은 다음과 같다.

- 직전 타겟 신분이 신뢰 가능한 상태다.
- 충돌할 배경 참가자가 여러 프레임 동안 같은 계보로 관찰되었다.
- 두 박스가 부분 겹침으로 시작하거나 하나의 커진 박스로 합쳐지는 증거가 있다.
- 주변에 자격을 통과한 배경 기준점이 최소 하나 있고, 가능하면 서로 다른 방향의 기준점이 두 개 이상 있다.

사건이 열리면 다음 정보를 고정한다.

- 사건 ID.
- 병합 전 타겟 트랙 ID와 이동 상태.
- 병합 전 배경 참가자 트랙 ID.
- 주변 qualified anchor ID 목록.
- 병합 직전의 위상 보정 상대좌표 fingerprint.
- 병합 박스와 참가자들의 마지막 개별 박스.

사건이 닫히기 전에는 근처의 다른 후보 때문에 새 사건을 다시 열지 않는다.

### 5.4 병합 중 상태 유지

박스가 하나로 합쳐지면 박스 중심을 타겟 중심으로 확정하지 않는다. 병합 직전 타겟 속도, 박스 내부 위치, 배경 참가자와 주변 anchor의 위상별 관계를 이용해 타겟의 가능한 내부 위치 구간만 유지한다.

두 박스가 겹친 채 따로 검출되는 경우에도 두 후보를 독립 타겟으로 다시 평가하지 않는다. 같은 사건의 참가자 두 개로 묶어 신분 결정을 보류한다.

### 5.5 같은 사건의 분리 자식 두 개 찾기

분리 후보는 화면의 모든 후보에서 고르지 않는다. 다음 조건을 만족하는 후보 쌍만 같은 병합 사건의 자식으로 인정한다.

- 병합 박스 또는 그 이동 예측 영역에서 나온다.
- 두 자식 박스의 합친 영역이 직전 병합 박스를 자연스럽게 설명한다.
- 각 자식은 병합 전 타겟 또는 배경 참가자의 크기와 모양 계보 중 하나에 연결된다.
- 갑자기 생긴 unrelated 후보나 화면 경계에서 들어온 후보는 제외한다.

유효한 자식 쌍을 만들 수 없으면 즉시 재획득하지 않고 HOLD한다.

### 5.6 위상 보정 상대좌표로 신분 복원

주변 qualified anchor마다 병합 전 배경 참가자와의 상대좌표 fingerprint를 저장한다.

`relative = (candidate_center - anchor_center) / stable_shape_scale`

배경 왜곡 때문에 이 값이 시간 전체에서 완전히 일정하다고 가정하지 않는다. 현재 phase와 local lag에 해당하는 한 바퀴 전 관계를 기대값으로 사용한다.

분리된 두 자식 각각에 대해 다음을 계산한다.

- 자식과 각 anchor 사이의 현재 정규화 상대좌표.
- 같은 위상에서 예상되는 배경 참가자의 상대좌표.
- 여러 anchor가 내는 상대좌표 오차의 중앙값.
- anchor 간 판정이 같은 방향을 가리키는지 나타내는 quorum.

배경 관계를 가장 잘 보존한 자식은 배경으로 판정한다. 다른 자식은 병합 전 타겟 계보와 자연스럽게 이어질 때 타겟으로 복원한다.

### 5.7 심판 우선순위

병합 분리 구간의 우선순위는 다음과 같다.

1. 전체 주기 자격은 배경 anchor 사용 가능 여부를 결정하는 hard gate다.
2. 위상 보정 상대좌표 일치도가 배경 자식 판별의 주심이다.
3. 병합 사건 참가자 계보와 두 자식의 합성 박스 일치도가 보조 심판이다.
4. 타겟의 병합 전 속도와 분리 후 속도 연결성이 타겟 자식 확인을 돕는다.
5. YOLO 점수는 현재 판의 후보 점수 분포보다 지나치게 낮을 때만 감점한다. 높은 점수에 추가 보너스를 계속 주지 않는다.
6. 겹침, texture, 강체 위반 신호는 서로 독립된 근거가 있을 때 보조한다.

주심과 보조 심판이 충돌하거나 anchor quorum이 부족하면 HOLD한다. HOLD 중에는 마지막 확정 신분을 유지하고 같은 사건 영역 안에서만 재획득을 시도한다.

## 6. 상태 전이

`IDLE -> ARMED -> PARTIAL_OVERLAP -> MERGED -> SPLITTING -> REACQUIRED -> CLOSED`

- `IDLE`은 신뢰 가능한 타겟이 아직 없다.
- `ARMED`는 타겟과 충돌 배경 계보를 확보했다.
- `PARTIAL_OVERLAP`은 두 박스가 겹치지만 아직 따로 보인다.
- `MERGED`는 하나의 큰 박스 또는 하나의 관측으로 합쳐졌다.
- `SPLITTING`은 동일 사건의 두 자식이 다시 나타났다.
- `REACQUIRED`는 배경 자식과 타겟 자식의 신분을 복원했다.
- `CLOSED`는 충분한 프레임 동안 복원 결과가 유지되어 사건을 닫았다.

불확실하면 이전 상태로 되돌아가 새 후보를 고르지 않고, 현재 사건 안에서 HOLD한다.

## 7. 진단 로그

각 병합 사건은 사람이 실패 이유를 확인할 수 있도록 다음 값을 남긴다.

- 추정 주기와 선택된 local lag.
- anchor별 전체 주기 생존 여부와 탈락 이유.
- 사용한 anchor ID와 위상.
- 병합 참가자와 분리 자식 ID.
- 자식별 relative error, ancestry score, motion continuity, YOLO penalty.
- 최종 판정과 HOLD 이유.
- 사건 시작, 병합, 분리, 재획득, 종료 프레임.

대표 이미지는 병합 직전, 최대 병합, 최초 분리, 최종 재획득 네 장만 기본 보존한다. 실패한 실험만 상세 프레임을 남기고, 성공한 반복 실험의 대용량 영상은 요약 결과로 대체한다.

## 8. 테스트 설계

### 8.1 단위 테스트

- 한 주기 동안 화면 안에 남고 같은 위상으로 돌아온 도형은 anchor 자격을 얻는다.
- 화면 경계를 나갔다가 다시 들어온 도형은 모양이 같아도 탈락한다.
- 중간에 큰 병합 박스가 된 트랙은 anchor 자격을 잃는다.
- 한 바퀴 후 위치는 비슷하지만 면적 또는 texture가 다른 도형은 탈락한다.
- 부분 겹침과 완전 병합 모두 하나의 event ID를 유지한다.
- 분리 직후 다시 겹쳐도 새 사건을 열지 않는다.
- 두 자식 중 anchor 상대관계를 유지한 쪽을 배경으로 판정한다.
- 타겟은 배경 상대관계를 깨지만 병합 전 운동과 자연스럽게 이어진다.
- anchor가 하나뿐이거나 anchor 판단이 갈리면 HOLD한다.
- 왜곡 때문에 raw 거리는 달라도 같은 위상 기대 관계에 맞으면 배경으로 인정한다.

### 8.2 검증 관문

검증은 비용을 줄이기 위해 작은 관문부터 통과한다.

1. 합성 단위 테스트를 통과한다.
2. 대표 실패판 한 개를 전체 프레임 replay한다. 기존 정답을 한 프레임 이상 잃지 않으면서 병합 구간 순증가가 있어야 한다.
3. 보존판 한 개에서 손실이 0인지 확인한다.
4. 서로 다른 병합 유형 세 판을 확인한다.
5. Studio seed 10개에서 기존 대비 순개선과 새 손실을 비교한다.
6. 16GT를 runtime GT 없이 replay해 16/16을 유지한다.
7. 새 랜덤판 1개, 3개, 10개 순으로 확대한다.
8. 마지막으로 마우스 OFF와 표적 시각화 ON 상태의 라이브 검증으로 넘어간다.

대표 실패판에서 기대한 상대좌표 분리가 나오지 않으면 횟수를 늘리지 않는다. 먼저 anchor 자격, event genealogy, split pair 구성 중 어느 단계가 틀렸는지 로그로 분해한다.

## 9. 성공 기준

- 병합 전후에 같은 event ID가 유지된다.
- 경계를 나간 배경 도형이 anchor로 채택되지 않는다.
- 병합 분리 시 화면 전체 후보가 아니라 같은 사건의 두 자식만 비교한다.
- 배경 자식은 여러 qualified anchor와의 같은 위상 관계로 설명된다.
- 타겟 자식은 병합 전 타겟 계보로 복원된다.
- 불확실한 경우 잘못 갈아타는 대신 HOLD한다.
- 대표 실패판에서 순개선이 1프레임 이상이고 기존 정답 손실은 0이다.
- 16GT 16/16과 새 랜덤판 일반화 검증을 모두 통과해야 live 기본 경로 승격을 검토한다.

## 10. 구현 경계

첫 구현은 opt-in shadow 경로에만 추가한다. 기존 live 선택 결과는 바꾸지 않고 새 판별 결과와 근거를 나란히 기록한다.

shadow 검증 관문을 통과한 뒤에만 live selector의 HOLD와 재획득 판단에 연결한다. 마우스 제어는 계속 OFF로 유지하며, 표적 시각화와 로그로 먼저 검증한다.
