# Studio와 puzzle.py 자동 시각 검증 컨텍스트 노트

## 2026-07-17 결정

- 사용자는 Studio와 puzzle.py를 합쳐 자동으로 계속 검증하고 싶다고 했다.
- 합친다는 의미는 한 파일로 섞는 것이 아니라, Studio는 문제 출제기, puzzle.py는 마우스 OFF 판정기, 별도 하네스는 채점기로 나누는 구조가 적합하다고 판단했다.
- 메모리 읽기 방식은 사용하지 않는다.
- 실제 마우스 제어도 검증 모드에서는 사용하지 않는다.
- 검증의 목적은 자동 통과가 아니라, 표적 경로를 잘 따라가는지와 실패 이유를 빠르게 찾는 것이다.

## 기존 코드 확인

- `puzzle.py`에는 `--live-dry-run`과 `--target-visual-check` 옵션이 있다.
- `target_visual_check`가 켜지면 `live_dry_run`이 켜지는 구조가 이미 있다.
- `LiveRecordingRuntime`은 `visual_check_mode`일 때 `mouse_enabled`를 강제로 끈다.
- CCTV 미리보기에는 후보 박스, 선택 표적, 경로 히스토리를 그리는 구조가 있다.
- 현재 녹화는 OpenCV `VideoWriter`와 FFV1 코덱 기반이며, `ffmpeg` 직접 파이프라인은 아직 아니다.

## Studio 확인

- Studio는 단일 `index.html` 중심이다.
- 내부에 `targetPos(f)`가 있어 프레임별 정답 위치를 계산할 수 있다.
- 자동 채점을 하려면 이 값을 테스트 모드에서 외부 JSONL로 내보내는 통로가 필요하다.

## 설계 방향

- 1차는 `Studio GT JSONL`과 `puzzle 선택 JSONL`을 비교하는 방식으로 간다.
- 브라우저 창 캡처 흐름은 유지해 실제 관찰 조건과 가깝게 둔다.
- 채점은 frame_id 기준으로 하며, 좌표계 불일치가 생기지 않도록 `canvas_rect` 또는 보드 ROI를 함께 기록한다.
- 성공률만 보지 않고 실패 프레임, 점프, 후보 없음, 신분 상실, 후보 갈아탐을 함께 기록한다.

## 보안과 운영 기준

- 원격 코드 실행, DLL 주입, 드라이버, 메모리 읽기, 관리자 권한 요구는 사용하지 않는다.
- 텔레그램 알림이나 영상 저장은 사용자가 켠 경우에만 동작한다.
- 대용량 녹화는 보존 기간과 정리 정책이 필요하다.
