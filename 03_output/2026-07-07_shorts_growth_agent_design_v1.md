# 쇼츠 성장형 제작 에이전트 설계서

작성일: 2026-07-07.
형태: 로컬 웹앱 MVP, 이후 개인용 웹사이트와 팀 도구로 확장.
핵심 원칙: 시간별 성과 데이터가 1순위 분석 축이고, 제작 데이터는 원인 후보를 좁히는 2순위 설명 변수다.

## 1. 결정 요약

이 도구는 한국 유튜브 인기/급상승 흐름에서 소재를 찾고, 대본 생성, TTS, 자막 싱크, 이미지/밈/클립/모션 편집, MP4 렌더링까지 한 사이클로 완성하는 개인용 쇼츠 제작 도구다.

첫 버전은 내 PC에서 실행하는 로컬 웹앱으로 시작한다. 상단에 작은 단계 표시를 두고, 중앙은 쇼츠 전용 편집기처럼 넓게 쓰는 구조다.

장기적으로는 제작 결과와 시간별 성과를 축적해 왜 잘 됐는지 또는 왜 안 됐는지 분석하고, 다음 제작의 하네스와 스타일 개선안을 제안한다.

자기개선은 빠른 자동 튜닝이 아니다. 충분한 시간별 성과 데이터가 쌓였을 때만 원인 후보를 좁히고, 변경 제안은 사용자가 승인해야 적용된다.

## 2. 제품 흐름

| 단계 | 주요 작업 | 핵심 출력 |
|---|---|---|
| 1. 키워드 | 한국 인기 영상, 카테고리, 선택 키워드 기반 수집 | 추천 키워드, 근거 영상, 상승 점수 |
| 2. 대본 | 기본/고급 하네스로 대본 생성 | 장면, 자막, 음성 지시, 이미지 지시, 모션 지시 |
| 3. 음성/자막 | 무료/로컬 TTS와 자막 자동 싱크 | 음성 파일, 자막 타임코드 |
| 4. 편집 | AI 이미지, 밈, 클립, 캐릭터, 효과음, 모션 조정 | 편집 가능한 쇼츠 프로젝트 |
| 5. 출력 | MP4 렌더링과 업로드 패키지 생성 | MP4, 썸네일, 제목, 설명, 해시태그 |

## 3. 화면 구조

상단에는 키워드, 대본, 음성/자막, 편집, 출력 단계를 작게 고정한다. 사용자는 현재 위치를 잃지 않으면서도 중앙 작업 공간을 넓게 사용할 수 있다.

| 영역 | 역할 |
|---|---|
| 상단 단계 | 전체 제작 흐름을 작게 표시하고 현재 위치를 보여준다. |
| 좌측 도구 | 카테고리, 키워드, 하네스, 소스, 편집 도구처럼 현재 단계에 필요한 조작을 모은다. |
| 중앙 작업 | 대본, 9:16 미리보기, 장면 카드, 타임라인을 배치한다. |
| 하단 타임라인 | 장면, 음성, 자막, 효과음, 모션 레이어를 시간 기준으로 조정한다. |
| 우측 AI 보조 | 추천 이유, 성장 메모리, 이전 성공/실패 패턴, 다음 액션을 보여준다. |
| 성장 리포트 | 별도 버튼이나 탭에서 시간별 성과 분석과 개선 제안을 확인한다. |

## 4. 대본 하네스

대본은 정보 전달형과 이슈 후킹형을 기본으로 한다. 첫 3초는 궁금증을 만들고, 본문은 빠르고 명확하게 정보를 전달한다.

| 모드 | 수정 가능 항목 | 목적 |
|---|---|---|
| 기본 모드 | 말투, 길이, 후킹 강도, 금지어, 정보 밀도 | 빠른 반복 제작 |
| 고급 모드 | 시스템 프롬프트, 출력 구조, 장면 규칙, 자막 분리 | 원하는 방향으로 일정한 결과 생성 |
| 테스트 생성 | 같은 키워드로 샘플 대본 비교 | 하네스 변경 효과 확인 |
| 버전 저장 | 하네스 버전, 적용 영상, 결과 성과 | 장기 분석의 기준점 확보 |

대본 출력은 장면 번호, 자막 문장, 음성 강조점, 이미지 프롬프트, 소스 타입 추천, 모션 타입, 효과음 추천을 포함해야 한다.

## 5. 소스와 편집

기본 소스는 AI 이미지다. 밈/짤은 MCP 연결 가능한 소스가 있으면 가져와 로컬 밈 라이브러리로 관리한다.

급상승 영상은 항상 재료로 쓰지 않는다. 대본 장면상 실제 클립이 필요하다고 판단될 때만 후보로 제안한다.

유튜브 클립은 사용자가 구간, 크롭, 확대, 위치를 직접 지정하고 얼굴 없음, 문자 없음, 출처 확인, 사용 가능 판단을 체크한다. 시스템은 자동 판정자가 아니라 후보 제안과 편집 보조 역할을 한다.

| 카테고리 | 소스 우선순위 |
|---|---|
| 뉴스/이슈 | 실제 자료 이미지, 짧은 참고 클립 후보, 설명용 AI 이미지 |
| 게임 | 실제 게임 장면 후보, UI 없는 짧은 클립, 밈/반응 이미지 |
| 상품/생활정보 | 상품 이미지, 사용 장면 AI 이미지, 비교/강조 모션 |
| 정보형 | AI 이미지, 아이콘형 시각화, 밈 보조 |

편집기는 9:16 캔버스, 장면별 타임라인, 이미지/영상/밈/캐릭터/자막/효과음 레이어를 제공한다. TTS에 맞춰 자막을 자동 싱크하고, 자막 위치, 글꼴, 크기, 색상, 테두리, 그림자, 효과음에 맞춘 단어 강조를 수정할 수 있어야 한다.

## 6. 성장형 분석 루프

분석의 중심은 시간별 성과 데이터다. 제작 데이터도 분석에 포함하되, 성과 곡선의 원인을 좁히는 설명 변수로 사용한다.

| 데이터 | 저장 시점 또는 내용 | 분석 역할 |
|---|---|---|
| 시간별 성과 | 10분, 30분, 1시간, 3시간, 6시간, 24시간, 3일, 7일, 14일, 30일 | 1순위 분석 축 |
| 성과 지표 | 조회수, 노출, CTR, 평균 시청 지속 시간, 이탈 지점, 좋아요, 댓글, 구독 전환 | 성과 곡선 해석 |
| 제작 데이터 | 키워드, 하네스 버전, 후킹 문장, 장면 구조, TTS, 자막, 모션, 효과음, 소스 | 원인 후보 비교 |
| 해석 기록 | 문제 원인 후보, 가능성 점수, 다음 실험, 승인/기각 기록 | 장기 자기개선 |

| 성과 패턴 | 가능한 원인 후보 |
|---|---|
| 노출은 충분하지만 클릭률이 낮음 | 제목과 썸네일 문제 가능성이 높다. |
| 클릭률은 좋은데 3초 이탈이 높음 | 첫 화면과 첫 문장 문제 가능성이 높다. |
| 초반 유지율은 괜찮지만 중간 이탈이 높음 | 장면 전환, 정보 밀도, 자막 리듬 문제 가능성이 있다. |
| 24시간 이후 성장이 멈춤 | 키워드 생명주기나 추천 지속성 문제 가능성이 있다. |

AI는 문제를 단정하지 않고 원인 후보를 가능성 점수로 제시한다. 충분한 데이터가 쌓이기 전에는 하네스나 스타일을 자동 변경하지 않는다.

## 7. 기술 구성

첫 MVP는 로컬 웹앱, SQLite, 파일 저장소, FFmpeg 계열 렌더링으로 구성한다.

| 구성 요소 | 역할 | MVP 결정 |
|---|---|---|
| 로컬 웹앱 | 브라우저 기반 작업 화면 | 본인용 MVP, 이후 서버 배포 가능 구조 |
| SQLite | 제작 데이터와 성과 스냅샷 저장 | 로컬 우선, 이후 서버 DB로 교체 |
| 파일 저장소 | 이미지, 음성, 클립, MP4 저장 | 프로젝트별 폴더 구조 |
| FFmpeg 계열 | 9:16 MP4 렌더링 | 장면, 자막, 오디오, 효과음 합성 |
| 어댑터 | YouTube, TTS, 이미지, 밈, 업로드 교체 | 초기 구현 후 단계적 확장 |

YouTube API, TTS, 이미지 생성, 밈 MCP, 업로드 기능은 어댑터로 분리한다. 이렇게 해야 나중에 로컬 도구에서 개인용 웹사이트나 팀 도구로 확장할 때 저장소와 작업 큐만 교체할 수 있다.

YouTube 업로드 자동화는 공식 Data API의 `videos.insert`를 사용할 수 있지만 OAuth 권한과 프로젝트 검증 이슈가 있다. 첫 버전은 MP4와 업로드 패키지를 만들고, OAuth 연결이 가능하면 비공개 업로드까지 지원한다. 공개/예약 자동화는 후속 단계로 둔다.

참고 공식 문서: https://developers.google.com/youtube/v3/docs/videos/insert.

## 9. MVP 범위와 개발 순서

첫 MVP는 트렌드 키워드 수집부터 MP4 렌더링까지 한 사이클이 반드시 돌아야 한다. 밈 MCP, 클립 구간 선택, 비공개 업로드, YouTube Analytics API, 장기 자기개선은 MVP 이후 확장한다. 단, 저장 구조는 처음부터 확장 가능하게 만든다.

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 기본 로컬 웹앱과 상단 단계형 UI | 빈 프로젝트 생성과 단계 이동 가능 |
| 2 | YouTube API 설정 | 한국 카테고리/키워드 기반 인기 영상 수집 가능 |
| 3 | 키워드 점수화 | 조회수와 상승 속도 기반 추천 가능 |
| 4 | 대본 하네스 | 기본/고급 편집과 버전 저장 가능 |
| 5 | 장면 구조 생성 | 자막, 음성, 이미지, 모션 지시 포함 |
| 6 | TTS와 자막 싱크 | 음성 길이에 맞춘 자막 타임코드 생성 |
| 7 | 편집기 | 자막 위치, 글꼴, 모션, 효과음 수정 가능 |
| 8 | 렌더링 | 9:16 MP4 출력 가능 |
| 9 | 제작/성과 저장 | 제작 데이터와 수동 성과 입력 저장 가능 |
| 10 | 회고 리포트 | 시간별 성과와 제작 데이터를 바탕으로 원인 후보 제시 |

## 10. 리스크와 원칙

| 영역 | 원칙 |
|---|---|
| 외부 클립 | 자동으로 무단 삽입하지 않는다. 후보 제안 후 사용자가 구간, 크롭, 출처, 사용 가능 여부를 확인한다. |
| 저작권 | 얼굴이 보이지 않거나 3초 이하라도 리스크가 완전히 없다고 단정하지 않는다. |
| TTS와 밈 | 라이선스, 한국어 품질, 설치 난이도, 상업적 사용 가능성을 확인한 뒤 추가한다. |
| 유튜브 참고 | 특정 유튜버의 문장, 말투, 썸네일, 편집 구조를 복제하지 않고 이슈 키워드와 반응 흐름만 참고한다. |
| 업로드 | MVP는 수동 업로드 패키지와 비공개 업로드 보조 중심으로 둔다. |

## 11. 구현 전 확정 사항

| 항목 | 결정 |
|---|---|
| 첫 사용자 | 본인 1명. 로그인, 결제, 사용자 관리는 MVP 제외 |
| 국가 | 한국 유튜브 중심. 해외 인기 영상 재가공은 MVP 제외 |
| 접근 방식 | 작은 파이프라인을 먼저 깔고 바로 편집 화면으로 연결하는 하이브리드 |
| 화면 | 상단 작은 단계 표시형 UI |
| 쇼핑 연동 | 쿠팡 파트너스와 유튜브 쇼핑을 염두에 두되, MVP는 업로드 패키지와 메타데이터 생성까지 |
| 자기개선 | 시간별 성과 분석 중심. 제작 데이터는 원인 후보를 좁히는 2순위 데이터 |
