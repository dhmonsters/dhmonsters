# 이진 병합 신분 전달 구현 체크리스트

## 고정 목표

- [x] 타겟 1개와 배경 1개의 이진 병합 사건만 다룬다.
- [x] 준비 구간은 배경 흐름 압축 자료로만 사용한다.
- [x] 실행 중 GT를 사용하지 않는다.
- [x] 병합 부모 중심을 타겟 궤적에 사용하지 않는다.
- [x] 불확실하면 HOLD한다.

## 구현 준비

- [x] 설계 문서를 승인했다.
- [x] 기존 병합 감지기, 모델, Studio replay 경계를 확인했다.
- [x] 새 모듈의 책임과 공개 인터페이스를 계획에 고정했다.

## 구현

- [ ] Task 1. 순수 H1/H2 역할 가설 판별기를 TDD로 만든다.
- [ ] Task 2. 준비 구간 지역 배경 흐름을 숫자로 압축한다.
- [ ] Task 3. 이진 병합 사건과 분리 자식 증거를 trace에서 재구성한다.
- [ ] Task 4. 사건 전용 replay와 사후 GT 채점을 분리한다.
- [ ] Task 5. 대표 병합 사건 1개만 검증하고 확대 여부를 결정한다.
- [ ] Task 6. Gate 1 통과 시에만 Studio opt-in 진단에 연결한다.

## 검증

- [ ] 병합 중 타겟 확정이 0회인지 확인한다.
- [ ] 올바른 분리 자식으로 신분 전달하는지 확인한다.
- [ ] 배경 자식으로 잘못 갈아타는 사건이 0개인지 확인한다.
- [ ] 물리 후보가 두 개가 아니면 HOLD하는지 확인한다.
- [ ] 첫 분리 관측이 모호하면 같은 사건 ID로 다음 관측까지 HOLD하는지 확인한다.
- [ ] 병합 부모 중심을 바꿔도 타겟 운동 잔차가 변하지 않는지 확인한다.
- [ ] 주변 배경 상대거리 심판이 실제 현재 배경 후보를 사용해 계산되는지 확인한다.
- [ ] GT를 바꿔도 runtime 결정이 변하지 않는지 확인한다.
- [ ] opt-out 기존 replay 결과가 변하지 않는지 확인한다.
- [ ] 대표 사건 실패 시 확대 검증을 중단한다.

## 완료 조건

- [ ] 새 테스트와 관련 회귀 테스트가 모두 통과한다.
- [ ] 독립 코드 리뷰의 Critical과 Important가 0건이다.
- [ ] 대표 사건 결과가 간단한 검증 보고서에 기록된다.
- [ ] 코드와 검증 결과가 의미 단위별 커밋으로 남는다.
