# Studio 가설 생성 병목 개선 계획

## 고정 목표

처음 흰색 타겟의 신분을 잃지 않고 끝까지 따라가는 시간축 판별기를 만든다.

GT는 실행 중 입력으로 사용하지 않고, 재생이 끝난 뒤 후보 보관 결과를 채점하고 원인을 분류하는 데만 사용한다.

## 현재 기준

- 고정 seed 10개, 총 1,500프레임.
- 최종 통과 1,110프레임, 74.00%.
- 보관 가설 oracle 1,198프레임.
- 후보 중심 oracle 1,384프레임.
- 가설 생성 오류 147프레임.
- selector 오류 133프레임.

## 검증할 원인

1. 보관함 16칸이 같은 후보의 중복 상태로 채워져 서로 다른 후보를 충분히 보존하지 못하는지 확인한다.
2. 각 상태가 상위 5개 분기만 확장하여 정답 후보가 분기 단계에서 잘리는지 확인한다.
3. 비용순 전역 가지치기에서 정답 후보가 밀려나는지 확인한다.
4. 초기 흰색 anchor와 이후 속도 예측이 잘못된 방향으로 고착되는지 확인한다.

## 실험 순서

1. 실패 프레임마다 정답 근접 후보의 후보 순위, 보관 여부, 보관된 서로 다른 위치 수, 상태 수를 집계한다.
2. 기존 `width=16, branch=5, 후보당 최대 2상태`를 기준선으로 둔다.
3. `branch=8`, `width=24`, 후보 다양성 우선 가지치기를 각각 독립 비교한다.
4. 기존에 보관되던 정답 가설을 잃지 않으면서 보관 가설 oracle이 증가하는 대안만 선택한다.
5. 선택한 대안을 라이브 selector에 연결한 뒤 고정 seed 10개와 16GT를 다시 검증한다.

## 성공 기준

- 가설 생성 오류 147프레임이 감소한다.
- 기존 보관 성공 프레임의 회귀가 0이거나, 전체 최종 통과율이 명확히 상승하는 근거가 있어야 한다.
- GT 좌표나 정답 후보 ID를 실행 중 selector 입력에 사용하지 않는다.
- 마우스 OFF, 표적 시각화 ON 검증 원칙을 유지한다.
- 16GT 16/16을 유지한다.
