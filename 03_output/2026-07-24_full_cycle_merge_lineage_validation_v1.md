# 전체 주기 병합 계보 검증 보고서

## 고정 목표

처음 흰색 타겟의 신분을 잃지 않고 끝까지 따라가는 시간축 판별기를 만든다.

GT는 실행 후 채점에만 사용한다. 고정 좌표, 고정 방향, 절대 프레임, GT 정답은 실행 규칙에 넣지 않는다. 불확실하면 다른 후보로 갈아타지 않고 HOLD한다. 검증 중 마우스 출력은 끈다.

## 구현 범위

- 준비 구간에서 전체 주기를 생존한 안정 배경 트랙만 주기 증거로 사용한다.
- 현재 위치와 이전 주기 위치는 정확한 안정 트랙 ID를 이용해 연결한다.
- 병합 시작부터 분리까지 하나의 사건 ID와 참여 후보 계보를 유지한다.
- 분리 후보는 전체 주기 일치도, 겹침 주변 상대좌표, 사건 참여 이력을 함께 평가한다.
- 주기나 local lag가 불확실하면 병합 계보 심판은 fail-closed로 선택을 보류한다.
- 새 흰색 에피소드가 시작되면 이전 판의 추적 속도, 확인 대기, 병합 및 주기 상태를 모두 초기화한다.
- 기능은 `merge_split_relative=True`인 opt-in shadow에서만 켜진다.

## 판정

확장 게이트는 `improved_frames >= 1`과 `regressed_frames == 0`이다. 개선 70은 만족했지만 회귀 42가 남아 실패했다. 따라서 일괄 3판, seed 10개, 16GT 확장 검증은 실행하지 않았다.

`1,021 -> 1,049`는 전체 replay 선택기의 결과이며 전체 주기 병합 계보 심판 단독 성과가 아니다. 병합 계보 심판의 실제 선택 횟수는 0회다. 이는 불확실한 상태에서 잘못 개입하지 않는 fail-closed 계약은 지켰지만, 대표 판에서 주기 증거를 확정하지 못해 새 심판이 활성화되지 않았다는 뜻이다.

현재 병목은 후보 부족이나 가중치 부족이 아니다. 전체 주기를 생존한 안정 트랙은 만들어졌지만, 같은 ID들의 닫힌 주기 재발을 충분히 확정하지 못했다. 다음 실험은 가중치 조정이 아니라 준비 구간의 안정 트랙 재발 관측을 더 분명하게 만드는 일반화 신호 하나를 먼저 설계해야 한다. 그 신호가 대표 판 1개에서 period와 phase-qualified를 실제로 만들면서 회귀 0을 보일 때만 검증 범위를 넓힌다.
