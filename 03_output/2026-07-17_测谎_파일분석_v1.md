# 测谎 폴더 정적 분석 보고서

- 분석 대상. `C:\Users\PC\Downloads\Telegram Desktop\测谎`.
- 분석일. 2026-07-17.
- 분석 방식. 파일을 실행하지 않은 정적 분석.
- 대상 규모. 파일 20개, 총 234,788,386바이트.

## 1. 핵심 결론

이 폴더는 카메라·맥박·음성 등을 측정하는 일반적인 생체 신호 기반 거짓말 탐지 프로그램이 아니다. 실제 구성은 **Unreal Engine 게임의 강한 안티디버깅을 우회하기 위한 커널·가상화 기반 디버거와, 그 위에서 동작하는 `PolygraphBot` 자동화 프로그램의 묶음**에 가깝다.

핵심은 다음 세 계층이다.

1. `PolygraphBot_vmp.exe`가 최상위 자동화·제어 클라이언트로 보인다. VMProtect로 대부분의 로직이 숨겨져 있고, 원격 IP `23.140.4.181`과 WinHTTP 연결 기능을 포함한다.
2. `UnrealDbg.aes`, `UnrealDbgServer_vmp.exe`, `UnrealDbgDll.dll`이 사용자 인터페이스, 라이선스, 디버거 선택, 대상 프로세스 시작과 커널 구성요소 제어를 담당한다.
3. `VT_Driver.sys`, `DbgkSysWin10.sys`, `DbgkSysWin11.sys`, `Hook.dll`, `Hook64.dll`, `AIHelper.dll`이 실제 커널 디버깅, 메모리 접근, 중단점, DLL 주입, 안티디버깅 우회를 수행한다.

프로그램의 이름에 `AIHelper`가 있지만 이 DLL은 AI 추론 모듈이 아니다. 정적 분석상 드라이버 서비스 관리와 원격 DLL 주입을 수행하는 로더다. 폴더 안에는 별도의 AI 모델, 얼굴 분석 모델, 음성 분석 모델이 없다.

## 2. 판단의 확실성

### 확인된 사실

- `UnrealDbg.aes`는 암호화 파일이 아니라 이름만 `.aes`인 정상 PE 형식의 64비트 GUI 실행파일이다.
- `UnrealDbg.aes`는 관리자 권한을 요구하며 CD키 로그인·하트비트, 디버거 목록, VT 디버깅 모드, 네트워크 클라이언트·서버 기능을 포함한다.
- `AIHelper.dll`은 `InjectDll`, `InjectDllEx`, `LoadNT`, `UnloadNT`를 제공하며 서비스 생성, 디버그 권한 획득, 원격 메모리 할당·쓰기, 원격 스레드 생성을 사용한다.
- `Hook.dll`과 `Hook64.dll`은 Windows 디버그 API, 프로세스 메모리, 스레드 컨텍스트와 중단점을 가로채고 `\\.\UnrealDbg` 장치로 IOCTL을 보낸다.
- `DbgkSysWin10.sys`와 `DbgkSysWin11.sys`는 Windows 디버그 객체·이벤트·프로세스·스레드·메모리 기능을 커널에서 다룬다.
- `VT_Driver.sys`는 Intel VT와 물리·가상 메모리 주소 기능을 사용하는 하이퍼바이저 계열 드라이버다.
- `PolygraphBot_vmp.exe`는 VMProtect로 패킹됐고 WinHTTP, 외부 프로그램 실행, 하드코딩 IP `23.140.4.181`을 포함한다.
- `run_kr.py`는 관리자 권한을 얻어 현재 사용자 로캘을 중국어 간체로 임시 변경하고 `UnrealDbgServer_vmp.exe`를 실행한 뒤 종료 시 원래 값을 복원한다.
- 폴더의 두 로그 파일은 모두 0바이트다.

### 강한 추정

- `UnrealDbgServer_vmp.exe`가 보호된 로더 또는 로컬 중계 서버로 작동하고 `UnrealDbg.aes`와 `PolygraphBot_vmp.exe` 사이의 실행·통신을 조정할 가능성이 높다.
- `copyright.db`는 CD키·라이선스 또는 사용권 상태를 암호화해 저장하는 파일로 보인다.
- `ffmpeg.exe`는 `PolygraphBot_vmp.exe`가 화면 또는 게임 세션을 녹화·변환하는 데 사용될 가능성이 높다. 다만 VMProtect 때문에 실제 명령행은 확인되지 않았다.
- `PolygraphBot_vmp.exe`는 Unreal 게임 내부 상태를 디버거·Hook 계층으로 읽고 특정 “측谎/Polygraph” 게임 기능을 자동화하는 봇으로 보인다.

### 현재 확인할 수 없는 내용

- `PolygraphBot_vmp.exe`가 정확히 어느 게임을 대상으로 하는지.
- 원격 IP로 전송되는 데이터, 인증 방식, 명령 구조와 현재 서버의 운영 주체.
- FFmpeg의 실제 캡처 대상과 저장 경로.
- 봇의 구체적인 판단 알고리즘과 자동 입력 순서.
- 이 PC에서 실제로 실행됐는지 여부. 폴더 자체에는 실행을 입증하는 로그가 없다.

## 4. 전체 작동 방식

### 4.1 실행 준비

`run_kr.py`는 먼저 관리자 권한을 요청한다. 현재 사용자 레지스트리의 `Control Panel\International` 값을 백업하고 로캘을 `zh-CN`, ANSI 코드 페이지 936으로 바꾼다. 이후 같은 폴더의 `UnrealDbgServer_vmp.exe`를 시작하고 프로세스가 끝날 때까지 기다린 뒤 원래 로캘을 복원한다.

이 스크립트는 시스템 전체 설정이 아니라 HKCU의 현재 사용자 설정만 바꾸지만, 비정상 종료나 강제 종료 때 복원이 실패할 수 있다.

### 4.2 보호된 서버와 GUI

`UnrealDbgServer_vmp.exe`는 VMProtect로 패킹돼 정적 import가 거의 숨겨져 있다. 확인되는 `socket` import와 이름, 런처의 직접 호출 관계를 보면 로컬 서버 또는 보호 로더 역할이 강하다.

`UnrealDbg.aes`는 이름과 달리 실행 가능한 GUI 본체다. 제품 정보는 `UnrealDbg 1.0.0.0`이며 Delphi로 작성됐다. 매니페스트에서 `requireAdministrator`를 요구한다. 내부 문자열에는 다음 기능이 확인된다.

- CD키 로그인과 하트비트.
- 디버거 추가·삭제 메뉴와 `DebuggerList.ini`.
- `EnterVTDebuggingMode`와 `TL_BlockResumeThread`.
- 프로세스·모듈·드라이버 열거.
- TCP 클라이언트·서버와 HTTP 기능.
- `D-encryption.dll`, `UnrealDbgDll.dll`, `Config.ini` 호출.

### 4.3 드라이버 로드와 DLL 주입

`UnrealDbgDll.dll`은 Windows 버전에 따라 `DbgkSysWin10.sys` 또는 `DbgkSysWin11.sys`를 선택하고 `VT_Driver.sys`와 통신한다. `AIHelper.dll`을 통해 드라이버 서비스를 생성·시작하고 필요하면 제거한다.

`AIHelper.dll`은 대상 프로세스를 열어 DLL 경로를 원격 메모리에 쓰고 `CreateRemoteThread` 계열로 DLL을 주입한다. 32비트 대상에는 `Hook.dll`, 64비트 대상에는 `Hook64.dll`이 사용되는 구조다.

### 4.4 후킹과 커널 디버깅

Hook DLL은 일반 Windows 디버거가 사용하는 `WaitForDebugEvent`, `ContinueDebugEvent`, `NtDebugActiveProcess`, `GetThreadContext`, `SetThreadContext`, `ReadProcessMemory`, `WriteProcessMemory`, `VirtualProtectEx` 등을 가로챈다.

실제 작업은 `\\.\UnrealDbg` 장치에 IOCTL을 보내 커널 계층에 위임한다. 문자열로 확인되는 명령에는 하드웨어·소프트웨어 중단점 설정·해제·읽기가 포함된다.

`DbgkSysWin10.sys`와 `DbgkSysWin11.sys`는 Windows의 디버그 객체와 프로세스·스레드 이벤트를 재구성한다. 프로세스 메모리 보호·복사, 스레드 일시정지·재개, 컨텍스트, 모듈 로드 이벤트를 커널에서 처리한다. Microsoft 기호 서버 또는 중국 내 기호 미러에서 커널 PDB를 내려받는 PowerShell 명령 문자열도 포함한다.

`VT_Driver.sys`는 Intel VMX를 활성화하고 EPT 기반 후킹과 VM-exit 처리를 제공하는 하이퍼바이저 계층이다. 이 계층의 목적은 일반 디버거를 탐지·차단하는 게임 드라이버 아래에서 디버깅 이벤트와 메모리 접근을 유지하는 것이다.

### 4.5 PolygraphBot 계층

`PolygraphBot_vmp.exe`는 2026-06-05 빌드 시각을 가진 최신 구성요소이며 파일 전체 엔트로피가 7.78로 높다. 대부분의 원래 섹션은 raw 데이터가 0이고 고엔트로피 `.qu` 섹션 하나에 코드가 몰려 있어 VMProtect 보호가 명확하다.

평문으로 남은 정보는 WinHTTP 연결, 외부 프로그램 실행, 시스템 설정 조회, VMProtect SDK, IP `23.140.4.181` 정도다. 따라서 이 파일이 상위 제어 클라이언트라는 판단은 강하지만 정확한 봇 로직은 정적 분석만으로 복원할 수 없다.

동일 폴더의 FFmpeg는 2026-05-31 개발 스냅샷 `N-124714-g49a77d37be`다. 봇이 녹화·캡처를 위해 실행할 가능성이 있지만 직접적인 `ffmpeg` 명령 문자열은 보호 영역에 있어 확인되지 않았다.

## 5. DebuggerList.ini가 보여주는 사용 방식

`DebuggerList.ini`는 GB18030 인코딩이며 섹션 이름은 중국어 `配置`, 즉 설정이다. 총 15개의 도구가 등록돼 있다.

- `虚幻调试器.exe`, 즉 Unreal 디버거.
- Cheat Engine과 `cheatengine-x86_64.exe` 계열 여러 버전.
- `SunnyNet` 패킷 캡처 도구.
- `Reqable` HTTP·HTTPS 디버깅 도구.
- `SenNetUtil`.
- `WinsockPacketEditor`.

경로는 `F:\`, `G:\`, `C:\Users\Administrator\...`처럼 원 개발자 PC의 절대 경로다. 따라서 현재 PC에서 실제로 이 프로그램들이 설치·실행됐다는 증거가 아니라, UnrealDbg GUI가 실행할 수 있도록 개발자가 미리 등록한 도구 목록이다.

이 목록은 패키지의 목적이 일반 소비자용 거짓말 탐지보다 게임 프로세스·메모리·네트워크 디버깅과 자동화에 있다는 강한 근거다.

## 6. 사용 흔적과 출처

- `AIHelper.log`와 `UnrealDbgDll.log`는 모두 0바이트다.
- 대부분 파일의 마지막 수정 시각은 2026-06-07 23:00:45~46으로 동일하다. 압축 해제 또는 일괄 복사 시각으로 보인다.
- `run_kr.py`만 2026-06-07 23:09:26에 생성·수정됐다. 원 패키지 복사 뒤 한국어 Windows 호환을 위해 추가된 파일로 보인다.
- 대부분 파일의 `Zone.Identifier`는 인터넷 영역 `ZoneId=3`이고 Telegram Desktop 아래 ZIP 파일을 참조한다.
- `UnrealDbgServer_vmp.exe`와 `run_kr.py`에는 같은 Zone.Identifier가 없다. 이 두 파일은 별도 전달·생성되었을 가능성이 있으나 확정할 수 없다.

폴더 내부 자료만으로는 이 PC에서 프로그램이 실제로 실행됐다고 확정할 수 없다. 실행 여부를 확인하려면 Windows Prefetch, 이벤트 로그, Defender 기록, 방화벽·DNS·라우터 로그를 별도의 포렌식 범위로 조사해야 한다.

## 7. 보안과 안정성 평가

### 높은 위험 요소

- 관리자 권한과 커널 드라이버를 사용한다.
- 서비스 생성·시작·삭제 기능을 사용한다.
- 다른 프로세스에 DLL을 주입하고 메모리를 읽고 쓸 수 있다.
- Intel VT 하이퍼바이저와 EPT 후킹을 사용한다.
- PowerShell을 통한 기호 파일 다운로드 기능이 드라이버 문자열에 포함돼 있다.
- 보호된 클라이언트에 하드코딩된 외부 IP가 있다.
- 주요 실행파일이 VMProtect로 감춰져 있어 전체 기능 감사가 어렵다.
- 핵심 EXE·DLL은 디지털 서명이 없다.

세 드라이버에는 Rockstar Games·Take-Two Interactive 명의의 2011~2013년 인증서가 붙어 있지만 현재 검증 상태는 `UnknownError`이며 인증서 유효기간이 끝났다. 드라이버 빌드 경로와 공개 UnrealDbg 프로젝트는 Take-Two와 무관하다. 이 서명을 신뢰 근거로 사용하면 안 된다.

### 악성 여부에 대한 판단

정적 분석만으로 이 패키지를 악성코드라고 단정할 증거는 부족하다. 공개된 UnrealDbg 프로젝트는 게임 드라이버의 안티디버깅 우회를 목적으로 하는 VT 기반 디버거라고 스스로 설명한다. 대상 파일의 구성과 PDB 경로도 그 공개 프로젝트의 모듈 구조와 일치한다.

그러나 이 프로그램이 사용하는 기술은 루트킷·게임 치트·악성코드가 사용하는 기술과 상당 부분 겹친다. 특히 `PolygraphBot_vmp.exe`와 `UnrealDbgServer_vmp.exe`는 보호돼 있고 외부 통신이 있으므로 공개 UnrealDbg 원본과 별개로 신뢰할 수 없다.

따라서 실사용 위험도는 **높음**으로 평가한다. 주 PC, 개인 계정이 로그인된 환경, 안티치트 게임이 설치된 환경에서는 실행하지 않는 것이 안전하다.

## 8. 핵심 파일 우선순위

1. `PolygraphBot_vmp.exe`. 최상위 봇 로직과 원격 통신을 가진 것으로 보이나 가장 불투명하다.
2. `UnrealDbg.aes`. 사용자가 조작하는 실제 GUI와 라이선스·디버거 제어의 중심이다.
3. `UnrealDbgDll.dll`. GUI와 주입·드라이버 계층을 연결한다.
4. `AIHelper.dll`. 드라이버 서비스와 DLL 주입을 담당한다.
5. `VT_Driver.sys`. 안티디버깅 우회의 가장 낮은 하이퍼바이저 계층이다.
6. `DbgkSysWin10.sys`, `DbgkSysWin11.sys`. 커널 디버그 이벤트와 프로세스 제어 계층이다.
7. `Hook.dll`, `Hook64.dll`. 사용자 모드 디버거 API를 커널 계층으로 중계한다.
8. `UnrealDbgServer_vmp.exe`. 보호된 서버·로더로 보이지만 세부 동작은 확인되지 않는다.

## 10. 분석 한계와 다음 단계

이번 분석은 안전을 위해 파일 실행, DLL 등록, 드라이버 설치, 외부 서버 접속을 하지 않았다. VMProtect로 보호된 두 실행파일의 실제 제어 흐름은 정적 분석만으로 확정할 수 없다.

추가 동적 분석이 필요하다면 개인 데이터가 전혀 없는 전용 물리 테스트 PC가 가장 적합하다. VT 하이퍼바이저 드라이버는 일반 가상머신에서 충돌하거나 동작하지 않을 수 있다. 네트워크는 처음부터 차단하고, 커널 크래시 덤프·프로세스·파일·레지스트리·서비스·네트워크 트래픽을 모두 기록해야 한다.
