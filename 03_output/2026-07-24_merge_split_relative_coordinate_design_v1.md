# 병합-분리 배경 상대 좌표 판별기 설계

## 상태

- 설계 승인 완료.
- 구현 전 사용자 문서 검토 대기.
- 적용 대상은 우선 Studio replay의 opt-in shadow다.
- `puzzle.py` 라이브 선택과 마우스 제어는 검증 관문을 통과하기 전까지 변경하지 않는다.

## 고정 목적

처음 흰색 타겟의 신분을 보존하고, 타겟이 배경 도형과 부분 또는 완전 병합된 뒤 분리될 때 배경 관계를 유지하지 않는 자식 경로를 타겟으로 복원한다.

GT와 정답 좌표는 실행 중 입력으로 사용하지 않는다. GT는 실행 종료 후 채점에만 사용한다.

## 해결할 문제

일반 이동에서는 기존 시간축 selector가 대체로 신분을 유지한다. 주요 실패는 다음 순서에서 발생한다.

1. 타겟과 배경 도형의 박스가 겹친다.
2. 부분 겹침에서는 두 박스가 남기도 하고, 완전 겹침에서는 하나의 커진 병합 박스만 남기도 한다.
3. 병합 박스 중심은 배경 쪽으로 밀리므로 타겟 중심으로 사용할 수 없다.
4. 분리 순간 기존 selector가 배경 자식을 타겟으로 잘못 상속한다.

따라서 현재 프레임 후보를 다시 점수화하는 것보다, 병합 전 신분 계보와 배경끼리의 상대 관계를 보존하는 전용 판별기가 필요하다.

## 범위 밖

- 특정 실패 프레임, 좌표, 오른쪽·왼쪽 방향을 규칙으로 넣지 않는다.
- 시계 방향 자체를 정답 반대 규칙으로 사용하지 않는다.
- 병합 박스의 커진 중심을 타겟 관측값으로 사용하지 않는다.
- YOLO 점수 하나로 분리 자식의 신분을 확정하지 않는다.
- 첫 구현에서 병합 박스 내부 segmentation이나 optical flow로 숨은 중심을 확정하지 않는다.

## 핵심 개념

### 타겟 포함 병합 사건

아무 박스 두 개가 겹친다고 타겟 사건으로 보지 않는다. 현재 타겟 계보와 연결된 후보가 다른 배경 후보와 결합될 때만 타겟 포함 병합 사건으로 연다.

### 배경 상대 좌표

안정적인 배경 기준점 두 개를 `A1`, `A2`, 판별할 후보를 `P`라고 한다.

1. `A1`에서 `A2`로 향하는 단위 벡터를 `e`로 둔다.
2. 두 기준점 사이 거리를 `L`로 둔다.
3. 다음 두 값을 후보의 상대 좌표로 저장한다.

```text
u = dot(P - A1, e) / L
v = cross(e, P - A1) / L
```

`u`, `v`는 화면 전체의 평행 이동, 회전, 균일 확대에 거의 영향을 받지 않는다. 배경 도형끼리 묶여 움직이면 배경 자식의 상대 좌표는 병합 전 값과 비슷하게 유지된다. 독립적으로 움직이는 타겟은 이 관계가 깨진다.

기준점이 세 개 이상이면 여러 기준점 쌍의 상대 좌표 잔차를 계산하고 중앙값으로 결합한다. 한 기준점만 남으면 거리와 국소 흐름만 사용할 수 있으므로 낮은 신뢰도로 보류한다.

### 적응형 허용 오차

고정 픽셀이나 고정 상대 좌표 임계값을 사용하지 않는다. 병합 전 주변 배경 도형들의 상대 좌표 흔들림을 측정해 해당 판의 불확실성 `sigma_bg`를 만든다.

```text
relative_residual = distance(current_uv, expected_uv) / max(sigma_bg, epsilon)
```

기준점이 흔들리거나 글라스 왜곡이 강하면 허용 범위가 넓어지고, 안정적인 판에서는 좁아진다.

## 상태기계

### `SEPARATE`

- 타겟과 배경 후보가 분리된 정상 상태다.
- 초기 타겟 신분, 최근 속도, 안정적인 배경 기준점과 배경 상대 좌표를 갱신한다.

### `PARTIAL_OVERLAP`

- 타겟 후보와 배경 후보가 동시에 보이지만 겹침이 커지는 상태다.
- 두 신분 경로를 모두 유지한다.
- 박스 중심이 겹침 방향으로 밀리면 관측 신뢰도를 낮춘다.
- 병합 전 상대 좌표 fingerprint를 고정한다.

### `MERGED`

- 후보 수 감소와 면적 증가가 함께 나타나 하나의 병합 관측만 남은 상태다.
- 병합 박스 중심으로 타겟 상태를 갱신하지 않는다.
- 겹치기 전 속도로 타겟 잠재 경로를 예측하고 불확실성만 증가시킨다.
- 배경 기준점은 계속 추적한다.

### `SPLITTING`

- 병합 관측 주변에서 다시 여러 자식 후보가 나타난 상태다.
- 각 자식 후보를 병합 전 배경 fingerprint에 대입한다.
- 배경 상대 좌표를 가장 잘 유지하는 자식을 배경 신분으로 배정한다.
- 남은 자식을 타겟 도전 경로로 유지한다.

### `REACQUIRED`

- resolver가 만든 같은 타겟 도전 경로를 기존 `PersistentEvidenceQuorum`이 최소 3개의 유효 관측에서 확인할 때 진입한다.
- resolver는 최종 확정 횟수를 별도로 세지 않는다.
- 확정 후 일반 selector로 돌아간다.

상태 전환에는 진입과 이탈 조건을 다르게 두는 hysteresis를 사용한다. 후보 수가 한 프레임 흔들리는 것만으로 상태가 왕복하지 않게 한다.

## 구성 요소

### `MergeSplitEventDetector`

입력은 현재 타겟 상태, 후보 박스, 초기 도형 크기, 이전 상태다. 출력은 병합 상태, 참여 후보, 정규화된 겹침·면적 변화와 전환 이유다.

판정값은 초기 도형 크기와 현재 후보 분포로 정규화한다.

### `BackgroundAnchorManager`

병합에 참여하지 않고 화면 경계에서 잘리지 않았으며 여러 관측에서 배경 흐름을 유지한 후보를 기준점으로 관리한다.

- 기준점 2개 이상은 정상 판정이 가능하다.
- 기준점 1개는 낮은 신뢰도다.
- 기준점 0개는 기권한다.
- 기준점 자체가 겹치거나 잘리면 즉시 교체하거나 기권한다.

### `BackgroundRelationFingerprint`

충돌 배경 도형이 기준점 쌍에 대해 가졌던 `(u, v)`와 판별 불확실성을 보존한다. 병합된 큰 박스의 크기나 중심으로 fingerprint를 덮어쓰지 않는다.

### `MergeLineageResolver`

부분 병합에서는 타겟과 배경 경로를 함께 유지한다. 완전 병합에서는 타겟을 잠재 상태로 유지한다. 분리되면 자식 후보와 기존 배경 fingerprint 사이의 최소 비용 배정을 계산한다.

후보 수가 적으므로 첫 구현은 복잡한 일반 최적화보다 모든 작은 배정 조합을 비교하는 결정적 방식으로 제한한다.

검출기 후보 ID는 프레임마다 달라질 수 있으므로 ID 문자열을 신분으로 사용하지 않는다. 예측 위치, 배경 상대 좌표, 후보 크기로 이어지는 공간 경로에 신분을 귀속한다.

병합 전에 충돌 배경의 fingerprint를 만들지 못했다면 분리 자식을 억지로 배정하지 않고 기권한다.

### `SplitIdentityDecision`

결과는 한 점수가 아니라 다음 구조로 반환한다.

- 배경으로 배정된 자식과 근거.
- 타겟 도전 자식과 근거.
- 사용한 기준점 수.
- 상대 좌표 잔차와 해당 판 불확실성.
- 국소 배경 흐름 잔차.
- 겹치기 전 타겟 속도 연결 오차.
- 확정, 보류, 기권 중 하나의 판정.

## 판단 순서

병합-분리 상태에서만 다음 계층을 사용한다.

1. 배경 상대 좌표로 배경 자식을 먼저 배정한다.
2. 현재 판에서 측정한 국소 배경 흐름으로 배경 배정을 확인한다.
3. 남은 자식이 겹치기 전 타겟 속도와 연결되는지 확인한다.
4. 초기 흰색 도형의 크기·가로세로비 신분을 보조 근거로 사용한다.
5. YOLO는 현재 후보 분포보다 낮을 때만 감점한다.
6. resolver가 만든 도전 경로를 기존 quorum이 최소 3개 유효 관측에서 확인할 때만 타겟 신분을 확정한다.

배경 상대 좌표와 기존 local rigid는 같은 계열의 근거일 수 있으므로 독립 표 두 장으로 세지 않는다. 상대 좌표는 배경 신분 배정의 주심이고 local rigid는 그 배정의 확인 근거다.

## 보류와 기권

- 두 자식의 상대 좌표 잔차 차이가 해당 판의 배경 흔들림보다 작으면 보류한다.
- 타겟이 잠시 배경과 같은 방향으로 움직여도 즉시 배경으로 확정하지 않는다.
- 기준점이 부족하거나 잘렸으면 관계 심판은 0점이 아니라 기권한다.
- 관측 불가능 프레임은 3회 지속 횟수에 포함하지 않는다.
- 정답 후보가 후보군에 없으면 selector가 임의의 후보를 선택하지 않고 후보 생성 문제로 보고한다.

## 기존 구조와의 연결

첫 연결은 `studio_hypothesis_shadow.py`의 opt-in replay 경로다. 새 resolver가 만든 타겟 도전 경로를 기존 `PersistentEvidenceQuorum` 앞에 전달한다.

기존 quorum은 도전 경로를 확정하는 역할을 유지한다. 새 resolver는 어떤 자식이 배경인지 배정하는 역할만 담당한다. 두 책임을 한 점수 함수로 합치지 않는다.

## 진단 로그

각 병합 사건에 다음 정보를 남긴다.

- 사건 ID와 상태 전환 프레임.
- 타겟 계보와 병합 참여 후보.
- 기준점 ID, 안정성, 기권 이유.
- 병합 전 background fingerprint.
- 분리 자식별 상대 좌표 잔차와 순위.
- 배경 배정과 타겟 도전 경로.
- 보류·확정 이유와 확정까지 걸린 유효 관측 수.
- GT 비참조 실행이 끝난 뒤에만 추가되는 사후 정오표.

## 검증 지표

- 병합 사건 검출 정확도.
- 분리 자식 후보군에 실제 타겟이 포함된 비율.
- 배경 자식 배정 정확도.
- 분리 후 타겟 신분 복원률.
- 잘못된 신분 교체 횟수.
- 분리 시작부터 복원까지의 유효 관측 수.
- 전체 프레임 적중과 기존 정답 A/B 회귀 수.

전체 프레임 적중만으로 병합 문제를 가리지 않도록 사건 단위 지표를 함께 사용한다.

## 검증 관문

1. 변환 불변성 단위검사를 통과한다.
2. 과거 실패판 한 개에서 분리 신분을 개선하고 기존 정답 회귀가 0이어야 한다.
3. 성공 보존판 한 개에서 회귀가 0이어야 한다.
4. 부분 병합, 완전 병합, 기준점 부족을 포함한 혼합 3판을 통과한다.
5. 정식 Studio seed 10판에서 기존 대비 개선이 있고 A/B 회귀가 0이어야 한다.
6. GT 비참조 selector와 런타임 selector의 16GT 16/16을 유지해야 한다.
7. 새 무작위 Studio 판을 1판, 3판, 10판 순서로 확대해 회귀 0을 유지해야 한다.
8. 모든 관문 후에만 `puzzle.py` 마우스 OFF 검증 모드 연결을 검토한다.

## 실패 분기

- 사건을 못 찾으면 `MergeSplitEventDetector` 문제다.
- 정답 자식이 후보군에 없으면 detector 또는 후보 생성 문제다.
- 정답 자식이 있는데 배경으로 배정하면 기준점과 fingerprint 문제다.
- 올바른 자식을 만들었지만 quorum이 거부하면 지속 확인과 기존 selector 연결 문제다.
- 기존 정답이 하나라도 회귀하면 판 확대를 중단하고 해당 규칙을 보류한다.

## 승인된 결론

병합-분리 문제의 주심은 화면 방향이 아니라 배경 도형끼리 유지되는 상대 좌표다. 타겟은 직접 알아보는 대신 배경으로 설명되는 자식을 제거해 복원한다. 완전 병합 중에는 신분을 새 병합 중심에 덮어쓰지 않고 잠재 상태로 보존한다.
